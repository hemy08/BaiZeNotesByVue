## 1. 功能概述

白泽笔记支持把外部格式内容转换为 Markdown 后放入编辑器。当前实现要点：

| 项 | 当前值 |
| --- | --- |
| 导入注册表 | `InsertImportFrom`（`import.ts`），**9 个键**：`word`、`html`、`excel`、`csv`、`json`、`text`、`ini`、`yaml`、`xml` |
| 转换依赖 | `mammoth`（Word→HTML）、`turndown`（HTML→Markdown）、`csv-parser`（CSV）、`iconv-lite` + `jschardet`（编码） |
| 菜单入口 | 文件 → 从文件导入（6 种格式）；插入 → 来自文件（8 种扩展名） |
| 右键入口 | 资源管理器右键 → 新建 → 从 Word 导入 / 从 HTML 导入（插入模式） |
| 两种模式 | `isImport = true`：导入后弹「导入选项」对话框；`false`：直接插入到光标处 |
| 导入后去向 | 替换当前内容 / 新建 .md 文件 / 插入到光标处 |
| 不支持 | xls/xlsx（明确提示）、PDF（无入口） |

## 2. 入口与去向

### 2.1 三个入口

| 入口 | 菜单动作 / IPC | 模式 | 可选格式 |
| --- | --- | --- | --- |
| 文件 → 从文件导入 | `baize:menu:file:import:<word\|html\|json\|yaml\|xml\|text>` → 主进程 `fileMenuHandlers.import.*` → `InsertImportFormFile(mainWindow, type, true)` | 导入（弹选项框） | word / html / json / yaml / xml / text |
| 插入 → 来自文件 | `baize:menu:insert:from-file:<json\|text\|ini\|yaml\|xml\|html\|csv\|excel>` → 主进程 `insertMenuHandlers['from-file'].*` → `InsertImportFormFile(mainWindow, type, false)` | 插入（光标处） | json / text / ini / yaml / xml / html / csv / excel |
| 资源管理器右键 → 新建 → 从 Word 导入 / 从 HTML 导入 | `IPC.FILE_MANAGER.IMPORT_FROM`（`baize:fs:import-from`）→ `dialogs.ts` → `InsertImportFormFile(mainWindow, type, false)` | 插入（光标处） | word / html |

> 「插入 → 来自文件」没有 Word 入口（Word 只在「从文件导入」与右键菜单），这是菜单数据的现状而非 bug。

### 2.2 导入流程图

```text
点击菜单 → InsertImportFormFile(mainWindow, fileType, isImport)
  ├─ 查 InsertImportFrom[fileType]，无此键 → 错误框「暂不支持当前格式…」并返回
  ├─ dialog.showOpenDialog（按格式 filters 过滤扩展名）
  ├─ 用户取消 → 直接返回（无提示）
  ├─ registerTrustedPath(file) + isPathAllowed(file) 校验（路径守卫 P1-AS-1）
  ├─ readerFn(file) 读取/转换
  │    └─ 抛错 → 错误框「导入文件失败: {error}」（只提示一次，FE-19）
  ├─ content = model.argStart + context + model.argEnd（按格式包裹代码围栏）
  ├─ isImport=true → send(IPC.DIALOG.OPEN_VUE_DIALOG, 'importOption', { content })
  └─ isImport=false → send(IPC.MONACO_INSERT.AFTER_CURSOR, content)   // 光标处插入
```

## 3. 支持的格式总表

| 注册键 | 对话框过滤器名 | 扩展名 | 读取/转换器 | 包裹前后缀 | 菜单可达性 |
| --- | --- | --- | --- | --- | --- |
| `word` | `Word Files` | `doc`, `docx` | `convertDocxToMarkdown`（mammoth → HTML → turndown） | 无 | 从文件导入 / 右键导入 |
| `html` | `HTML Files` | `html`, `htm`, `mhtml` | `convertHtmlToMarkdown`（编码探测读取 → turndown） | 无 | 从文件导入 / 插入来自文件 / 右键导入 |
| `csv` | `Sheet Files` | `csv` | `convertCsvToMarkdown`（编码探测 → csv-parser → Markdown 表格） | `\r\n` + `\r\n` | 插入 → 来自文件 |
| `excel` | `Sheet Files` | `xls`, `xlsx` | `rejectExcelImport`（**抛错引导转 CSV**） | 无 | 插入 → 来自文件（会提示不支持） |
| `json` | `Json Files` | `json` | `formatJsonString`（解析后自定义缩进格式化，失败返回原文） | json 代码围栏（前后均含 CRLF） | 从文件导入 / 插入来自文件 |
| `text` | `Text Files` | `txt`, `log`, `ini` | `ReadFile`（编码探测） | text 代码围栏（前后均含 CRLF） | 从文件导入 / 插入来自文件 |
| `ini` | `INI Files` | `ini` | `ReadFile`（编码探测） | text 代码围栏（前后均含 CRLF） | 插入 → 来自文件 |
| `yaml` | `YAML Files` | `yaml`, `yml` | `ReadFile`（编码探测） | yaml 代码围栏（前后均含 CRLF） | 从文件导入 / 插入来自文件 |
| `xml` | `XML Files` | `xml` | `ReadFile`（编码探测） | xml 代码围栏（前后均含 CRLF） | 从文件导入 / 插入来自文件 |

补充：

- 主进程动作树 `fileMenuHandlers.import` 的 6 个键（word/html/json/yaml/xml/text）与「文件 → 从文件导入」菜单 6 项一一对应。
- `insertMenuHandlers['from-file']` 的 8 个键（json/text/ini/yaml/xml/html/csv/excel）与「插入 → 来自文件」菜单 8 项一一对应。
- `mhtml` 虽在 html 扩展名列表内，但菜单不单独暴露，需从 html 过滤器选择。
- **PDF 不在支持列表**；「来自文件」中的 `*.xls;*.xlsx` 会走 `excel` 键并弹出引导提示。

## 4. 各格式转换规则

### 4.1 Word（.doc / .docx）

- `mammoth.convertToHtml({ path })` 把 Word 转 HTML，再用 `turndown` 转 Markdown。
- 支持 mammoth 能识别的标题/段落/列表/表格等基本结构。
- **图片**：mammoth 默认把内嵌图片以内联 `data:` URI 写入 `<img src>`，经 turndown 后成为超长 base64 图片链接——图片会保留但文档体积可能显著增大，不提供图片外置/落盘处理。
- 失败时抛错，由外层统一提示「导入文件失败: {error}」。

### 4.2 HTML（.html / .htm / .mhtml）

- 先用 `ReadFile`（编码探测）读成文本，再 `turndown.turndown(html)` 转 Markdown。
- 支持标题、段落、列表、链接、图片（远程/相对路径原样保留）、引用、表格（turndown 默认规则）等常见元素。
- FE-19：转换失败内层**不再弹框**，统一上抛由外层提示，一次失败只弹一个错误框。

### 4.3 CSV（.csv）

- 编码探测读取文本 → `csv-parser` 流式解析 → 拼 Markdown 表格字符串（前后各包一个 `\r\n`）。
- **已知问题（需人工确认，代码现状）**：`tests/unit/import.test.ts` 对真实输出做了精确断言并注明「含两个疑似 bug」：
  1. `headers` 事件回调收到的是**数组**，代码用 `Object.keys()` 取到的是列索引，表头行输出为 `0\|1\|2` 列号而非真实表头 `a\|b\|c`；
  2. 数据行以 `| |` 开头，首列多出一个空单元格，例如 `| | 1 | 2 | 3  |`。
- 例（当前真实输出）：输入 `a,b,c\n1,2,3\n` → 输出 `| 0| 1| 2 |` / `| ---| ---| --- |` / `| | 1 | 2 | 3  |`。
- 复杂 / 含引号 / 多行单元格由 csv-parser 处理；转换后的表格若列数不齐需人工调整。

### 4.4 JSON（.json）

- 编码探测读取 → `JSON.parse` 成功后用自定义 `formatterJson`（2 空格缩进、数组/对象逐行展开）美化；解析失败返回原文。
- 输出包裹 ` ```json ` 代码围栏（插入模式）；导入模式包裹同样存在，但最终由「导入选项」决定去向。

### 4.5 YAML / XML / 文本 / INI

- 统一 `ReadFile`（编码探测）读取原文，按格式包裹 ` ```yaml ` / ` ```xml ` / ` ```text ` 围栏（前后缀见第 3 章表）。
- `.ini` 在插入菜单中单独一项（FUN-14 补充独立注册键，此前缺失导致恒提示「暂不支持」）。

### 4.6 Excel（.xls / .xlsx）

- **不支持解析**：FUN-14 起 `rejectExcelImport` 直接抛错，文案为
  *暂不支持直接导入 .xls/.xlsx 文件，请先将表格导出为 CSV 格式再导入*。
- 不再按文本读取二进制（避免把乱码内容插入文档）。

## 5. 编码探测

所有文本类读取（text/ini/yaml/xml/csv/html）统一调用 `file-encoding.ts` 的 `decodeFileContent(buffer)`：

| 步骤 | 规则 |
| --- | --- |
| 1. BOM | `EF BB BF` → UTF-8（去 BOM）；`FF FE` → UTF-16LE；`FE FF` → UTF-16BE |
| 2. 指定编码 | 导入场景不指定（编码菜单「以指定编码打开」才传 `preferredEncoding`） |
| 3. 启发式探测 | `jschardet.detect(buffer)` |
| 4. 归一化 | `ENCODING_ALIASES`：`utf8/ascii→utf-8`、`gb2312/gbk/gb18030→gbk`、`big5→big5`、`utf-16le/be`、`shift_jis`、`euc-jp`、`euc-kr`、`windows-1252`、`latin1` |
| 5. 兜底 | iconv-lite 不支持的编码回退 UTF-8 |

> 导入只读一次、非大文件流式路径（`InsertImportFormFile` 用 `fs.readFile`）；大文件流式 `ReadFileContentAdaptive` 用于主流程打开文件（>5MB），导入不涉及。

## 6. 导入选项对话框（3 种去向）

### 6.1 对话框

- 组件：`dialogs/medium/ImportOptionDialog.vue`，标题「导入选项」，副标题「请选择如何处理导入的内容」。
- 打开方式：导入流程经 `IPC.DIALOG.OPEN_VUE_DIALOG('importOption', { content })` 打开并携带内容；渲染层 `configStore.showDialog('importOption')` 会先清空 `content`（历史兼容分支，当前菜单树没有直接打开该对话框的入口）。
- 确认后由 `BaiZeNotes.vue` 的 `handleImportOptionConfirm(option)` 分发：

| 选项 | zh-CN 文案 | 行为 |
| --- | --- | --- |
| `replace` | 替换当前内容 / *清空当前编辑区，使用导入的内容替换* | `EventBus.$emit(MONACO_REPLACE_TEXT, content)` → 编辑器全文替换 |
| `newfile` | 新建文件 / *创建新文件并导入内容（需要选择保存位置）* | `invoke(IPC.FILE.IMPORT_NEW_FILE, content)` → 主进程 `ImportCreateNewFile` |
| `insert` | 插入到当前位置 / *在当前光标位置插入导入的内容* | `EventBus.$emit(MONACO_INSERT_TEXT, content)` → 光标处插入 |

### 6.2 新建文件（`ImportCreateNewFile`）

1. `dialog.showSaveDialog`：标题「保存导入文件」，默认文件名「导入文件.md」（有活动文件时默认目录为其所在目录），过滤器 `Markdown (*.md)`。
2. 用户取消 → `{ success: false }`。
3. 文件名未以 `.md` 结尾时自动追加 `.md`。
4. `registerTrustedPath(filePath)` + `isPathAllowed()` 校验；拒绝则状态栏提示并返回失败。
5. `fs.writeFile(filePath, content, 'utf-8')` → `OpenSelectFile({...})` 打开新文件 → 100ms 后 `ReloadDirFromDisk()` 刷新目录树。

## 7. 错误提示与安全边界

### 7.1 用户可见提示（主进程 `tMain` 文案）

| 场景 | 文案 |
| --- | --- |
| 未知格式键 | 暂不支持当前格式的文件。当前支持 `*.txt`、`*.log`、`*.ini`、`*.json`、`*.yaml`、`*.yml`、`*.csv`、`*.xml`、`*.html`、`*.htm`、`*.mhtml`、`*.doc`、`*.docx`；`*.xls`、`*.xlsx` 请先导出为 CSV 格式再导入 |
| xls/xlsx | 暂不支持直接导入 .xls/.xlsx 文件，请先将表格导出为 CSV 格式再导入 |
| 读取/转换失败 | 导入文件失败: {error}（一次失败只提示一次，FE-19） |
| 路径不被允许 | 经 `notifyPathAccessDenied` 提示操作失败（状态栏） |

### 7.2 安全边界

- 文件路径来自系统打开对话框（用户显式选择）→ `registerTrustedPath(file)` 登记为受信精确文件后再读取；`isPathAllowed()` 拒绝不受信/异常形态路径（P1-AS-1 Path Guard）。
- 新建导入文件的目标路径同样来自系统保存对话框并登记受信。
- 大文件（>5MB）导入仍为一次性 `readFile`；当前无大小上限校验（与打开文件不同，导入不 streaming）。

## 9. 扩展新格式

1. 在 `import.ts` 写转换函数：`async function convertXxxToMarkdown(file: string): Promise<string>`（文本类可直接 `ReadFile`）。
2. 在 `InsertImportFrom` 增加模型：

```ts
export const InsertImportFrom: Record<string, ImportFormatModel> = {
    // ...
    xxx: {
        name: 'XXX Files',
        extensions: ['xxx'],
        importReader: convertXxxToMarkdown,
        insertReader: convertXxxToMarkdown,
        argStart: '```xxx\r\n',
        argEnd: '\r\n```\r\n'
    }
}
```

3. 在 `menu-config.ts` 对应菜单加条目（`labelKey` + `menuAction`），并在 `menu-file.ts`（导入模式）或 `menu-view.ts` 的 `insertMenuHandlers['from-file']`（插入模式）注册处理函数。
4. 在 `menu.ts`（中英）补文案；注意 `templates.ts` 的 `InsertFromFiles` 若也要出菜单项需同步。
5. 跑 `npm test -- tests/unit/import.test.ts`（注册表完整性、编码探测、xls 拒绝、HTML 失败单次提示等）。

## 10. 已知限制与已知问题

| 类别 | 内容 |
| --- | --- |
| 不支持 | xls/xlsx（提示转 CSV）、PDF；Word 图片以内联 data URI 保留（会显著增大文档体积，无外置处理） |
| **CSV 导入** | ✅ **2026-11-15 已修复**（原缺陷：表头取列索引 `0\|1\|2` + 数据行多一个前导空列；根因是表头事件参数被按数组下标取键、拼行时重复加竖线）。现输出标准 Markdown 表格：真实表头、列数严格对齐、单元格内 `\|` 转义、换行折叠为 `<br>`、空行跳过、BOM 兜底 |
| 导入模式 | 「文件 → 从文件导入」选完文件后**必须**在 3 选项对话框里二次确认；直接插入模式没有确认框 |
| 大文件 | 导入不流式读取、无大小上限提示；超大文件可能卡顿 |
| 菜单入口缺口 | 「插入 → 来自文件」无 Word；`mhtml` 只能从 html 过滤器选；「自定义模板」等未实现项与导入无关 |
| 编码 | 导入不提供「指定编码」入口（编码菜单只作用于已打开文件）；启发式探测可能误判 |
