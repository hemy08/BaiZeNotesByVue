# 文件导出功能说明

> 更新于 2026-11-15（对照 v1.3.0）
>
> 文档版本 2.0 ｜ 代码基线 v1.3.0
> 事实来源：`src/main/utils/file-utils/export.ts`、`src/main/ipc/menu-file.ts`、`src/renderer/src/components/ResourceManager/resource-manager.ts`、`src/shared/i18n/messages/*/mainMsg.ts`，以及 `tests/unit/export.test.ts`。
> 一句话结论：导出由主进程配置表驱动，支持 **6 种格式**（word/json/xml/yaml/html/pdf）；保存路径一律由用户在系统保存对话框中显式选择（取消则中止）；PDF 用**隐藏 BrowserWindow + `printToPDF`（A4）**生成；JSON/XML/YAML 的元数据版本号取自 `package.json`（当前 **1.3.0**）。

## 1. 功能概述

| 项 | 当前值 |
| --- | --- |
| 导出配置表 | `exportConfigs`（`export.ts`），**6 个格式**：`word`、`json`、`xml`、`yaml`、`html`、`pdf` |
| 内容来源 | `appState.currentActiveFile?.content`（当前活动文件全文）；为空则提示「当前没有可导出的内容」 |
| 保存方式 | `dialog.showSaveDialog`（用户显式选路径）→ 目标路径登记受信 → 对应导出器写入 |
| 默认文件名 | `untitled.docx` / `untitled.json` / `untitled.xml` / `untitled.yaml` / `untitled.html` / `untitled.pdf` |
| 编码 | 文本格式统一 UTF-8 写出 |
| 元数据版本 | 运行时读取 `package.json` 的 `version`（当前 1.3.0；读取失败回退 `app.getVersion()`，再失败 `'unknown'`） |
| 入口 | 文件 → 导出到文件（6 种）；资源管理器右键 → 导出到文件（6 种） |

## 2. 入口

| 入口 | 菜单动作 | 落点 | 说明 |
| --- | --- | --- | --- |
| 文件 → 导出到文件 | `baize:menu:file:export:<word\|json\|xml\|yaml\|html\|pdf>` | 主进程 `fileMenuHandlers.export.*` → `ExportToFile(mainWindow, type)` | 6 项与 6 个配置键一一对应 |
| 资源管理器右键 → 导出到文件 | 同上（`send(IPC.MENU.ACTION, ...)`） | 主进程 | **FE-12**：先 `IPC.FILE.OPEN_SELECT_FILE` 打开右键节点并等待 `IPC.FILE.USER_SELECT_FILE` 确认活动文件切换后再导出；打不开/5 秒超时则取消导出，绝不导出错误内容 |

## 3. 支持的格式总表

| 配置键 | 过滤器名（中文） | 扩展名 | 默认文件名 | 导出器 | 依赖 |
| --- | --- | --- | --- | --- | --- |
| `word` | Word 文档 | `docx` | `untitled.docx` | `ToWord` | `officegen` |
| `json` | JSON 文件 | `json` | `untitled.json` | `ToJson` | 无（原生 `JSON.stringify`） |
| `xml` | XML 文件 | `xml` | `untitled.xml` | `ToXml` | 无（模板字符串） |
| `yaml` | YAML 文件 | `yaml`, `yml` | `untitled.yaml` | `ToYaml` | 无（模板字符串） |
| `html` | HTML 文件 | `html`, `htm` | `untitled.html` | `ToHtml` | `markdown-it` |
| `pdf` | PDF 文件 | `pdf` | `untitled.pdf` | `ToPdf` | Electron `printToPDF` |

> 过滤器名经 `tMain('mainMsg.filters.*')` 按当前语言实时翻译（CMP-30 getter）；`getSupportedExportFormats()` 返回 `['word','json','xml','yaml','html','pdf']`。

## 4. 保存路径与用户选择

### 4.1 保存对话框

- 标题：`导出为 {name}`（`mainMsg.dialog.exportTitle`，`name` 为格式名）。
- 默认路径：`untitled.<ext>`（不继承当前文件路径）。
- 过滤器：单个 `{ name: 格式名, extensions: [...] }`。
- 用户取消或未选路径 → **直接返回，不写文件、不提示**。

### 4.2 安全边界（P1-AS-1）

1. 保存目标来自系统保存对话框（用户显式选择）→ `registerTrustedPath(result.filePath)` 登记为受信精确文件。
2. 导出器只写该路径；渲染层无法通过其它入口驱动任意写。
3. 写入失败（权限/磁盘/占用等）→ 错误框「导出文件失败: {error}」。

### 4.3 写入方式

| 格式 | 写入 API |
| --- | --- |
| word | `createWriteStream(filePath)` 交给 `officegen.generate(stream)`，`close` 视为成功、`error` 视为失败 |
| json/xml/yaml/html | `fs.writeFile(filePath, 文本, 'utf-8')` |
| pdf | `fs.writeFile(filePath, pdfData)`（二进制 Buffer） |

## 5. 各格式输出细节

### 5.1 Word（.docx，`ToWord`）

- 使用 `officegen('docx')`，按行扫描 Markdown：
  - `# ` → 加粗 20 号段落；`## ` → 加粗 18 号；`### ` → 加粗 16 号；
  - 非空普通行 → 普通段落；
  - 空行被跳过。
- **不支持**：代码块、表格、图片、链接、列表、粗体/斜体内联语法（按纯文本处理）。适合简单文本文档。

### 5.2 JSON（.json，`ToJson`）

```json
{
  "content": "<Markdown 全文>",
  "metadata": {
    "exportedAt": "2026-11-15T…Z",
    "version": "1.3.0",
    "type": "markdown",
    "app": "BaiZeNotes"
  }
}
```

- 2 空格缩进；`exportedAt` 为 ISO 时间。

### 5.3 XML（.xml，`ToXml`）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<document>
  <metadata>
    <exportedAt>…</exportedAt>
    <version>1.3.0</version>
    <type>markdown</type>
    <app>BaiZeNotes</app>
  </metadata>
  <content><![CDATA[…正文…]]></content>
</document>
```

- 正文用 CDATA 包裹；**`]]>` 会先转义**为 `]]]]><![CDATA[>`（FUN-15），否则会提前终止 CDATA 生成非法 XML。

### 5.4 YAML（.yaml / .yml，`ToYaml`）

```yaml
content: |
  <Markdown 全文，逐行缩进 2 空格>
metadata:
  exportedAt: 2026-11-15T…Z
  version: 1.3.0
  type: markdown
  app: BaiZeNotes
```

### 5.5 HTML（.html / .htm，`ToHtml`）

- `markdown-it` 渲染正文 → 完整 HTML 文档（`<html lang="zh-CN">`）。
- 内置 CSS：正文最大宽 800px、居中、`pre/code` 浅灰底、`blockquote` 左边框、`table` 边框合并等。
- 底部 footer：`Exported from BaiZeNotes at <本地化时间>`。
- 支持 markdown-it 默认语法（标题/段落/列表/代码块/表格/链接/图片/引用等）；不解析 Mermaid/KaTeX/PlantUML（导出为代码块源码）。

### 5.6 PDF（.pdf，`ToPdf`）

1. 新建隐藏窗口 `new BrowserWindow({ width: 800, height: 600, show: false, webPreferences: { nodeIntegration: false, contextIsolation: true } })`。
2. `markdown-it` 渲染正文 → 极简 HTML（Arial、padding 20px、line-height 1.6）。
3. `win.loadURL('data:text/html;charset=utf-8,' + encodeURIComponent(html))`。
4. `win.webContents.printToPDF({ printBackground: true, pageSize: 'A4', margins: { top: 1, bottom: 1, left: 1, right: 1 } })`。
5. `fs.writeFile(filePath, pdfData)`。
6. **`finally` 中 `win.close()`**：加载/打印/写盘任一步失败都关闭隐藏窗口，避免窗口泄漏（FUN-15/MEM-07）。

## 6. 内容来源与右键导出

### 6.1 正常导出（菜单）

- 取 `appState.currentActiveFile?.content`（活动文件全文，含未保存修改，编辑器每次内容变化都会同步到主进程状态）。
- 内容为空字符串/未打开文件 → 错误框「当前没有可导出的内容」并中止。

### 6.2 右键导出（FE-12）

旧实现直接 `send(MENU.ACTION)`，主进程固定取「当前活动文件」内容 → **右键 A 文件却导出已打开的 B 文件内容**（数据错导）。当前实现：

```text
右键节点 → onHandleExport(node, fmt)
  ├─ invoke(IPC.FILE.OPEN_SELECT_FILE, node)          // 打开右键节点文件（主进程会先保存当前文件）
  ├─ 等待 IPC.FILE.USER_SELECT_FILE 确认活动文件已切换（5s 超时）
  ├─ 切换成功 → send(MENU.ACTION, 'baize:menu:file:export:<fmt>')
  └─ 打不开/超时 → 取消导出（绝不继续导出错误文件）
```

- 右键导出子菜单仅在文件节点可用（文件夹禁用）。
- 该链路不改变导出格式本身，只保证「导出的是右键的那个文件」。

## 8. 关键代码与 IPC

### 8.1 核心函数

| 函数 | 说明 |
| --- | --- |
| `ExportToFile(mainWindow, fileType)` | 主入口：校验内容 → 查配置 → 保存对话框 → 登记受信 → 调导出器 → 成功/失败提示 |
| `ToWord` / `ToJson` / `ToXml` / `ToYaml` / `ToHtml` / `ToPdf` | 6 个导出器（均导出为可单测的纯函数 `(content, filePath) => Promise<void>`） |
| `getSupportedExportFormats()` | 返回内置格式键列表 |
| `registerExportFormat(formatKey, config)` | 注册自定义格式（`ExportConfig`：`name`/`extensions`/`defaultName`/`exporter`） |
| `getAppVersionForExport()` | 读 `package.json` 版本（缓存），用于元数据 |

### 8.2 IPC / 通道

| 通道 | 方向 | 用途 |
| --- | --- | --- |
| `IPC.MENU.ACTION` = `baize:menu:action` | 渲染 → 主（send） | 菜单/右键导出动作 |
| `IPC.FILE.OPEN_SELECT_FILE` = `baize:file:open-select-file` | 渲染 → 主（invoke） | 右键导出前打开节点文件（FE-12） |
| `IPC.FILE.USER_SELECT_FILE` = `baize:file:user-select-file` | 主 → 渲染 | 活动文件切换确认 |
| `IPC.DIALOG.OPEN_VUE_DIALOG` | 主 → 渲染 | 与导出无直接关系（导出用系统保存对话框） |

> 导出不使用新增 IPC 通道：动作 id 复用菜单通道，保存对话框在主进程内完成。

## 9. 扩展新格式

1. 在 `export.ts` 实现导出器：

```ts
export async function ToXxx(content: string, filePath: string): Promise<void> {
    // 生成内容并写盘
}
```

2. 在 `exportConfigs` 增加配置（名称建议用 getter 走 `tMain('mainMsg.filters.*')`）：

```ts
xxx: {
    get name() { return tMain('mainMsg.filters.xxx') },
    extensions: ['xxx'],
    defaultName: 'untitled.xxx',
    exporter: ToXxx
}
```

3. 在 `menu-config.ts` 的 `exportMenu.submenu` 增加 `{ labelKey: 'menu.file.export.xxx', menuAction: 'baize:menu:file:export:xxx' }`，并在 `src/main/ipc/menu-file.ts` 的 `fileMenuHandlers.export` 增加同名处理函数。
4. 补 `menu.ts` 与 `mainMsg.ts`（filters）中英文案；需同步 `menu_config.test.ts` 的导入/导出子菜单条目数断言（当前各 6 项）。
5. 跑 `npm test -- tests/unit/export.test.ts`。

> 也可运行时用 `registerExportFormat()` 注册自定义格式（单测覆盖），但目前没有 UI 入口，需由主进程代码调用。

## 10. 已知限制

| 类别 | 内容 |
| --- | --- |
| 内容范围 | 只导出**当前活动文件**全文；不支持批量/目录导出 |
| PDF 样式 | 使用极简 HTML 样式，不继承应用主题与预览样式；Mermaid/KaTeX/PlantUML 以源码呈现 |
| Word 能力 | 仅标题 + 段落（加粗/字号），无表格/图片/链接/列表 |
| Markdown 本身 | 无「导出为 .md」项（当前文档本身就是 .md，直接保存即可） |
| 默认路径 | 固定 `untitled.*`，不记忆上次导出目录 |
| 二进制写盘 | 无原子写/临时文件；写入中途失败可能留下不完整文件（`writeFile` 语义） |
| 旧文档「导出大文件可能较慢」 | 主进程一次性读取全文再转换，超大文件会有内存/耗时压力（无分片） |
