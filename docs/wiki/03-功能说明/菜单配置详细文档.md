## 1. 菜单系统概述

### 1.1 核心事实（先看这段）

| 事实 | 说明 |
| --- | --- |
| **无 Electron 原生菜单** | 全仓没有 `Menu.buildFromTemplate` / `Menu.setApplicationMenu`；顶部菜单栏是 **渲染层 Vue 自绘**（`MenuBar.vue`），主进程只负责「动作 → 处理函数」树式分发（`menu-handle.ts`） |
| **菜单数据在渲染层** | 菜单树真源是 `src/renderer/src/components/MenuBar/menu-config.ts` 的 `menuMap`（`ref` + `markRaw`） |
| **字段名是 `menuAction`** | 全仓已无 `menu_action` 字段/标识符（v1.3.0 死通道清理时统一改名）；仅在 `CHANGELOG.md` 历史条目与少量注释里保留了旧文件名 `menu_actions.ts` 字样 |
| **空组自动剪枝** | `pruneEmptySubmenus()` 递归剔除 `submenu` 为空的分组，并清理由此暴露的首尾/连续分隔符 |
| **菜单栏可开关** | 系统设置 `menuBarStyle` 为 `electron`/`default` 时显示顶部菜单栏（`BaiZeNotes.vue` 的 `v-show="electronMenu"`），其他值隐藏 |
| **无原生菜单模块** | 旧文档中的 `src/main/menu/*.ts`、`menucontext.ts`、`menu_ipc.ts` 均已不存在；对应职责迁移到 `src/main/ipc/menu-*.ts` 与渲染层 `menu-actions.ts` |
| **i18n 即时切换** | 菜单文案只存 `labelKey`（`menu.*` 命名空间），`MenuBar.vue` 渲染时调用 `t(labelKey)`，切换语言无需重建菜单 |

### 1.2 三种「菜单」形态

| 形态 | 实现 | 入口 |
| --- | --- | --- |
| 顶部应用菜单栏 | Vue 组件 `MenuBar.vue` + 数据 `menu-config.ts` + 动作 `menu-actions.ts` | 主界面标题栏下方 |
| 文件树右键菜单 | `@imengyu/vue3-context-menu`，`ResourceManager/resource-manager.ts` | 资源管理器节点右键 |
| 编辑器内菜单 | Monaco 内置右键菜单（contributions）+ 快速访问工具栏的模板/表情/符号右键菜单 | 编辑器区域右键/工具栏 |

### 1.3 技术实现

- **菜单数据**：TypeScript 常量 + i18n key（`menu-config.ts`、`menu-consts.ts`、`common/templates.ts`）。
- **菜单渲染**：纯 Vue 递归组件（`BaiZeSubMenuItem`），子菜单 `teleport` 到 `body` 并做屏幕边界钳制。
- **动作分发**：渲染层 `HandleMenuAction()` 先拦截可本地处理的动作；其余经 `IPC.MENU.ACTION` 交主进程 `HandleBaiZeMenuAction()` 按 `baize:menu:` 前缀解析路径并执行处理函数。
- **快捷键**：`globalShortcut`（主进程全局热键，`short-key-register.ts`）+ Monaco `addCommand`（编辑器内键位，`hemy-editor-shortcut.ts`）+ Monaco 原生键绑定。

## 3. 菜单动作字段与 i18n

### 3.1 `menuAction` 字段

```ts
// src/shared/types/menu.ts
export interface BaiZeMenuItem {
    labelKey?: string
    label?: string
    accelerator?: string
    menuAction?: string
    type?: 'separator'
    enabled?: boolean
    submenu?: BaiZeMenuItem[]
}
```

- **字段名**：`menuAction`（camelCase）。全仓已无 `menu_action`（v1.3.0 死通道清理，改名 270 处）；新代码/测试请勿再使用下划线命名。
- **动作 id 命名**：`baize:menu:<主菜单>:<子级...>:<动作>`，例如 `baize:menu:file:import:word`、`baize:menu:plugins:encrypt:rsa-generator`。
- **唯一性**：整棵菜单树内 `menuAction` 不重复（单测守护）。
- **叶子判定**：`MenuBar.vue` 只对「有 `menuAction` 且无 `submenu`」的项绑定点击；分组项只展开子菜单。

### 3.2 i18n 渲染规则（CMP-30 / FE-28）

| 规则 | 说明 |
| --- | --- |
| 文案只存 key | 菜单项优先用 `labelKey`（`menu.*` 命名空间），渲染时 `t(labelKey)`；切换语言即时生效 |
| 不翻译的保留 `label` | 品牌名（`GitHub`、`WebIDE Online`、`THX from Alimama FE`）、版本号（`v1.3.0`）、模板图格式名（`flowchart`、`BlockDiagram`、`Packet`、`XYChart`、`Zenuml`、`AsciiMath`）、文件扩展名（`*.json` 等）直接使用 `label` |
| 单测白名单 | `tests/unit/menu_config.test.ts` 校验「仍用 `label` 的项不含中文且在豁免清单内」 |
| 提示型菜单项 | 编码菜单两组末尾的 `{ labelKey: 'menu.coding.warning' }`（`注意: 请勿直接编辑乱码文件。`）是纯展示项，无 `menuAction`，点击无动作 |

### 3.3 `icon` 字段现状

✅ **2026-11-15：`icon` 字段已从菜单配置中删除**。原 11 个顶层菜单声明的 `icon`（`file`/`edit`/`view`/…/`help`）从未被 `MenuBar.vue` 渲染（历史实现在 `62ee568`/`dff0f3f` 中移除），且 `assets/icons` 下 11 个 SVG 均为同一占位圆圈（无法区分、`stroke` 也不继承主题变量）。当前菜单为**纯文字菜单**（`span.menu-label`）；如需图标，应重新提供差异化 SVG 资源并走主题变量实现。

## 4. 空组剪枝机制

### 4.1 背景

`menu-consts.ts` 中一批插件映射表在 A-4/ARC-09/CMP-29 清理后是空数组（`[]`），但 `menu-config.ts` 仍会把它们渲染为「无箭头、无 `menuAction`、点击无反应」的菜单组（FE-16 的 9 个空条目即来源于此）。v1.3.0 在数据层统一修复。

### 4.2 实现（`pruneEmptySubmenus`）

```ts
// menu-config.ts
export const menuMap = ref(markRaw(pruneEmptySubmenus([...12 个顶层菜单...])))
```

| 步骤 | 行为 |
| --- | --- |
| 1 | 递归处理 `submenu`：先剪枝子级，再判断子级是否为空 |
| 2 | `submenu` 递归后长度为 0 的容器项整体丢弃（菜单动作叶子全部保留） |
| 3 | 剪枝后清理分隔符：删除首尾分隔符与连续分隔符（`prev && next && prev.type !== 'separator' && next.type !== 'separator'`） |
| 4 | 不修改入参（返回新树），便于测试断言 |
| 5 | 数据补齐后无需改函数：子组有数据即自动恢复展示 |

### 4.3 当前被剪掉的组（v1.3.0 实点）

| 被剪掉的组 | 数据源 | 空数组原因 |
| --- | --- | --- |
| 插件 → 语言语法关键字对照表 | `PluginCodeDef = []` | 正则/Markdown/LaTeX/语言关键字等 23 项未实现，条目已归档（CMP-29） |
| 插件 → 各类转换器（整组） | 4 个子组 `PluginCodeConvertMaps/PluginConvertMaps/PluginUpLowerMaps/PluginFormatMaps` 均为 `[]` | 编解码/格式/大小写/格式化转换组件无注册 |
| 插件 → 网络计算插件 → 解析器 | `PluginNetGenerators = []` | 二维码生成器两项等无注册组件 |
| 插件 → 常用对照表 → 数据和命令对照表 | `PluginInfoCmd = []` | SQL/JSON 数据类型、Git/NPM 命令等 10 项未实现 |
| 插件 → 网络计算插件（数据层空数组） | `PluginNetWork = []` | 展开后无条目、不产生组（DNS/Ping/端口扫描等 14 项未实现），并非渲染后被剪枝 |

保留的组与条目见 [第 8 章](#8-插件菜单与工具注册表一致性)。

### 4.4 回归防护

`tests/unit/menu_config.test.ts` 中 `pruneEmptySubmenus（FE-16）` 5 个边界用例（空组、纯空子树、保序、分隔符清理、不改入参）+ `should not render any empty submenu group` 全树校验，防止再次回归出空组。

## 5. 渲染与交互行为

### 5.1 `MenuBar.vue` 行为表

| 行为 | 实现 |
| --- | --- |
| 顶层菜单 | `v-for="menu in menuMap"`，`:class="{ active: activeMenu === index }"`，`@click="toggleMenu(index)"`、`@mouseenter="handleMenuEnter(index)"` |
| 子菜单挂载 | `<teleport to="body">`，`position: fixed`，`z-index: 10000`，带 `submenu-fade` 过渡 |
| 定位 | 按被点菜单项的 `getBoundingClientRect()` 计算，宽 220px、边距 8px，超出右/左/顶部时钳制 |
| 多级子菜单 | 递归组件 `BaiZeSubMenuItem`；hover 展开下一级（`.nested-submenu` 绝对定位在右侧） |
| 关闭 | 鼠标离开菜单栏/子菜单后 100ms 延迟关闭（hover 子菜单可取消）；点击外部（非 `.menu-bar`/`.submenu-container`）关闭；窗口 resize 时重算位置 |
| 分隔符 | `type === 'separator'` 渲染为 `.menu-separator` 细线 |
| 快捷键展示 | 子菜单项右侧 `.menu-item-accelerator` 显示 `accelerator` 文本（顶层菜单不显示 accelerator） |
| 箭头 | `submenu.length > 0` 时显示 `▶`；disabled 项 `.disabled` 弱化并禁止 hover 高亮 |
| 主题 | 颜色全部走 CSS 变量（`--theme-*`），跟随主题切换 |

- 系统设置默认 `menuBarStyle: 'electron'`（`system-setting.ts`）。

## 6. 动作分发链路

### 6.1 总流程

```text
MenuBar 子菜单项点击
  └─ HandleMenuAction(action)                       // menu-actions.ts（渲染层）
       ├─ 命中渲染层拦截分支 → 直接执行（打开 Vue 对话框 / emit EventBus / showDialog）
       └─ 未命中 → window.electron.ipcRenderer.send(IPC.MENU.ACTION, action)   // 'baize:menu:action'
             └─ HandleBaiZeMenuAction(action, mainWindow)   // main/ipc/menu-handle.ts
                  ├─ MenuActionParser.parse：`baize:menu:` 前缀，split(':').slice(2) → 路径
                  ├─ findHandler：逐级查找处理函数树（file/edit/view/coding/insert/tools/online/ai/github/help）
                  ├─ 命中 → 执行；async 返回值统一 catch → reportMenuActionError
                  └─ 未命中 → console.warn('Unknown menu action: ', action)
```

- `insert` 树在构造时 `delete insertHandlers['md-table']`、`delete insertHandlers['web-link']`（渲染层优先拦截，保底剔除重复路径）。
- **动作失败上报（FE-08）**：处理函数返回 rejected Promise 时统一 `console.error('Error executing menu action: ', action, ', error: ', error)`，并经 `IPC.EVENTS.STATUS_BAR_UPDATE` 写入状态栏；`No active file` 走专门文案 `mainMsg.status.noActiveFileSave`，其余用 `mainMsg.status.menuActionFailed`。

| F12 | 开发人员工具 | **仅开发环境注册**（AS-12；生产包不注册该全局热键） |
| Ctrl+N | 新建 | `send(IPC.DIALOG.OPEN_VUE_DIALOG, 'createFileFolder', { dirPath: GetCurrentFileDirectory() })` |
| Ctrl+O | 打开文件夹 | `OpenDirectory(mainWindow)` |
| Ctrl+R | 从磁盘重新加载 | `ReloadDirFromDisk()`（含脏状态保护） |
| Ctrl+Shift+R | 重启应用 | `app.relaunch()` + `app.quit()` |
| F4 | 退出 | `app.quit()` |

实现要点（AS-12）：

- `globalShortcut` 为**系统级热键**（应用失焦时仍会抢占按键），与历史 F9–F12 机制一致。
- 只注册一次：macOS `activate` 重建窗口时只更新 `targetWindow`，不重复 `register`。
- 回调发送前取存活窗口，窗口已销毁时跳过并记录警告日志。
- Ctrl+S **故意不全局注册**（编辑器侧已绑定，避免抢占键盘事件破坏「先 flush 再落盘」契约）。

### 10.2 编辑器内快捷键（`hemy-editor-shortcut.ts`，14 个 `addCommand`）

| 快捷键 | 动作 |
| --- | --- |
| Ctrl+1 ~ Ctrl+6 | 一~六级标题（`h1`…`h6`） |
| Ctrl+B | 加粗 |
| Ctrl+I | 斜体 |
| Ctrl+U | 下划线 |
| Ctrl+D | 删除线（`~~` 包裹，快捷键说明中标签为「删除线」） |
| Ctrl+K | 键盘按键样式（`<kbd>` 包裹） |
| Ctrl+L | 链接（`[]()`） |
| Ctrl+S | `EventBus.emit(MONACO_SAVE_FILE_CONTENT_TO_DISK, true)`（编辑器侧保存链路） |
| Ctrl+V | 粘贴拦截：剪贴板含图片时插入图片，否则粘贴文本 |

另有 Monaco 原生键绑定（编辑器聚焦时生效，无需额外注册）：Ctrl+Z/Y（撤销/重做）、Ctrl+X/C/V（剪贴板）、Ctrl+F/H（查找/替换）、Ctrl+G（跳行）。

> 菜单标注（`accelerator`）与真实绑定对照：**文件菜单** Ctrl+N/O/S/R/Shift+R/F4 有真实绑定（全局或编辑器侧）；**编辑菜单** Ctrl+Z/Y/X/C/V/F/H/G 为 Monaco 原生绑定；**视图菜单** F9–F12 有全局绑定（F12 仅开发环境）；顶层菜单的 accelerator 不渲染，也不参与绑定。

## 12. 扩展指南

### 12.1 新增一个菜单项（同一层级）

1. 在 `menu-config.ts` 对应菜单的 `submenu` 中追加条目：`{ labelKey: 'menu.xxx.yyy', menuAction: 'baize:menu:<主菜单>:<动作>' }`（brand/格式名用 `label`）。
2. 在 `src/shared/i18n/messages/zh-CN/menu.ts` 与 `en-US/menu.ts` 补 `labelKey` 文案（中英都要）。
3. 若为动作型：
   - 可在渲染层处理 → 在 `menu-actions.ts` 增加分支（打开 Vue 对话框 / emit EventBus）；
   - 需要主进程 → 在对应 `src/main/ipc/menu-<域>.ts` 处理函数树中加 key，`menu-handle.ts` 自动按路径命中。
4. 若动作需要快捷键：全局键加在 `short-key-register.ts`；编辑器内键加在 `hemy-editor-shortcut.ts`；仅在菜单展示的 `accelerator` 不产生真实绑定，请勿标注不存在的键位（FUN-26 教训）。
5. 运行 `npm test` 让 `menu_config.test.ts` / `plugin_tools_const.test.ts` / `menu-handle.test.ts` 守护唯一性、i18n 解析与可达性。

### 12.2 新增一个顶层菜单

1. 在 `menu-config.ts` 定义新 `BaiZeMenuEntry`（`labelKey: 'menu.<name>.label'`、`icon`、`submenu`）。
2. 加入 `pruneEmptySubmenus([...])` 数组（顺序即展示顺序）。
3. 补 `menu.ts` 中英 labelKey；若需主进程处理，在 `menu-handle.ts` 的 `menuHandlers` 增加对应子树。
4. 注意 `MenuBar.vue` 顶层不渲染 `accelerator`；如需访问键请走系统级热键。

### 12.3 新增一个插件工具入口

1. 在 `PluginTools/<分类>/` 新建 `.vue`，并在 `plugin-tools-const.ts` 的 `pluginTools` 注册：`{ id: 'baize:menu:plugins:<分类>:<kebab-id>', component: lazyTool(() => import(...)) }`。
2. 在 `menu-consts.ts` 对应 `Plugin*Maps`（或 `menu-config.ts` 的补入口）新增 `{ labelKey, menuAction: <同一 id> }`。
3. 补 `menu.plugins.*` 中英文案。
4. `plugin_tools_const.test.ts` 会检查「注册表 ↔ 菜单」双向一致；空组会被 `pruneEmptySubmenus` 自动隐藏，因此**不要**新增无数据的占位组。
