## 1. 项目概述

### 1.1 项目简介

**白泽笔记**（`baize-notes`）是一款基于 Electron 43 + Vue 3.5 + TypeScript 6 构建的现代化 Markdown 编辑器桌面应用程序。主进程/预加载/渲染进程三层分离，Monaco Editor 提供编辑能力，Markdown 预览在渲染进程本地单跳渲染。

### 1.2 核心特性

#### Markdown 编辑功能

- **实时预览**：编辑 / 预览 / 分屏三种模式（F9 / F10 / F11），预览渲染在渲染进程内完成
- **语法高亮**：Monaco Markdown 语法 + highlight.js 代码块高亮（仅显式声明语言）
- **代码折叠**：标题层级与围栏代码块折叠（全部折叠/展开、1~6 级）
- **表格 / 数学公式**：MdSheet 表格对话框、KaTeX 公式（行内 `$...$`、块级 `$$...$$`）
- **图表**：Mermaid 渲染层本地渲染；PlantUML 本地 teaVM 离线渲染（失败降级远程）
- **文章大纲**：预览侧章节大纲与标题定位

#### 编辑器功能

- **Monaco Editor 0.57.0**：VS Code 同款编辑器，仅打包 editor worker（语言 worker 已移除）
- **多主题**：**28 种应用主题 + 57 种 Monaco 编辑器主题**（内置 3 + 磁盘 54）
- **快捷键**：全局视图切换（F9/F10/F11/F12）、文件操作（Ctrl+N/O/S/R/Shift+R、F4）
- **快速访问**：Emoji、特殊符号、写作模板、文本块模板快速插入
- **右键菜单**：编辑器上下文菜单（`@imengyu/vue3-context-menu`）
- **查找替换**：Monaco 原生查找/替换、跳转行

#### 文件管理

- **文件树浏览**：增量重扫 + 稳定 id + 整树 JSON 指纹去重；`fs.watch` 递归监听
- **文件操作**：新建/打开/保存/另存为/重命名/删除/复制/剪切/粘贴/在资源管理器显示
- **编码检测**：`jschardet` 探测 + `iconv-lite` 转换，支持 9 种编码重新打开/切换
- **多格式导入**：Word（docx）/ HTML / JSON / YAML / XML / 纯文本
- **多格式导出**：Word / JSON / XML / YAML / HTML / PDF（隐藏窗口 `printToPDF`）

#### 扩展功能

- **插件工具**：**38 个**内置工具（加密 8 / 信息 8 / 网络 4 / 编解码 5 / 格式转换 5 / 小工具 3 / 文本 3 / 格式化 2）
- **快速链接自定义**：网页链接与本地程序（EXE 白名单 + 确认），首页 NaviTab 展示
- **在线工具菜单**：7 组外部站点（菜鸟工具、W3School、编码、IDE、开发、团队、云）
- **HTML / PDF 查看器**：HTML iframe 沙箱预览、PDF 编辑查看
- **国际化**：`zh-cn` / `en-us` 双语，12 个 i18n 命名空间

#### 应用特性

- **跨平台**：Windows 10/11（当前发布）；macOS / Linux 打包配置保留
- **自动更新**：electron-updater，更新源强制 https
- **无框窗口**：自定义标题栏（拖拽/最小化/最大化/关闭 + 8 向缩放）
- **配置备份/恢复**：系统设置内置备份与恢复（默认保留 5 份，最多 20 份）

## 2. 技术架构

### 2.1 架构模式

白泽笔记采用 **Electron 多进程架构**：

```
┌─────────────────────────────────────────────────────────┐
│                    Electron 应用                         │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  ┌─────────────────────────────────────────────────┐   │
│  │              主进程 (Main Process)               │   │
│  │  - Node.js 环境                                 │   │
│  │  - 文件系统访问 / 配置持久化（electron-store）   │   │
│  │  - 窗口管理（主窗口 / 对话框 / 隐藏窗口）        │   │
│  │  - 菜单动作分发 / IPC 处理                       │   │
│  │  - PlantUML 本地渲染 / PDF 导出 / 自动更新       │   │
│  └─────────────────────────────────────────────────┘   │
│                          ↕                              │
│                    IPC 通信（91 个通道 / 17 组）          │
│                          ↕                              │
│  ┌─────────────────────────────────────────────────┐   │
│  │           预加载脚本 (Preload Script)            │   │
│  │  - 主窗口 index.ts：window.electron / window.api │   │
│  │  - 对话框 dialog.ts：window.electronAPI（白名单）│   │
│  │  - contextBridge 安全桥接（必须单文件产物）      │   │
│  └─────────────────────────────────────────────────┘   │
│                          ↕                              │
│  ┌─────────────────────────────────────────────────┐   │
│  │            渲染进程 (Renderer Process)           │   │
│  │  - Chromium 环境                                 │   │
│  │  - Vue 3 应用（欢迎页 / 主界面 / 23 个对话框）   │   │
│  │  - Monaco Editor + 本地 Markdown 预览管线        │   │
│  │  - EventBus（24 个事件）组件间通信               │   │
│  └─────────────────────────────────────────────────┘   │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 2.2 架构优势

#### 性能优势

- **预览本地化**：Markdown 预/后渲染全部在渲染进程完成（PF-02），每轮预览主进程 IPC 由 4 → 0（仅 PlantUML 保留 1 个渲染 IPC）
- **主进程不被渲染阻塞**：KaTeX/Material/TabbedSet 字符串变换不再占用主进程事件循环
- **增量刷新**：目录树增量重扫 + 指纹去重，实测目录刷新耗时 -94.8%

#### 安全优势

- **Context Isolation + sandbox**：主窗口与对话框均 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`
- **Path Guard**：`security.ts` 的 `isPathAllowed` / `assertSafePath` 约束文件读写范围
- **sender 校验**：`ipc-security.ts` 的 `withSenderCheck` 拒绝非受信发送方
- **协议白名单**：`shell.openExternal` 仅 http/https；导航边界拦截；CSP + DOMPurify

#### 开发优势

- **热重载**：`electron-vite dev` 开发模式
- **TypeScript**：node / web / test 三段类型检查全部通过
- **单一真源**：IPC 通道常量、i18n 词典、配置 schema 集中管理

#### 3.1.3 IPC 通信

主进程监听的通道一律引用 `src/shared/ipc-channels.ts` 常量（禁止字面量）。常用通道示例：

- `IPC.WINDOW.*`：`baize:window:minimize` / `maximize` / `close` / `toggle-maximize` 等 8 个
- `IPC.THEME.UPDATE_THEME`：`baize:theme:update`（渲染层 → 主进程），主进程广播 `baize:theme:updated`
- `IPC.MENU.ACTION`：`baize:menu:action`（渲染层 → 主进程菜单动作）
- `IPC.FILE.*`：24 个文件通道（`baize:file:open-select-file`、`baize:file:save-content-to-disk`、`baize:file:welcome-enter-main`、`baize:file:read-binary`、`baize:file:open-in-browser` 等）
- `IPC.FILE_MANAGER.*`：14 个文件管理通道
- `IPC.SETTING.SYSTEM_SETTING_UPDATE`：`baize:setting:updated`（系统设置/语言广播）
- `IPC.EDITOR.INIT_SETTING`：`baize:editor:init-setting`（编辑器设置初始化下发）
- `IPC.DIALOG.OPEN_VUE_DIALOG` / `DIALOG.*_ENTER`：打开 Vue 对话框 / 对话框回车确认

> 完整 91 个通道（17 组）见 `src/shared/ipc-channels.ts` 与 [IPC 通信矩阵](../../reports/md/03-专项治理/IPC通信矩阵.md)。

#### 3.2.2 状态管理

项目**已彻底移除 Vuex**（依赖、导入与用法均为零），采用：

| 机制 | 实现 | 用途 |
| ------ | ------ | ------ |
| `useConfigStore` | `src/renderer/src/common/useConfigStore.ts` | 渲染层配置状态（theme/editor/system/quickLinks），写盘去抖 200ms，`flushConfigWrites()` 关窗前落盘 |

### 3.3 预加载脚本架构

预加载脚本作为主进程和渲染进程之间的安全桥梁，产物必须是**单文件**。

| 文件 | 暴露对象 | 使用者 |
| ------ | ------ | ------ |
| `src/preload/index.ts` | `window.electron`（**受限 `ipcRenderer`**：send/invoke 白名单 60 个、on/once 白名单 25 个，不含 sendTo/sendSync 等）、`window.api`（`config.read/write`、`app` 信息） | 主窗口渲染层 |
| `src/preload/dialog.ts` | `window.electronAPI`（`send` 白名单仅 2 个回车通道：`CREATE_FILE_FOLDER_ENTER`、`RENAME_FILE_FOLDER_ENTER`；`closeDialog`；`openExternal` 仅 http/https） | HTML 对话框 |
| `src/preload/index.d.ts` | 类型声明 | 全局类型 |

> **关键约束**：主窗口与对话框均 `sandbox: true`，`electron.vite.config.ts` 的 preload 配置必须保持 `isolatedEntries: true` + `externalizeDeps: false`，禁止生成共享 chunk，否则 `contextBridge` 不注入、渲染层所有按钮失效（2026-11-15 实机事故）。

## 6. 通信机制

### 6.1 IPC 通信

**唯一真源**：`src/shared/ipc-channels.ts`（91 个通道 / 17 组；命名 `baize:<domain>:<name>`；domain 白名单 18 个，实际使用 17 个）。

**渲染进程 → 主进程（invoke / send）**：

```typescript
// 渲染层（window.electron 由 preload contextBridge 暴露）
const content = await window.electron.ipcRenderer.invoke(IPC.FILE.OPEN_SELECT_FILE, path)
window.electron.ipcRenderer.send(IPC.MENU.ACTION, 'baize:menu:file:save')

// 主进程（handlers.ts，经 ipcListenerManager 注册）
ipcListenerManager.registerHandleOnce(IPC.FILE.OPEN_SELECT_FILE, withSenderCheck(...))
```

**主进程 → 渲染进程（webContents.send）**：

```typescript
mainWindow.webContents.send(IPC.THEME.THEME_UPDATED, payload)
mainWindow.webContents.send(IPC.FILE.WELCOME_ENTER_MAIN, { type: 'directory', path })
```

**关闭/退出落盘协议**：主进程发送 `IPC.EDITOR.FLUSH_CONTENT` → 渲染层回执 `IPC.EDITOR.FLUSH_CONTENT_DONE`（2 秒超时兜底）→ 主进程 `appState.isDirty()` 时 `SaveActiveFile()`。

### 6.2 事件总线

**渲染层组件间通信**（不跨进程）：

```typescript
import { EVENT_BUS } from './common/event-bus/event-bus-events'
import { useEventBus } from './composables/useEventBus'

const bus = useEventBus()
bus.$on(EVENT_BUS.MONACO_INSERT_TEXT, handler)
bus.$emit(EVENT_BUS.PLUGIN_TOOL_SHOW, 'baize:menu:plugins:encrypt:crypto')
bus.$off(EVENT_BUS.MONACO_INSERT_TEXT, handler)
```

24 个事件常量见 `src/renderer/src/common/event-bus/event-bus-events.ts`（`plugin-tools-show`、`workspace-show`、`monaco-insert-text`、`monaco-chapters`、`theme-updated`、`status-bar-*` 等）。

### 6.3 配置读写

```typescript
// 渲染层：window.api.config.read/write（preload 暴露）
const system = await window.api.config.read('system')
await window.api.config.write('editor', editorConfig)
```

主进程 `config-manager.ts` 的 `STORE_BACKED_CONFIGS` 将 `system` / `theme` / `editor` / `quick-links` / `backup` 路由到 electron-store 模块（写入后触发布局/主题/自动保存等副作用），`recent-folders` / `show-welcome` 走裸 JSON。

## 7. 业务流程

### 7.1 应用启动流程

```
1. Electron 启动主进程（src/main/index.ts）
   ├─> initUserDataDirectory()（用户数据目录初始化）
   ├─> registerRemoteResourceGuard()（远程图表外发阻断）
   ├─> registerConfigIpcHandlers()
   └─> createWindow()
       ├─> 无框主窗口（sandbox + contextIsolation，900x650）
       ├─> 注册关闭前 flush 协议（D-3）
       ├─> ready-to-show：show() → 下发 INIT_THEME_STYLES / insertCSS(字体) / INIT_SETTING
       ├─> RegisterShortKeys() + 导航拦截 + shell 协议白名单
       └─> restoreLastOpenedFile()（后台恢复上次目录/文件）

2. 渲染进程初始化（src/renderer/src/main.ts）
   ├─> 导入样式、全局拖拽拦截
   ├─> createApp(App) + 注册 ContextMenu
   ├─> initI18n()（读取系统语言 + 订阅语言变更）
   └─> mount('#app')

3. 启动界面（2026-11-15 产品决策）
   ├─> **始终显示欢迎页**（show-welcome === false 时例外）
   ├─> 主进程恢复的数据在欢迎页期间可能被丢弃，不影响后续使用
   └─> 用户点击「最近文件夹 / 打开文件 / 打开文件夹」→ 隐藏欢迎页、最大化窗口、进入主界面
```

### 7.2 文件编辑流程

```
1. 打开文件
   ├─> 欢迎页/菜单触发 IPC.FILE.WELCOME_OPEN_FILE 或 IPC.FILE.OPEN_SELECT_FILE
   ├─> 主进程 dialog 选择文件 → 读取内容 + 编码探测（jschardet）
   ├─> 登记受信路径（Path Guard）→ 下发文件内容与目录树
   └─> 渲染层载入 Monaco 编辑器

2. 编辑文件
   ├─> Monaco change → 防抖同步内容 → 更新预览（本地渲染，150ms 防抖）
   └─> 内容指纹对比 → 脏标记

3. 保存文件
   ├─> Ctrl+S / 菜单 → IPC.FILE.SAVE_TO_DISK
   ├─> 主进程写盘（原子写 + 编码转换）→ 更新 appState 指纹
   └─> 自动保存：主进程定时器（默认 60s，可配置）仅在有脏内容时落盘

4. 关闭应用
   ├─> 主进程拦截 close / before-quit
   ├─> 发送 FLUSH_CONTENT → 渲染层 flush 编辑器内容与配置写盘
   ├─> 等待回执（2s 超时）→ 脏则 SaveActiveFile() → 真正关闭
   └─> cleanupApp()：停自动保存定时器、关 fs.watch、销毁隐藏窗口、清理 IPC 监听
```

### 7.3 主题切换流程

```
1. 用户选择主题（ThemeSettingDialog 等）
   ├─> 渲染层 send(IPC.THEME.UPDATE_THEME, themeType, monacoTheme, separate)
   ├─> 主进程 getThemeStylesByType() / getMonacoTheme()
   └─> broadcastThemeToAllWindows({ themeStyles, monacoTheme, separateEditorTheme })

2. 应用主题
   ├─> 所有窗口接收 IPC.THEME.THEME_UPDATED 广播
   ├─> 渲染层更新 CSS 变量 + Monaco 主题
   └─> 主题配置持久化（theme-config.json）

3. 预览/编辑器主题
   ├─> Monaco 主题 JSON 按需读取（theme-registry）
   └─> 独立编辑器主题开关（separateEditorTheme）
```

### 7.4 Markdown 预览流程（PF-02 本地单跳）

```
1. 内容变化（150ms 防抖）→ 大文档检测（>2MB 或 >5万行 → 降级）
2. HemyRenderPreLocal(content)        # KaTeX / admonition / tabbed / 图片与文件 URL 转换
3. editor.Render.PreMarkdownRender()  # PlantUML 本地 IPC + Mermaid 本地渲染
4. md.render()                        # markdown-it（highlight 仅显式语言）
5. HemyRenderPostLocal(html)          # 后处理（当前恒等，保留 API 对等）
6. DOMPurify.sanitize()               # XSS 消毒
7. ApplyRemoteImagePolicy()           # 远程图片默认拦截
8. v-html → 预览区
```

**Electron Fuses 发布矩阵与 E2E 分离**：

- 配置真源：`electron-builder.yml` 的 `electronFuses`（8 项全量显式声明）；矩阵语义单一真源
  `build/electron-fuses-matrix.js`（`RELEASE_FUSE_MATRIX`），构建后由

### 8.5 依赖分类策略（生产依赖 vs 打包边界，P2-5）

> 背景：2026-11-20 安全扫描 P2-5 指出「渲染层实际运行时安全库（dompurify / mermaid / katex / highlight.js / crypto-js / markdown-it-*）位于 devDependencies，而 CI 只跑 `npm audit --omit=dev`」，审计面与实际随包分发的库不一致；同时「哪些运行时库可以留在 devDependencies」缺少书面策略与自动门禁。本节固定分类策略，**可执行门禁**为 `tests/architecture/dependency-classification.test.ts`（8 用例）。

**1. 判定依据是「产物边界」，不是「运行时是否被调用」**

| 类别 | 位置 | 判定标准 | 打包行为 |
| ------ | ------ | ------ | ------ |
| 生产依赖（externalize） | `dependencies` | 主进程 `externalizeDeps: true` 时保留为 `require('pkg')`，运行时从 `app.asar/node_modules` 解析 | electron-builder 把 dependencies 的 node_modules 复制进 app.asar（现版本产物实测 111 个顶层包 / 3,522 条 node_modules 条目） |
| 打包期运行时库（Vite 内联） | `devDependencies` + 显式 allowlist | 只被 renderer / preload 源码 import，产物内已内联，运行时不存在 `require(node_modules)` 路径 | 不复制 node_modules，避免重复打包；仍由「全量树 audit」覆盖 |
| 宿主提供（不入依赖） | — | `electron` 由 Electron 运行时二进制提供；`fs` / `path` / `node:*` 为 Node 内建 | — |

**2. `dependencies`（11 个，主进程 externalize 依赖）**

`@electron-toolkit/utils`、`csv-parser`、`electron-store`、`electron-updater`、`fs-extra`、`iconv-lite`、`jschardet`、`mammoth`、`markdown-it`、`officegen`、`turndown`。

**3. `devDependencies` 中的打包期运行时库（15 个，显式 allowlist，新增需评审）**

| 包 | 层 / 打包方式 | 说明 |
| ------ | ------ | ------ |
| `vue` | renderer / Vite | Vue 3 运行时（102 个文件消费） |
| `monaco-editor` | renderer / Vite | 编辑器（别名指向 editor.api，按需 + worker chunk） |
| `mermaid` | renderer / Vite | 图表渲染（动态 `import()` 独立 chunk） |
| `katex` | renderer / Vite | 数学公式（按需动态加载 + CSS） |
| `highlight.js` | renderer / Vite | 代码高亮（core + 显式语言子路径） |
| `dompurify` | renderer / Vite | 预览 HTML/SVG 消毒（`v-html` 唯一 sink 防线，安全敏感） |
| `crypto-js` | renderer / Vite | 加密解密插件工具（渲染层实现） |
| `markdown-it-emoji` / `markdown-it-highlightjs` / `markdown-it-plantuml` | renderer / Vite | 预览管线插件（`markdown-it` 本体在主进程也使用，故留在 dependencies） |
| `@imengyu/vue3-context-menu` | renderer / Vite | 快捷菜单组件库 + CSS |
| `pdfjs-dist` | renderer / Vite | PDF 查看器（pdf.js + worker，懒加载） |
| `uuid` / `ulid` | renderer / Vite | UUID / ULID 生成插件工具 |
| `@electron-toolkit/preload` | preload / 内联 | preload 必须单文件（sandbox 硬性要求），`externalizeDeps: false` 将其内联 |

**4. 为什么这些库留在 devDependencies 是安全的**

- **产物边界**：electron-vite 对 renderer 不做 externalize，上述库已被 Rollup 内联进 `out/build/renderer`；对 preload 显式 `externalizeDeps: false` 内联进单文件产物。运行时不解析 node_modules。
- **避免重复打包**：electron-builder 只复制 dependencies 树进 app.asar（现版本 `app.asar` 实测：`fs-extra`/`markdown-it`/`mammoth`/`electron-store` 在包内，`vue`/`monaco-editor`/`mermaid`/`dompurify`/`katex`/`highlight.js`/`crypto-js`/`pdfjs-dist` 均不在）。若把这些库移入 dependencies，会在 asar 里再复制一份巨大的 node_modules（Monaco 约 7.5 MiB、Mermaid 生态约 6.5 MiB 的源文件），安装包膨胀且无任何运行时收益。
- **审计覆盖**：审计口径已由「仅生产依赖」升级为「全量依赖树（含 dev）」，见 §5。
- **版本治理**：Dependabot 的 `markdown` 分组覆盖 dompurify / mermaid / katex / highlight.js / markdown-it-*；`overrides` 对全树钉版修复版本，因此 devDependencies 中的库同样受升级与钉版保护（详见 [依赖安全治理报告](../../reports/md/03-专项治理/依赖安全治理报告.md)）。

**5. 审计口径（CI / release / 本地三方一致）**

- `package.json` 脚本：`audit` / `audit:all` = `npm audit --registry=https://registry.npmjs.org --audit-level=high`（**全量树，含 dev**）；`audit:prod` = 追加 `--omit=dev`（仅生产专项，保留用于快速核对）。
- CI `quality-gate` 与 `release.yml` 发布门禁均执行 `npm run audit:all`（不再使用 `--omit=dev` 作为唯一门禁）。
- 本地 `.npmrc` 的 registry 指向 npmmirror 镜像，该镜像**不实现 audit 端点**，直接 `npm audit` 会报 `NOT_IMPLEMENTED`；脚本显式指定官方 registry 保证本地可复现。
- 当前实测（2026-11-20，官方 registry）：全量树 **0 漏洞**。
- `overrides`（20 项）针对传递依赖钉版修复版本，作用于整棵依赖树（dev + prod 均包含），例如 `dompurify: 3.4.18` 同时约束渲染层直接依赖与 mermaid 等包的传递副本；因此「dompurify 在 devDependencies」不影响其安全修复的生效。

**6. 新增依赖的落地流程（门禁会拦截）**

1. **renderer / preload 新增库**：优先放 `devDependencies`，并在架构测试的 allowlist 追加「包 / 层 / 打包方式 / ≥20 字理由」条目、把 `EXPECTED_ALLOWLIST_SIZE` +1；漏登记会被门禁拦截。
2. **main 新增库**：必须放 `dependencies`（externalize 后运行时从 asar 解析；放 devDependencies 会被门禁拦截）。
3. 任意新增依赖都必须通过 `npm run audit:all`；包不再被 import 时，allowlist 条目会被判为「过期条目」要求删除。

**7. 本轮治理结论（保守，不擅自删依赖）**

- 15 个 allowlist 库全部被 renderer / preload 真实 import，**未发现渲染层运行时 dead dependency**。
- 一处可评估移除项：`@vue/eslint-config-typescript@14.9.0` 未被 `eslint.config.js` 引用，也不存在以 peerDependency 要求它的包（ESLint 10 flat 配置的 typescript-eslint 规则由 `@electron-toolkit/eslint-config-ts` 内含）；属工具链冗余声明，建议单独批次评估删除，本轮不改（涉及 lockfile 变更）。
