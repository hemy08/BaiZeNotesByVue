# 产品体验优化方案（美化 / 手感 / 功能增强）

> 更新于 2026-11-27　|　适用版本基线：**v1.5.3（已发布）**　|　**归属版本：v1.5.5**（体验优化线整体排入 1.5.5）　|　性质：**只读方案（本阶段不改代码）**
> 方法来源：已接入 DSH 的 ECC 技能——`design-system`、`make-interfaces-feel-better`、`frontend-design-direction`、`motion-patterns`、`accessibility`/`frontend-a11y`、`click-path-audit`、`ui-to-vue`、`benchmark`、`knowledge-ops`、`article-writing`。

## 0. 结论先行

- **功能不是短板，体验一致性是短板**：1.5.2/1.5.3 已补大量能力（剪藏、PDF 标注、OCR、日记收件箱、非模态工具窗、表格编辑器），但界面细节仍停留在"逐组件手写"阶段。
- 实测三个硬指标：**802 处硬编码色值散落 80 个文件**、**242 处圆角用了 21 种不同值**、**91 处 transition 无统一时长/缓动**；MenuBar 无 `role`/`aria`/键盘处理，`tabindex` 全仓仅 12 处。
- 这意味着：**换主题时部分 UI 不跟随（视觉破功）**、**新组件视觉风格随机**、**键盘用户无法完整操作**、**动效节奏忽快忽慢**。
- 方案分三线：**A 视觉统一（美化）→ B 交互手感（体验）→ C 功能闭环（产品能力）**，均以"等值替换/规范统一/不重设计"为边界。

## 1. 现状盘点（实测，2026-11-27）

| 维度 | 实测 | 解读 |
| --- | --- | --- |
| 硬编码色值 | **802 次 / 80 个文件** | 28 套主题下这些地方不跟随变量 → 主题切换局部不协调；深/浅色对比可能失效 |
| 圆角 | 242 次 / **21 种值** | 视觉层级混乱（按钮 4px/6px/8px/10px 混用） |
| 间距 | 无统一令牌，散落 padding/margin | 4px 基准未落地，布局"差 2px"感 |
| 动效 | transition 91 次，无时长/缓动规范 | 弹窗/页签/悬浮反馈节奏不一致；无"减少动效"偏好支持 |
| 可访问性 | aria 138 / role 107 / **tabindex 12**；MenuBar 无 role/aria/keydown | 键盘无法完整操作菜单；焦点管理仅对话框具备 |
| 组件规模 | 120 个 Vue、22 个 CSS、48 个对话框 .vue | 规模已大，靠"每个组件手写样式"不可持续 |
| 已有优势 | 28 应用主题 + 57 Monaco 主题、对话框 BaseDialog+a11y、命令面板、非模态工具窗、设计变量 20 个 | 底座齐备，缺"令牌化 + 规范 + 门禁" |

## 2. 线 A：视觉统一（美化）—— 先让"换主题不破功"

> 目标：**视觉一致性**（不是重设计）。所有动作以"等值替换 + 取值归一 + 主题逐套校验"为边界，像素级外观默认不变；确需视觉提升的项单独列 P2 由你拍板。

| 编号 | 优化项 | 做法（技能） | 产出 | 优先级 |
| --- | --- | --- | --- | --- |
| A1 | 设计令牌抽取 | `design-system`：从现有 20 个 CSS 变量 + 实际取值抽取三层令牌（基础/语义/主题映射） | `docs/design/design-tokens.json` + `DESIGN.md` | P0 |
| A2 | 硬编码色清理 | 802 处按"映射到最近语义令牌 → 等值替换"清理，阴影/rgba 白名单标注 | 清理清单 + 分批 PR（按文件域） | P1 |
| A3 | 圆角归一 | 21 种 → 4 档（`2/4/6/8px`，控件/卡片/弹窗/胶囊），逐处确认无视觉变化 | 圆角规范 + 替换 | P1 |
| A4 | 间距阶梯 | 落地 4px 基准（4/8/12/16/24/32），替换散落 magic number | 间距规范 | P1 |
| A5 | 阴影/层级 | 定义 3 档阴影（卡片/悬浮/弹窗）+ z-index 层级表 | 阴影规范 | P1 |
| A6 | 28 主题逐套校验 | 每个主题跑"变量覆盖 + 对比度 + 关键页截图"矩阵 | 主题一致性矩阵（28×N） | P2 |
| A7 | 反 AI-slop 审计 | `design-system` 10 维评分 + AI-slop 清单（泛滥渐变、随机大圆角、过度阴影、每处不同字号） | 评分报告 + 清理建议 | P0（报告） |

**验收**：硬编码色（白名单外）→ 0；圆角种类 ≤4；间距全部来自阶梯；28 主题 100% 变量覆盖；评分报告维度得分可量化对比。
**风险**：等值替换不彻底会引入细微色差 → 每批配截图对比（主题切换前后各一张）；不做布局重排。

## 3. 线 B：交互手感（体验）—— 让"能发现、有反馈、可键盘"

| 编号 | 优化项 | 做法（技能） | 产出 | 优先级 |
| --- | --- | --- | --- | --- |
| B1 | 菜单键盘可达 | `accessibility`：MenuBar 补 `role="menubar"/"menu"/"menuitem"`、方向键/Enter/Esc/Home/End、焦点可视 | a11y 修复 + 测试 | P0 |
| B2 | 工具窗/表格键盘操作 | 非模态工具窗（1.5.3）补焦点陷阱/外部点击语义/`Esc` 行为、表格单元格键盘导航 | 键盘矩阵测试 | P0 |
| B3 | 焦点与对比度审计 | 全量检查 focus-visible、对比度（WCAG 2.2 AA 4.5:1）、`prefers-reduced-motion` | a11y 审计报告 | P0 |
| B4 | 动效规范 | `motion-patterns` 思想迁移：统一时长（150/200/300ms）+ 缓动（标准/强调/退出）+ 减少动效降级 | `docs/design/MOTION.md` | P1 |
| B5 | 空态/加载/错误态统一 | 新建/搜索/工具窗/OCR 等 6 处空态与加载骨架、错误可重试文案 | 状态组件 + 使用清单 | P1 |
| B6 | 新能力首次引导 | 剪藏/OCR/PDF 标注/日记收件箱 4 项：首次使用 1 步提示（在哪开、做什么），可"不再提示" | 引导组件 + 设置项 | P1 |
| B7 | 操作反馈与进度 | 剪藏/OCR/PDF 保存/主题切换的进度与成功反馈（复用状态栏/Toast 体系，避免重复弹窗） | 反馈清单 | P1 |
| B8 | 点击链路终态审计 | `click-path-audit`：P0 十链路（含 1.5.3 非模态工具窗、表格编辑）判定"单独可用但组合后终态错误" | 审计报告 + 断言用例 | P2 |
| B9 | 性能体感 | `benchmark`：启动/切换/首帧/大文档滚动体感基线；长列表/表格虚拟化评估 | 体感基线报告 | P2 |

**验收**：MenuBar 键盘 100% 可达（有测试）；对比度不达标项清零；4 项新能力 100% 有首次引导；空态/加载/错误 3 类状态有统一组件；P0 链路有 PASS/FAIL 判定。
**风险**：a11y 补属性可能影响既有测试快照 → 分组件推进并同步测试。

## 4. 线 C：功能闭环增强（产品能力）—— 把已有能力"用起来"

> 只做**现有能力的闭环与导出/整理**，不引入新服务；每项都可独立批准。

| 编号 | 优化项 | 说明（技能） | 用户价值 | 优先级 |
| --- | --- | --- | --- | --- |
| C1 | 剪藏闭环 | 剪藏后自动归档到收件箱 + 来源卡片（标题/URL/时间）+ 一键整理成笔记（`knowledge-ops` 摄取/去重思想） | 采集→整理→沉淀全流程 | P1 |
| C2 | OCR 闭环 | 识别结果可"插入/复制/追加到笔记"，并记录来源图片；中文语言包（chi_sim）评估 | 截图资料可搜索/可引用 | P1 |
| C3 | PDF 摘录闭环 | 摘录批量汇出为笔记、标注列表可筛选"已摘录/未摘录" | 读书笔记高效 | P1 |
| C4 | 日记/收件箱增强 | 日记模板变量增强（天气/待办/回顾）、收件箱三栏（待整理/已归档） | 日常记录更顺手 | P2 |
| C5 | 知识库检索增强 | `knowledge-ops`：标签聚合页 + 搜索排序（最近/相关）+ 结果高亮（复用现有索引） | 知识"找得到" | P2 |
| C6 | 写作声音一致性 | `article-writing` 方法：写作模式下的风格检查增强（语气/句式/术语表） | 长文质量 | P2 |
| C7 | 表格编辑器体验 | 1.5.3 表格续作：粘贴 Excel 多单元格、列类型（文本/数字/日期）、行操作 | 表格真正可用 | P1（1.5.3 延续） |
| C8 | 导出/分享体验 | 导出预设（PDF 主题/页眉页脚）、导出进度 | 输出专业 | P2 |
| C9 | 设计稿转界面 | `ui-to-vue`：未来新界面用截图/设计稿批量生成 Vue 组件（开发效率） | 迭代更快 | P2（工具链） |

## 5. 批次与验收指标

> **版本归属：v1.5.5**（1.5.3 已于 2026-11-27 发布）。视觉统一线已升级为独立的[视觉升级方案](视觉升级方案-1.5.5.md)（含设计方向与组件规格），本文保留三线总纲与功能闭环部分。

| 批次 | 内容 | 预估 | 验收指标 |
| --- | --- | --- | --- |
| **P0（约 1 周）** | A1 令牌抽取、A7 评分报告、B1 菜单键盘、B2 工具窗/表格键盘、B3 a11y 审计 | 4~5 人日 | 令牌文件落地；a11y 审计报告；MenuBar 键盘测试通过 |
| **P1（约 2 周）** | A2 硬编码色清理（分批）、A3 圆角、A4 间距、A5 阴影、B4 动效规范、B5 状态组件、B6 首次引导、C1/C2/C3 闭环 | 8~10 人日 | 硬编码色→0（白名单外）；圆角 ≤4 档；4 项能力有引导；3 个闭环可用 |
| **P2（3~4 周）** | A6 主题矩阵、B8 链路审计、B9 性能体感、C4~C9 | 10~15 人日 | 28 主题矩阵全绿；链路 PASS/FAIL；体感基线可对比 |

## 6. 需要你拍板的三件事

1. **美化边界**：接受"等值替换 + 规范归一（视觉零变化）"，还是要**视觉升级**（重设计部分界面，如工具窗/表格/菜单，需先出设计方向稿）？
2. **优先级**：先做 **P0（令牌 + a11y + 键盘可达）**，还是先做 **P1 的 C1~C3 功能闭环**（用户感知更强）？
3. **功能增强范围**：C 线里先做哪 2~3 项（建议 C1 剪藏闭环 + C2 OCR 闭环 + C7 表格续作，与 1.5.3 主线衔接）？
