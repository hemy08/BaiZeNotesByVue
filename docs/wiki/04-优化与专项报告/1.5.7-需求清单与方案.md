> 边界（计划 §1 已明确）：**不复制 LLM Wiki 桌面应用的全部 UI**（图谱/聊天/审阅），白泽只做**编辑、审阅、检索、管理工作台**；用 Markdown 文件 + MCP 对接。

## 1. 需求背景

- **LLM Wiki 模式**（Karpathy 2026-04 提出）：原始资料存于 `raw/` 且不可变 → LLM 持续将其"编译"为可被人类与 AI 共同消费的结构化知识库（`wiki/` + `schema.md` + `CLAUDE.md`）；核心价值是"编译态知识"而非"原始资料"的散乱堆积。
- **白泽现有能力映射**：B1（Wiki 双链/反链）、B2（标签/部分全文索引）、B3（关系图谱）、B5（附件管理）、D1~D8（编辑器能力）等基座已具备；工作区索引缓存 TTL 5s、`FILE.GET_WORKSPACE_INDEX` 为当前知识库基座。
- **集成目标**：0~3 个月完成 L1（工作区模板 + `raw/` 只读 + 只读 MCP Server）与 L2（MCP 只读接口），后续 AI MVP / B3 / E5 独立推进。

## 3. 建议的 1.5.7 范围与批次

1. **批次 1（P0）**：REQ-W01~W06（L1）→ 完成可用的「LLM Wiki 工作区模式」
2. **批次 2（P0）**：REQ-W07~W11（L2 MCP 桥）→ 外部 Agent 可只读访问
3. **批次 3（P1，可选/1.5.8）**：REQ-W12（L3 AI ingest + diff 审批）、REQ-W13（L4 图谱/嵌入）
4. **贯穿**：REQ-W14/W15（文档/链接/类型/单测/安全门禁）

> 建议先交付 P0（L1+L2）形成完整闭环（人可编辑 + AI 可只读接入），再按实际需求决定 L3/L4 节奏。

## 4. 验收指标

| 指标 | 目标 |
| --- | --- |
| LLM Wiki 初始化 | 一键生成 `raw/` / `wiki/` / `schema.md`，菜单与命令面板双入口可用 |
| `raw/` 只读 | 新建/保存/重命名/删除被拒绝并给出可理解提示；`wiki/` 不受影响 |
| 索引隔离 | 搜索/索引/图谱不含 `raw/` 内容 |
| 模式切换 | 设置页可切换 + 确认对话框 + 重启保持 + 取消不写入 |
| MCP 桥 | 4 个只读工具可被外部 Agent 调用；只读边界不可突破 |
| 安全门禁 | IPC 常量/契约/白名单/ sender 校验齐全；CSP/fuses 不放宽；无新增例外 |
| 工程门禁 | 全量测试/覆盖率/typecheck/ESLint/Prettier/docs:check/quality 全绿；新增 E2E 规格通过 |

## 5. 风险与依赖

- **风险**（计划 §9）：`raw/` 只读导致用户困惑（初始化文档说明 + 设置页提示）；MCP Server 调试成本（提供 PoC、外部 Agent 验证）；AI ingest 性能（先小规模 `raw/` 测试、批量阈值）；图谱 UI 重复造轮（图谱与知识库查询对话框分离，按 B3 独立推进）。
- **依赖基线**：1.5.6 已发布（375 文件 / 7,041 用例、IPC 108 通道 / 18 组、preload 白名单 74+28+6、CSP/fuses 8 项、体积预算 9 项）；实施计划中的文件位置需在开工前按 1.5.6 现状复核。

## 6. 需要拍板

1. **1.5.7 范围**：只做 P0（L1+L2，约 2~3 周）还是含 P1（L3/L4，另需 5~7 周）？
2. **MCP 传输方式**：stdio / HTTP / SSE？工具清单以计划 T2.2 的 4 个只读工具为准吗？
3. **AI ingest（L3）**：本地模型还是远程 API（涉及隐私与依赖）？是否在 1.5.7 内？
4. **计划文档更新**：实施计划开头标注的版本基线（v1.5.6 开发中）需随 1.5.7 启动同步更新，是否由我一并更新？
