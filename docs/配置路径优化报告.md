## 修改内容

### 1. electron-builder.yml 配置优化

**修改前问题**:
- extraResources 配置导致 resources 目录嵌套
- 打包后路径: `win-unpacked/resources/resources/...`

**修改后方案**:
```yaml
extraResources:
  - from: "resources/config"
    to: "config"
  - from: "resources/icon"
    to: "icon"
  - from: "resources/katex"
    to: "katex"
  - from: "resources/themes"
    to: "themes"
  - from: "resources/mermaid"
    to: "mermaid"
  - from: "resources/plantuml"
    to: "plantuml"
```

**效果**:
- 打包后路径: `win-unpacked/config/...`
- 资源文件与 resources.asar 同级

## 技术实现细节

### 1. 路径管理 (app-paths.ts)

**核心功能**:
```typescript
// 获取用户数据目录
getUserDataPath() → C:\Users\用户\.baizenotes

// 获取应用资源目录
getAppResourcesPath() → 
  开发环境: 项目目录/resources
  生产环境: 安装目录

// 获取各种资源路径
getIconPath()
getThemesPath()
getKatexPath()
getMermaidPath()
getPlantumlPath()
```

**环境适配**:
- 开发环境: 使用项目目录下的 resources
- 生产环境: 使用安装目录下的资源

### 2. Store 工厂 (store-factory.ts)

**统一配置**:
```typescript
export function createStore<T>(name: string, defaults: T): Store<T> {
    const userDataPath = getUserDataPath()
    const configDir = path.join(userDataPath, 'config')
    
    return new Store<T>({
        name,
        cwd: configDir,
        defaults
    })
}
```

**优势**:
- 统一配置文件位置
- 简化 Store 创建过程
- 便于维护和修改

### 3. 主进程初始化

**初始化流程**:
```typescript
app.whenReady().then(() => {
    // 1. 初始化用户数据目录
    initUserDataDirectory()
    
    // 2. 创建窗口
    createWindow()
    
    // 3. 其他初始化...
})
```

### 4. NSIS 卸载脚本

**脚本逻辑**:
```nsis
!macro customUnInstall
    MessageBox MB_YESNO "是否保留配置？" IDYES Keep IDNO Delete
    
    DeleteConfig:
        RMDir /r "$PROFILE\.baizenotes"
        Goto Done
    
    KeepConfig:
        ; 保留配置
        Goto Done
    
    Done:
!macroend
```
