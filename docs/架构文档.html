一、项目概览

定位

本地优先 Markdown 笔记

基于 Electron + Vue 3 的桌面端 Markdown 编辑器，以本地文件为基础，不依赖云端服务。

技术栈

Electron 28 + Vue 3 + TypeScript

主进程 Electron 28，渲染进程 Vue 3.4 + TypeScript 5.3，预加载层安全桥接。

编辑器

Monaco Editor 集成

基于 Monaco Editor 0.45，内置多种主题，支持代码高亮和编辑增强。

架构

多进程架构

Electron 的 Main / Preload / Renderer 三进程模型，IPC 通信，安全沙箱。

二、系统架构

采用 Electron 经典三进程架构：Main Process 负责系统集成与文件 I/O，Preload 提供安全上下文桥接，Renderer 运行 Vue 3 应用。

关键技术决策

  • 类型安全：全栈 TypeScript，主进程到渲染进程共享接口定义
  • 安全通信：通过 contextBridge 暴露受限 API，遵循最小权限原则
  • 构建统一：Vite 5 构建主进程和渲染进程，electron-builder 打包
  • 状态管理：Pinia 管理前端状态，主进程状态通过 IPC 同步

三、主进程 Main Process

主进程是 Electron 应用的入口，负责窗口管理、系统菜单、文件 I/O、自动更新等。

核心职责

  • 窗口管理：创建/管理 BrowserWindow，窗口大小记忆
  • 文件系统：文件的打开/读取/写入/保存，目录遍历
  • IPC 通信：响应渲染进程的上下文菜单、对话框、原生功能调用
  • 应用生命周期：启动、激活、退出等事件处理

IPC 通道概览

四、预加载层 Preload

预加载脚本在渲染进程创建前执行，通过 contextBridge 向渲染进程暴露安全的 API。

安全策略

  • contextIsolation: true — 隔离渲染进程上下文
  • nodeIntegration: false — 禁用 Node.js 集成
  • sandbox: true — 启用沙箱
  • 仅暴露白名单 API，每个方法都有类型定义

六、数据流

用户操作在渲染进程触发，通过 Preload API 经 IPC 传达至主进程；主进程执行文件 I/O 后返回结果。

Renderer→Preload API→Main Process→File System

典型流程：打开文件

  • Renderer 调用 window.api.openFile()
  • Preload 通过 ipcRenderer.invoke 发送到主进程
  • Main 显示原生对话框，读取文件内容
  • 内容经 IPC 返回 Renderer，更新编辑器内容
点击打开→ipcRenderer.invoke→dialog.showOpenDialog→fs.readFile→Monaco 显示

ADR-001: Electron 技术栈选型已采纳

日期：2024-01 · 决策者：hemy08

背景

需要开发一款跨平台桌面笔记应用，支持 Windows、macOS、Linux 三个主流操作系统，要求具备原生桌面能力和 Web 前端开发效率。

决策

选择 Electron 38 + Vue 3.4 + TypeScript 6 作为核心技术栈。

理由

  • Electron：跨平台支持最成熟，文档丰富，社区庞大，可访问全部 Node.js 和原生 API
  • Vue 3：Composition API 提供更好的逻辑复用，响应式系统性能优异，TypeScript 支持完善
  • TypeScript：强类型保障代码质量，IDE 支持完善，重构安全

备选方案

  • Tauri：包体积更小，但 Rust 后端增加团队学习成本，且原生 API 覆盖不及 Electron
  • NW.js：生态不如 Electron，社区活跃度较低

影响

  • 安装包体积 ~150MB（含 Chromium）— 可接受
  • 内存占用 ~200MB — 在当前硬件水平下合理
  • 开发效率显著提升，Vue HMR + TypeScript 类型检查
ADR-002: Monaco Editor 选型已采纳

日期：2024-01 · 决策者：hemy08

背景

需要为用户提供专业的 Markdown 编辑体验，包括语法高亮、智能提示、快捷键、多光标编辑等功能。

决策

采用 Monaco Editor 0.55 作为核心编辑器组件。

理由

  • VS Code 同款编辑器，用户熟悉度高，开箱即用体验优秀
  • 原生 TypeScript 支持，与代码库语言一致
  • 语法高亮覆盖 100+ 语言，Markdown 编辑体验极佳
  • 快捷键系统与 VS Code 一致
  • 支持自定义语言和主题，扩展性强
  • 大文件处理性能优于 CodeMirror

影响

  • 包体积增加 ~2MB — 可接受
  • 首次初始化时间略长（~1-2s）— 已通过延迟加载优化
ADR-003: IPC 通信架构（禁用 remote）已采纳

日期：2024-01 · 决策者：hemy08

背景

Electron 渲染进程需访问主进程能力（文件操作、原生对话框、配置存取），需选择安全的通信方式。

决策

采用 IPC 通信模式（ipcMain.handle/ipcRenderer.invoke + ipcMain.on/ipcRenderer.send），禁用 @electron/remote 模块。使用 ipcListenerManager 统一管理监听器生命周期。

理由

  • 安全性：remote 模块存在严重安全风险
  • 性能：IPC 异步非阻塞，不影响 UI 线程
  • 最佳实践：Electron 官方推荐 IPC 而非 remote
  • 可控性：ipcListenerManager 提供注册/注销/统计能力

影响

  • 需手动定义和维护 IPC 通道清单（20+ 通道）
  • 代码量略增，但安全性和可维护性提升
ADR-004: CSS 变量主题系统已采纳

日期：2024-02 · 决策者：hemy08

背景

应用需要支持多主题（23 种应用主题 + 55 种编辑器主题），且要求在运行时即时切换，无需重启应用。

决策

应用主题使用 CSS 变量 方案（:root { --bg: #fff } → JS 修改 documentElement.style.setProperty()）。编辑器主题通过 monaco.editor.defineTheme() 动态注册。

理由

  • 运行时即时切换，无闪烁，无需重新加载
  • CSS 变量传播到所有子元素，一改全改
  • 添加新主题只需定义变量值集合，无需改逻辑
  • 性能优异（GPU 加速的 CSS 重绘）

影响

  • 主题切换零延迟，用户体验流畅
  • 主题配置集中管理（theme-config.ts 中约 60+ CSS 变量）
ADR-005: 定时器 + 脏检查自动保存已采纳

日期：2024-02 · 决策者：hemy08

背景

需要防止用户因忘记保存或意外崩溃导致数据丢失，同时避免频繁磁盘 I/O 影响性能。

决策

采用 定时器轮询 + 脏标志检查 策略：每 30s（用户可配置）检查 global.current_active_file.content 是否有修改，有修改则调用 SaveActiveFile()。

理由

  • 仅在内容真正变化时写盘，减少不必要 IO
  • 保存间隔用户可配（10s/30s/60s/关闭）
  • 实现简单可靠，不引入复杂的数据流追踪

影响

  • 数据安全性大幅提升，崩溃最多丢失 30s 内容
  • 性能影响极小（仅内存比较 + 条件写盘）
ADR-006: electron-store 持久化方案已采纳

日期：2024-01 · 决策者：hemy08

背景

需要持久化存储应用配置（主题选择、窗口位置、编辑器设置、最近文件列表等），要求简单可靠。

决策

采用 electron-store 8.2.0 作为持久化存储方案，并进行封装（baize-store.ts）添加类型安全 StoreFactory 和 LRU 缓存层。

理由

  • API 简洁：store.get(key)/set(key)，零学习成本
  • 默认使用 JSON 文件存储，人类可读
  • 自动处理文件同步，无需手动管理
  • 封装后提供类型安全接口 + LRU 缓存热点数据

影响

  • 配置读写性能优异（JSON 文件 + 内存 LRU）
  • 数据存储在 ~/.baizenotes/，用户可手动查看和修改
  • LRU 缓存 max 50 文件，防止内存膨胀
ADR-007: Vuex + reactive 分层状态管理已采纳

日期：2024-02 · 决策者：hemy08

背景

应用包含持久化状态（配置）和运行时状态（编辑器内容、UI 状态），需要清晰的分层管理策略。

决策

采用分层策略：持久化层（electron-store 存储配置）+ 运行时层（Vue reactive + Vuex 管理 UI 状态）+ 通信层（EventBus 组件间通信）。

理由

  • 分离持久/运行时状态，减少不必要的磁盘写入
  • Vuex 管理跨组件共享的全局状态
  • Vue reactive 管理局部运行时状态
  • EventBus 处理组件间松耦合通信（含自动清理 + 泄漏检测）

影响

  • 状态流向清晰：reactive → watch → IPC → store
  • EventBus 泄漏检测工具化，避免内存泄漏
ADR-008: 预加载脚本安全隔离策略已采纳

日期：2024-01 · 决策者：hemy08

背景

Electron 应用中，渲染进程运行在浏览器环境，需安全可控地访问主进程能力，防止 XSS 攻击升级为 RCE。

决策

启用 contextIsolation: true + nodeIntegration: false，使用 contextBridge.exposeInMainWorld() 精确暴露 window.electron（IPC 通信）和 window.api（配置 + 版本信息）。

理由

  • 最严格的 Electron 安全配置组合
  • 最小权限原则：只暴露渲染进程真正需要的 API
  • 明确的安全边界：渲染进程无法直接 require Node.js 模块

影响
