## 一、hosts 修改方案

### 1.1 GitHub520（521xueweihan/GitHub520）——仍在维护 ✅

- 项目地址：https://github.com/521xueweihan/GitHub520
- **最新 IP 列表直链（无需访问 GitHub）**：
    - 文本：`https://raw.hellogithub.com/hosts`（旧域名 `raw.520e.com` 已不再使用）
    - JSON：`https://raw.hellogithub.com/hosts.json`
- 实测证据：本会话 `web_fetch` 拉取 `https://raw.hellogithub.com/hosts` 与 `hosts.json` 均成功返回（HTTP 200），数据更新时间 `2026-11-14T20:12:33+08:00`；README 内嵌的 hosts 内容与之一致。
- ⚠️ 风险：README 顶部注明"服务器将于 2026-12-31 到期，续费需要 831 元/年"，即直链存在到期停更风险（第三方分析同样指出：https://hysenlabs.com/projects/521xueweihan-github520）。

**Windows 手动步骤**（摘自官方 README，2026-11-14 核实）：

1. 浏览器打开 `https://raw.hellogithub.com/hosts`，全选复制。
2. 以管理员身份用记事本打开 `C:\Windows\System32\drivers\etc\hosts`，把内容粘贴到末尾并保存。
3. CMD 执行 `ipconfig /flushdns` 刷新 DNS 缓存（无效可重启）。

**Windows 一键/自动更新方式（官方推荐 SwitchHosts）**：

- 下载 [SwitchHosts](https://github.com/oldj/SwitchHosts) → 新建规则，类型选 `Remote`，URL 填 `https://raw.hellogithub.com/hosts`，自动刷新设 1 小时。
- 命令行脚本（需 Git Bash，可加入任务计划程序定时执行）：

```shell
_hosts=$(mktemp /tmp/hostsXXX)
hosts=/c/Windows/System32/drivers/etc/hosts
remote=https://raw.hellogithub.com/hosts
reg='/# GitHub520 Host Start/,/# Github520 Host End/d'
sed "$reg" $hosts > "$_hosts"
curl "$remote" >> "$_hosts"
cat "$_hosts" > "$hosts"
rm "$_hosts"
```

- 第三方一键小工具：[YubaC/Github-Host-Updater](https://github.com/YubaC/Github-Host-Updater)（数据源同为 GitHub520，Release 较旧，保守使用）。

**注意事项**：

- IP 会变：需定期（建议每天/每周）更新，否则过期 IP 反而导致连不上。
- TLS 证书不受影响：hosts 只改 IP 解析，SNI/证书仍用官方域名，HTTPS 安全性不变。
- hosts 只解决"DNS 污染/解析到差 IP"问题，**解决不了 SNI 阻断和 IP 级连接重置**。
- 与 Watt Toolkit（Steam++）的 hosts 加速可能互相覆盖/冲突（HelloGitHub 用户评论证实，需先清理再二选一）。
- 只解决网页打开慢与图裂，对 clone/大文件下载提速有限。

### 2.2 git 配置命令

```bash
# 全局一次配置：所有 https://github.com/... 自动改写走镜像（clone/pull/fetch 生效）
git config --global url."https://gh-proxy.com/https://github.com/".insteadOf "https://github.com/"

# 之后照常使用官方地址即可：
git clone https://github.com/xxx/yyy.git

# 查看/取消配置
git config --global --get-regexp url
git config --global --unset url."https://gh-proxy.com/https://github.com/"

# 临时单次克隆（不写配置）
git clone --depth 1 https://gh-proxy.com/https://github.com/xxx/yyy.git

# 下载 release 文件
wget https://gh-proxy.com/https://github.com/xxx/yyy/releases/download/v1.0/file.zip
```

### 2.3 安全注意事项（重要）

- 第三方镜像可**篡改**返回内容：重要仓库（公司/生产依赖）不要走公共镜像，或克隆后核对官方 commit sha256 / 发布签名。
- **私有仓库、带 token/OAuth 的 URL 严禁走公共镜像**（凭据会被镜像方看到）。
- 镜像只支持读（clone/pull/raw/release），**不支持 push**；push 需走官方地址或 SSH。
- `insteadOf` 是全局生效的，配置后所有 GitHub 克隆都会走镜像，不想要时记得 unset。

## 四、DNS 优化：换 223.5.5.5 / 119.29.29.29 / DoH 有用吗？

**结论：只解决"纯 DNS 污染"，解决不了 SNI 阻断与 IP 级连接重置；单独使用效果有限，需与 hosts 组合。**

- 2026 年 GitHub 的问题通常是多层叠加：DNS 污染 + 部分 IP 被阻断 + 偶发 SNI 阻断。2026-08 的一篇排障实测（https://maoruoyu.github.io/posts/2026-08-08-github-sni-fix.html ）显示：DNS 解析是干净的，但 `github.com` 唯一返回的 IP 恰好被封、`github.io` 秒重置——这种场景换 DNS 完全无效，必须换 IP（hosts）。
- 另一实测（https://mhdy2233.github.io/archives/shi-yong-adguardzuo-wei-doh-dotlai-dui-kang-dnswu-ran-yi-ji-tong-guo-echtu-po-snifeng-suo/ ）认为 GitHub 主要是 DNS 污染、偶发 SNI 阻断——该场景 DoH/DoT 有效。
- 常见做法：Windows 11「设置 → 网络和 Internet → 以太网/WLAN → DNS 服务器分配 → 手动」，首选 `223.5.5.5`（阿里，DoH：https://dns.alidns.com/dns-query ），备选 `119.29.29.29`（腾讯 DNSPod，DoH：https://doh.pub/dns-query ），并开启 DoH 防运营商劫持/污染。
- 结论建议：换抗污染 DNS + hosts 指定可用 IP 双管齐下，比单换 DNS 有效得多。

## 五、SSH 走 443 端口（ssh.github.com:443）

已核实 GitHub 官方文档（https://docs.github.com/zh/authentication/troubleshooting-ssh/using-ssh-over-the-https-port ），当前仍有效：

**测试 443 是否可用：**

```bash
ssh -T -p 443 git@ssh.github.com
# 成功返回: Hi USERNAME! You've successfully authenticated...
```

**`~/.ssh/config` 写入（Windows 为 `C:\Users\<用户名>\.ssh\config`）：**

```text
Host github.com
    Hostname ssh.github.com
    Port 443
    User git
```

之后 `ssh -T git@github.com` 与普通 clone 都会自动走 443。

**局限（如实说明）：**

- 主要解决"22 端口被防火墙/运营商拦截"的场景；对 GitHub Enterprise Server 与带数据驻留的 Enterprise Cloud 不支持（官方声明）。
- 若 `ssh.github.com` 的 IP 本身被阻断/重置（中国大陆常见），443 方案同样无效；此时需配合 hosts 给 `ssh.github.com` 绑定可用 IP（GitHub520 的 hosts 未包含该域名，需自行测试添加）。
- 首次连接需按官方指纹核对 known_hosts（指纹列表见 GitHub 官方文档）。

## 七、推荐组合方案（按性价比/稳定性）

1. **网页访问/图裂（零成本，第一优先）**：Windows 11 系统 DNS 改为 `223.5.5.5`/`119.29.29.29` 并开 DoH；再用 [SwitchHosts](https://github.com/oldj/SwitchHosts) 订阅 `https://raw.hellogithub.com/hosts`（1 小时自动刷新）。⚠️ 注意该直链 2026-12-31 服务器到期风险，备选订阅 [ittuann/github-ip-hosts](https://github.com/ittuann/github-ip-hosts)。
2. **clone / 下载（日常主力）**：`git config --global url."https://gh-proxy.com/https://github.com/".insteadOf "https://github.com/"`（实测最稳），ghproxy.net 作为备选随时切换；release 大文件同样加前缀。私有/重要仓库直连并校验哈希，不走公共镜像。
3. **可选增强**：Watt Toolkit（steampp.net）或 DevSidecar——注意二者与 hosts 方案二选一，避免冲突。
4. **push / 端口受限兜底**：SSH over 443（`~/.ssh/config` 配 `ssh.github.com:443`）；若 IP 级阻断依然失败，则只剩正规代理通道（超出本报告范围）。
5. **稳定程度排序（2026-11-14 实测 + 社区记录）**：gh-proxy.com ≈ ghproxy.net > ghfast.top（时好时坏）> gh.ddlc.top / gh.llkk.cc（未验证）> mirror.ghproxy.com / ghp.ci / cnpmjs（已失效）。
