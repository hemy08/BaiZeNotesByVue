## 三、代码适配修复

依赖升级后，部分 API 发生变化，需要适配代码：

### 3.1 markdown-it 15 适配

**文件：** `src/main/renders/MaterialRender.ts`

`highlight` 选项从 plugin 选项移到 `MarkdownIt` 构造函数：

```ts
// 旧：highlight 作为 plugin 选项
const md = new MarkdownIt().use(highlightjs, { highlight: ... })

// 新：highlight 作为构造函数选项
const md = new MarkdownIt({ highlight: ... }).use(highlightjs)
```

**文件：** `src/renderer/src/components/Markdown/hemy-editor-render.ts`

`MarkdownIt` 类型引用方式变化：

```ts
// 旧：直接用作类型
function ParserMarkdownChapters(md: MarkdownIt, text: string)

// 新：使用 InstanceType
function ParserMarkdownChapters(md: InstanceType<typeof MarkdownIt>, text: string)
```

`parse` 方法的 `env` 参数类型从数组改为对象：

```ts
// 旧
const tokens = md.parse(text, [])

// 新
const tokens = md.parse(text, {})
```

### 3.2 monaco-editor 0.56 适配

**文件：** `src/renderer/src/components/Markdown/editor-options.ts`

`hover.enabled` 和 `hover.sticky` 的类型交换：

```ts
// 旧
hover: { enabled: true, sticky: false }

// 新
hover: { enabled: 'on', sticky: false }
```

### 3.3 vue-tsc 3.x 适配

**文件：** `tsconfig.web.json`

vue-tsc 3.x 严格执行 `noUnusedLocals`，但 Vue `<script setup>` 中 ref 变量在模板中使用不应报错。关闭此选项：

```json
{
  "compilerOptions": {
    "noUnusedLocals": false,
    "noUnusedParameters": false
  }
}
```

### 3.4 vitest 4.x 升级

vitest 3.x 的依赖 `loupe@3.2.1` 与 Node.js 24 不兼容（ESM 语法错误），升级到 vitest 4.x 解决。

## 六、已知问题与注意事项

### 6.1 Electron 二进制未自动下载

`npm install` 后 Electron 43 的二进制文件（`node_modules/electron/dist/electron.exe`）未自动下载，导致 `npm run dev` 报错 `Error: Electron uninstall`。需手动执行：

```bash
node node_modules/electron/install.js
```

或设置镜像后执行：

```bash
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
node node_modules/electron/install.js
```

**根因：** Electron 43 的 `package.json` 中 `postinstall` 脚本为空，不再自动触发二进制下载。

### 6.2 app-builder.exe x64 崩溃

`app-builder-bin@4.2.0` 的 x64 二进制在 Windows 10.0.26200 上启动即崩溃（`STATUS_STACK_BUFFER_OVERRUN`）。临时修复：用 ia32 二进制替换 x64。

```powershell
Copy-Item "node_modules\app-builder-bin\win\ia32\app-builder.exe" `
          "node_modules\app-builder-bin\win\x64\app-builder.exe" -Force
```

**注意：** `npm install` 后需重新执行此替换。

### 6.3 缺失资源目录

0

构建时出现警告：
- `resources/katex` 目录不存在
- `resources/mermaid` 目录不存在

不影响打包，但相关资源不会包含在安装包中。

### 6.4 vitest 配置警告

vitest 4.x 运行时警告 `vitest.config.ts` 使用 ESM 语法但被加载为 CommonJS。可通过将文件重命名为 `vitest.config.mjs` 或在 `package.json` 中添加 `"type": "module"` 解决。

### 6.5 大版本升级风险

以下大版本升级的 API 变化已适配，但建议在后续开发中关注：
- `electron-store` 8 → 11：ESM 导入方式
- `markdown-it` 14 → 15：类型导出和 `parse` 方法签名
- `jsdom` 24 → 29：API 可能变化
- `uuid` 10 → 14：API 可能变化
- `ulid` 2 → 3：API 可能变化
