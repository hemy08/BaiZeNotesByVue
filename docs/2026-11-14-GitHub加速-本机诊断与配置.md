## 一、诊断结论

### 实测数据（2026-11-14 20:26–20:39）

| 测试项                                                       | 结果                                                                  |
| ------------------------------------------------------------ | --------------------------------------------------------------------- |
| DNS 解析 github.com（ISP / 223.5.5.5）                       | 正常，返回 Azure 边缘 IP（20.247.166.64 / 20.6.7.17 等）              |
| 直连 TCP 443（20.247.166.64）                                | ❌ 8 次仅成功 2 次                                                    |
| 直连 TCP 443（140.82.112.3 / 140.82.114.4 / 20.205.243.166） | ⚠️ 当时 8/8 成功，但数分钟后 git 连接全部失败（"坏窗口"）             |
| git 直连 ls-remote                                           | ❌ 时好时坏，多次 "Operation too slow, Less than 1 bytes/sec"（限流） |
| git 直连浅克隆                                               | ❌ "Failed to connect after 21094 ms"                                 |
| gh-proxy.com 镜像                                            | ✅ ls-remote 5.2s；git/git 浅克隆 189s（解包 49.3 MB）                |
| ghproxy.net 镜像                                             | ⚠️ 可用但慢（ls-remote 38.6s）                                        |
| ghfast.top 镜像                                              | ❌ 本机 300s 超时                                                     |
| SSH github.com:22                                            | ✅ 可连，ed25519 密钥认证成功（Hi hemy08!）                           |
| ssh.github.com:443                                           | ✅ 可连                                                               |

### 结论

- **不是 DNS 污染**，而是本机到 GitHub 边缘节点（Azure/Fastly）的线路被**间歇性限流/阻断**：TCP 成功率和传输速率随时间窗口剧烈波动，这就是"时好时坏"的原因。
- 换 DNS（223.5.5.5 / DoH）**解决不了**这个问题，只能换路径。
- 本机当前最可靠的免费路径：**git 走 gh-proxy.com 镜像（拉取）+ SSH 直连（推送）**；网页访问用 Watt Toolkit 或 hosts 固定 IP。

## 二、已应用的 git 配置（全局）

```bash
# 拉取/克隆走镜像（仅影响 https://github.com/ 开头的 URL）
git config --global url."https://gh-proxy.com/https://github.com/".insteadOf "https://github.com/"
# 推送改走 SSH（优先级高于上面的镜像规则，push 不受镜像影响）
git config --global url."git@github.com:".pushInsteadOf "https://github.com/"
```

效果：

- `git clone https://github.com/xxx/yyy.git` → 自动经 gh-proxy.com（无需手动加前缀）；
- `git push` → 自动经 SSH 直连 GitHub（实测 22 端口可用、密钥认证成功）；
- 已有仓库无需改动 remote，两条规则对全部仓库生效。

撤销（如镜像失效或不再需要）：

```bash
git config --global --unset url."https://gh-proxy.com/https://github.com/".insteadOf
git config --global --unset url."git@github.com:".pushInsteadOf
```

备用镜像切换（gh-proxy.com 故障时改用 ghproxy.net）：

```bash
git config --global --unset url."https://gh-proxy.com/https://github.com/".insteadOf
git config --global url."https://ghproxy.net/https://github.com/".insteadOf "https://github.com/"
```

### ⚠️ 安全注意事项（重要）

- 第三方镜像能看到你拉取的**仓库路径与内容**（公共实例）：
    - **私有仓库**请直连拉取（`git -c url."".insteadOf= clone https://github.com/...` 或临时撤销上面规则）；
    - **不要**在镜像 URL 里携带 token/密码；
    - 生产/重要代码建议直连拉取后 `git log` 核对 commit SHA（镜像有被篡改的理论风险）。
- 镜像一般不支持 push，但本方案 push 已走 SSH，不受影响。

## 三、网页访问加速：hosts 一键脚本

脚本位置：`out/github-accel/setup-github-hosts.ps1`

用法（需管理员权限）：

1. 右键"开始"菜单 → **终端(管理员)**（或 PowerShell(管理员)）；
2. 执行：
    ```powershell
    powershell -ExecutionPolicy Bypass -File "E:\github.com\hemy08\BaiZeNotesByVue\out\github-accel\setup-github-hosts.ps1"
    ```
3. 脚本自动：下载最新 hosts（GitHub520，备用 jsDelivr 源）→ 备份原 hosts → 替换旧加速段落 → 刷新 DNS 缓存。

说明：

- GitHub520 数据每日更新，建议每周跑一次（可加到任务计划程序）；
- 已知风险：GitHub520 直链服务器 2026-12-31 到期，脚本已内置 jsDelivr 备用源，失效后需换源或改用 Watt Toolkit；
- **只能缓解"好窗口"下的稳定性，线路级阻断的"坏窗口"内无效**，与 Watt Toolkit 同时使用会互相覆盖 hosts，**二选一**。

## 六、备用方案

### SSH 走 443 端口（22 被拦时）

`~/.ssh/config` 增加：

```text
Host github.com
    HostName ssh.github.com
    Port 443
    User git
```

### 临时绕过镜像直连拉取（单条命令）

```bash
git -c url."".insteadOf="https://gh-proxy.com/https://github.com/" clone https://github.com/owner/repo.git
```

### 以后如有代理订阅

```bash
git config --global http.proxy socks5://127.0.0.1:7890   # 按实际端口修改
git config --global --unset http.proxy                   # 取消
```
