## 三、逐项实现方案

### 1~2. 启动恢复上次文件/目录（autoOpenLastFile / autoOpenLastFolder）

- **方案**：主进程主窗口 `did-finish-load` 后（或欢迎页就绪后）读取 `system` store 的这两个开关；开启时依次：隐藏欢迎页 → 复用 `runAfterMainViewEntered` 的投递顺序发送 `WELCOME_ENTER_MAIN` 与数据事件（文件经 `OpenSelectFile` 链路、目录经 `ReloadDirFromDisk` 链路），全部复用既有通道，不新增 IPC。
- **渲染层**：移除两处 `disabled` 与提示；无需新组件。
- **验收**：勾选后重启自动进入上次文件/目录且编辑器与目录树有数据；未勾选显示欢迎页；打开失败（文件已删）回退欢迎页并提示。

### 3. 开机自启动（autoStart）

- **方案**：主进程新增 `system-settings.ts` 工具或直接在保存路径处理：`app.setLoginItemSettings({ openAtLogin: enabled })`；对话框打开时用 `app.getLoginItemSettings().openAtLogin` 初始化显示值。
- **注意**：开发模式（未打包 electron）该 API 无效，UI 标注「需安装后生效」；macOS 需在 entitlements 允许（当前未支持 macOS 发布，不阻塞）。
- **验收**：打包环境勾选后登录自启；取消后不再自启。

### 4. 关闭时最小化到托盘（minimizeToTray）

- **方案**：
  - 新增 `src/main/utils/tray.ts`：创建 `Tray`（256 ico），菜单含「显示主窗口」「退出」；`tray.on('click')` 恢复窗口；
  - 主窗口 `close` 事件（`index.ts` 现有 close 拦截处）：flush 落盘后，若 `minimizeToTray` 开启且非显式退出（`app.isQuitting` 标志）→ `event.preventDefault()` + `win.hide()`；「退出」菜单与 `before-quit` 设置退出标志走真实退出；
  - 设置开关即时生效（保存后广播，无需重启）。
- **验收**：点关闭按钮窗口隐藏到托盘；托盘图标可恢复/退出；退出后进程完全结束（复用 MEM-11 的 cleanupApp）。

### 5. 记住窗口位置和大小（rememberWindowSize）

- **方案**：`createWindow` 读取 `system` store 持久化 bounds（新增 `windowBounds` 字段）；`resize`/`move` 事件 500ms 防抖写回；恢复时校验 bounds 落在可见屏幕内（`screen.getAllDisplays()` 求交），否则回退默认 1280×800 居中。
- **验收**：调整窗口后重启恢复位置大小；拔掉外接显示器后启动不出现窗口跑出屏幕。

### 6. 最近文件列表数量（recentFilesCount）

- **方案**：定位最近文件列表维护处（欢迎页「最近文件」与菜单「最近打开」数据源），写入侧按 `recentFilesCount`（默认 10，范围 5~20）截断去重。
- **验收**：修改数量保存后，最近列表不超过 N 条；旧数据即时裁剪。

### 7. 跟随系统主题（useSystemTheme）

- **方案**：主进程 `nativeTheme.on('updated')` → 若开启，按 `nativeTheme.shouldUseDarkColors` 选择 dark/light 应用主题（映射现有 24 主题中的对应主题或动态配色），经 `theme-broadcast` 广播；手动切换主题时自动关闭该开关（互斥语义在 UI 标注）。
- **验收**：切换系统深浅色后应用主题即时跟随；关闭后保持手动主题。

### 8~9. 自动备份（enableAutoBackup + backupInterval）

- **方案**：新增 `src/main/utils/auto-backup.ts`：按 `backupInterval`（小时）定时（`setInterval`，挂入 `cleanupApp` 清理）：把活动文件（或当前工作区全部 .md，避开 node_modules/.git）复制到 `userData/backups/<YYYYMMDD-HHmmss>/`，按 `backupCount` 滚动清理旧备份；手动备份按钮复用同一拷贝函数；备份结果状态栏提示（复用 i18n 错误映射）。
- **验收**：开启后按间隔生成备份；备份数不超过保留上限；磁盘写失败有用户可见提示。

### 10. 应用主题下拉（appTheme，非无实现）

- **方案（二选一）**：
  - A（推荐）：下拉替换为只读显示当前主题 + 「打开主题设置」按钮（触发既有主题设置对话框）；
  - B：直接绑定主进程 `currentTheme` 并可切换（与主题对话框同源，`theme-config.setThemeConfig`）。
- **验收**：不再出现"暂无实现"提示；主题切换路径唯一。

## 四、实施顺序建议

| 批次 | 设置项 | 预估 | 理由 |
|---|---|---|---|
| **A（0.5~1 天）** | #1/#2 启动恢复、#3 自启动、#5 窗口记忆、#6 最近文件数 | 各 0.25 天 | 复用现有链路，改动面小、用户价值直接 |
| **B（1~1.5 天）** | #4 托盘、#7 跟随系统主题 | 各 0.5~0.75 天 | 涉及窗口生命周期与主题链路，需回归验证 |
| **C（1~1.5 天）** | #8/#9 自动备份 + #10 主题下拉收口 | 1~1.5 天 | 备份策略细节需确认（目录范围/去重/配额） |

合计约 3~4 人天。每批完成后：typecheck / eslint / vitest 全绿 + 相关设置项的新增单测（配置读写、定时器清理、窗口 bounds 校验等）。

## 五、风险与注意事项

- **托盘与关闭语义**：minimizeToTray 会改变"关闭即退出"的用户预期，需要清晰的托盘菜单与提示；与现有 close 拦截 flush 落盘顺序整合，避免数据丢失回归（FUN-03）；
- **自动备份体积**：大工作区全量拷贝的磁盘占用与耗时，建议默认只备份活动文件 + 已打开目录的 .md，并在文档说明；
- **开机自启**：仅打包环境可验证；`electron-vite dev` 下 API 无效果，测试用 mock；
- **跟随系统主题**：与手动主题互斥语义需 i18n 文案说明，避免"切换后又被系统覆盖"的困惑；
- **并行开发注意**：`SystemSettingDialog.vue` 与 `system.ts` 是多方改动热点，实施时保持写作用域隔离（AGENTS.md 约束）。
