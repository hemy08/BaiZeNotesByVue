### CQ-01 ESLint 门禁完全失守，`npm run lint` 100% 失败且带 `--fix` 【P1】
 → ✅ 已修复

- **位置**：`.eslintrc.cjs:4-19`、`package.json:12`、`out\tool-results\eslint.txt:22-23`
- **描述**：devDependencies 使用 eslint 9.39.4，但项目仍是旧式 `.eslintrc.cjs`；ESLint 9 默认只认 flat config，需 `ESLINT_USE_FLAT_CONFIG=false` 才能读到该文件；而 `@electron-toolkit/eslint-config@2.1.0` 只输出 flat config 专用属性 `languageOptions`，被旧配置校验器拒绝，直接 exit 2。lint 门禁因此 100% 失败，代码风格与规则无任何自动化保障。
- **证据**：
  - `package.json:12`：`"lint": "eslint . --ext .js,.jsx,.cjs,.mjs,.ts,.tsx,.cts,.mts,.vue --fix"`
  - `.eslintrc.cjs:8`：`extends: [... '@electron-toolkit', ...]`
  - `out\tool-results\eslint.txt:22-23`：`Error: ESLint configuration in .eslintrc.cjs » @electron-toolkit/eslint-config is invalid: - Unexpected top-level property "languageOptions".`
  - `node_modules\@electron-toolkit\eslint-config\index.js:9`：flat config 专用 `languageOptions`；其 `package.json:36` 声明 `peerDependencies.eslint >= 9.0.0`（只支持 flat）。
- **影响**：ESLint 规则形同虚设（本报告发现的大量问题本可被拦截）；`--fix` 意味着一旦配置修好、第一次跑 lint 就会静默批量改写全库代码，无 review 不可控。
- **修复建议**：新建 `eslint.config.js`（flat），用 `@electron-toolkit/eslint-config`（flat）+ `@electron-toolkit/eslint-config-ts` 的 `configs.recommended` + `eslint-plugin-vue` 的 `flat/recommended` + `@vue/eslint-config-prettier` 组装；把 `.eslintignore` 内容迁移为顶层 `ignores` 并删除 `.eslintignore`；`lint` 脚本去掉 `--fix`（另设 `lint:fix` 显式脚本），并在 CI 增加只读 `eslint .` 门禁。
- **工作量**：0.5~1 天。

### CQ-05 错误处理缺陷：async IPC 不 catch、错误塞进返回值、Promise 不 await 【P1】
 → 🟡 部分修复

- **位置**：`src/main/ipc/handlers.ts:76-117`、`src/main/utils/utils.ts:27-183`、`src/main/utils/encrypt_decrypt.ts:149-183`、`src/main/config/config-manager.ts:18-32`、`src/main/renders/HemyRender.ts:133-161`
- **描述**：主进程存在一批"异常会静默丢失或污染返回值"的路径，是代码质量维度最实际的风险面。
- **证据**：
  - async `ipcMain.on` 回调无 try/catch（Electron 不兜底，rejection 会成为 unhandledRejection）：`handlers.ts:76-81/84-97/100-117`、`utils.ts:27-29/68-70/72-79/142-148/157-162`；
  - Promise 不 await：`utils.ts:31-36` 调用 `HemyRenderPre/Post` 不 await（其签名 `HemyRender.ts:133/155` 声明 async 但体内无 await，异常只进 Promise 拒绝链）；`utils.ts:153` `FileUtils.SaveActiveFile()` 浮动调用；
  - 错误混入正常返回值：`encrypt_decrypt.ts:149-152` `result = error as string`、`:180-183` `return error`（Error 对象被当字符串返回给渲染层）；`config-manager.ts:29-32` `readConfig` catch 后返回 null，渲染层无法区分"不存在"与"读取失败"；`utils.ts:105-107` 忽略 `shell.openPath` 返回的错误字符串；
  - 无意义 try/catch：`import.ts:99-101` `catch → throw`；空 catch 存在性检查模式：`image-operations.ts:54/111/138`、`clipboard-operations.ts:67`（模式可接受，建议改用注释或封装 `exists()` 帮助函数）。
- **影响**：用户看不到失败原因（如打开文件夹失败、导入失败、自动保存失败静默），问题难以排查；加密工具把 Error 显示成"密文"，误导用户。
- **修复建议**：① 制定约定：IPC 一律 `ipcMain.handle` + 返回 `{ ok, data | error }` 或抛错让 invoke 统一 reject；② async on-handler 统一包 `try/catch → console.error + showErrorMessageBox`；③ 修复 encrypt_decrypt 返回通道（错误走 throw/reject）；④ 开 `no-floating-promises`（修复 CQ-01 后由 typescript-eslint 提供）。
- **工作量**：1~2 天。
