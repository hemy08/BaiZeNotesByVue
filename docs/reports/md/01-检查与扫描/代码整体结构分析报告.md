# 白泽笔记代码整体结构分析报告

> **性质**：结构分析（非缺陷清单）——对 v1.3.6 代码库做一次自顶向下的整体结构切片，梳理进程边界、模块分层、数据流、工程链路与结构风险。
> **分析时点**：2026-11-19（v1.3.6，git HEAD `3ea3a51`，工作区干净）。规模与门禁数字均为当时实测；历史报告的旧口径不适用于本报告。
> **方法**：3 个并行只读分析代理分别深读「主进程 + preload」「渲染层」「共享层 + 构建/测试/文档」，根代理汇总并出图。原始分析记录见 `out/tool-results/struct-main.md`、`struct-renderer.md`、`struct-cross.md`。

## 0. 摘要与关键结论

**一句话**：白泽笔记是一个「Electron 三进程 + shared 单真源 + 自研轻量基础设施」的本地优先 Markdown 笔记应用——主进程收口全部系统能力，preload 用两份白名单把 92 个 IPC 通道收敛为受信桥，渲染层用 Vue 3 承载欢迎页/编辑器/预览/38 个插件工具，工程侧以自建 md→HTML 报告流水线维护文档。

| 指标 | 数值（2026-11-19 实测） |
| --- | ---: |
| 源代码 | 362 文件 / 95,021 行（`.ts` 201/66,594；`.vue` 81/25,005；`.css` 13/2,610；其余声明/资源） |
| 进程分布 | main 70 文件/18,439 行 · preload 3/443 · shared 39/6,200 · renderer 250/69,939 |
| 测试 | 158 个测试文件 / 45,608 行 / **2,871 用例全通过**（jsdom 47 文件）+ 4 条 Playwright E2E |
| 依赖 | 生产依赖 11 · 开发依赖 39 · lockfile 828 包 |
| 跨进程契约 | IPC **92 通道 / 17 组**（67 个主进程注册 + 25 个主进程广播） |
| 国际化 | 12 命名空间 × 1,821 词条/语言（zh/en 强制同构） |
| 功能规模 | 28 套应用主题 / 54 套 Monaco 主题 / 38 个插件工具 / 18 个 Vue 对话框 |
| 产物 | NSIS 安装包 118.38 MB · 便携版 107.43 MB · app.asar 49.96 MiB |
| 文档 | wiki 27 篇 + reports 20 篇（本报告为第 21 篇）· HTML Wiki 22 页 |

**五条关键结论**

1. **边界清晰、真源纪律强**：92 IPC 通道、9 领域共享类型、12 命名空间 i18n 词典各有唯一出口，且有防回归测试做「常量 ↔ 调用点」双向核对。
2. **主进程是「薄外壳 + 厚内核」**：`index.ts` 只做生命周期编排，业务集中在 `utils/file-utils`；IPC 注册分散 7 个文件但统一在 `whenReady` 后一次性执行，全部套发送方校验。
3. **渲染层是「双段式外壳 + 单主界面 + 懒加载边界」**：欢迎页入口 chunk ≈114 KB，主界面（Monaco + 预览 ≈9.6 MB）整体异步；61 处动态 import 构成全部按需加载边界，无手工 manualChunks。
4. **预览管线是当前最复杂的单条链路**：预渲染 → markdown-it（mkdocs/basic/media/blocks 四层插件）→ 异步图表 → DOMPurify → 远程图片策略 → v-html + TOC，逐层可降级、可单测。
5. **主要结构债集中在三处**：`config ↔ utils` 双向依赖、preload 白名单三份手工清单、Vue 对话框与主进程 JSDOM 对话框双体系；另有文档口径漂移与发布链路未 CI 化。

## 2. 进程架构

<!-- SVG:structure-overview -->

**三进程职责与边界**

| 进程 | 职责 | 关键约束 |
| --- | --- | --- |
| 主进程 `src/main` | 窗口生命周期、文件/配置读写、菜单动作、IPC 处理、Markdown 渲染工具（PlantUML 隐藏窗）、自动更新、日志、托盘 | 所有 IPC 注册套 `withSenderCheck`；路径守卫 + shell 协议白名单 + 导航拦截 |
| preload `src/preload` | 以 `contextBridge` 暴露受限 API（`window.electron` / `window.api` / 对话框 `window.electronAPI`） | 双入口、白名单手工清单、单文件产物（`isolatedEntries` + 关闭 externalize） |
| 渲染进程 `src/renderer` | 全部 UI：欢迎页、编辑器、预览、资源管理器、插件工具、Vue 对话框 | 不直接使用 Node 能力；主题只走 CSS 变量；预览末端 DOMPurify |

**安全边界（纵深 6 层）**：导航拦截 → preload 白名单 → 主进程 sender 校验（68 处）→ 路径守卫（`isPathAllowed`/realpath）→ shell/外链协议白名单 → CSP/DOMPurify/远程资源阻断。

## 3. 主进程结构

<!-- SVG:structure-main -->

**模块分层**

| 层 | 目录/模块 | 职责 |
| --- | --- | --- |
| L0 入口 | `main/index.ts` | 单实例锁、`whenReady` 编排（注册 7 处 IPC / 创建窗口 / 托盘 / 更新 / 备份）、窗口创建与关闭/退出落盘链路、`cleanupApp` 九步清理 |
| L1 IPC 编排 | `main/ipc/` | `handlers.ts`（窗口/菜单/欢迎/最近/快捷链接）、`menu-*.ts`（菜单 handler 树）、`ipc-listener-manager.ts`（注册台账/持久化/组件级清理）、`theme-broadcast.ts`（唯一主题广播） |
| L1 窗口外设 | `main/dialogs/`、`main/renders/` | JSDOM HTML 对话框工厂与右键菜单、PlantUML 本地渲染隐藏窗、在线网页窗口 |
| L2 配置 | `main/config/` | `config-manager`（CONFIG.READ/WRITE 路由、校验、迁移、副作用）+ 5 个 electron-store 单真源 + 28 应用主题/54 Monaco 主题注册表 + 窗口管理 |
| L3 业务内核 | `main/utils/file-utils/` | 文件打开/保存/另存、编码检测与转换、目录树扫描 + `fs.watch`、自动保存、导入导出（PDF/Office）、文件状态持久化 |
| L3 安全与状态 | `main/utils/` | `ipc-security`（sender 校验）、`security`（导航/shell/路径守卫）、`app-state`（窗口引用/当前文件/脏标记/退出标志） |
| L3 基础设施 | `main/utils/` | logger（userData 落盘 + 脱敏）、托盘、自动备份、自动更新、窗口边界、`tMain` i18n |
| L4 共享 | `src/shared/` | IPC 常量、类型、词典、常量 |

**启动顺序（`whenReady` 之后）**：初始化 userData → 注册远程资源阻断 → 注册配置 IPC → 创建主窗口 → 注册主进程菜单/对话框/工具 IPC → 注册 PlantUML 本地渲染 → 注册 activate 重建逻辑；关闭链路：`close` → flush 编辑器内容（2s 超时）→ 脏则落盘；`before-quit` 同链路；`window-all-closed` → `cleanupApp`。

**IPC 体系（92 通道 / 17 组）**

| 项 | 说明 |
| --- | --- |
| 真源与命名 | `src/shared/ipc-channels.ts`，统一 `baize:<domain>:<name>`（17 组：WINDOW/CONFIG/THEME/MENU/EDITOR/FILE/FILE_MANAGER/PLUGIN/RENDER/DIALOG/NAVIGATION/VIEW/MONACO/SETTING/SYSTEM/QUICK_LINKS/EVENTS） |
| 注册模式 | 全部经 `ipcListenerManager`（`registerOnce`/`registerHandleOnce`/组件级 `register`），区分 persistent 与随窗口清理两类 |
| 方向 | 67 个主进程注册（R→M send/invoke），25 个主进程 → 渲染层广播；无 `sendSync`、无硬编码通道字符串 |
| 安全 | 68 处 `withSenderCheck` 全覆盖；文件系统/配置写/外链/执行等高风险通道另有路径、协议、白名单、用户确认等专项校验 |
| 已知问题 | `SYSTEM.OPEN_EXTERNAL_LINK` 等少量死通道残留；preload 白名单与常量无编译期对应（见 §9 风险 H2） |

**核心子系统**：配置（electron-store 单真源 + 迁移 + 备份）、文件与自动保存/备份、目录监听（增量刷新）、主题、编辑器设置、菜单动作分发、对话框体系、PlantUML 隐藏窗（串行队列 + LRU + 空闲销毁）、自动更新、日志/状态栏、编码检测与转换、加密工具、导入导出、全局快捷键/托盘/窗口边界。

## 4. 渲染层结构

<!-- SVG:structure-renderer -->

**分层与目录**

| 层 | 组成 | 说明 |
| --- | --- | --- |
| L0 入口 | `index.html`、`src/main.ts`、`App.vue` | CSP/外链 CSS/ContextMenu/i18n 初始化；欢迎页与主界面双段式（`v-if`），主界面异步加载 + loading/error/重试 + `main-view-mounted` 握手 |
| L1 壳层 | `BaiZeNotes.vue`（≈730 行） | 标题栏/窗口控制/主题应用/全局事件/18 个对话框统一宿主 |
| L2 布局 | `MenuBar`、`WorkSpace`、`StatusBar` | 菜单数据驱动（13 顶层菜单）、分栏容器（编辑/预览/资源管理器/HTML·PDF 查看）、状态栏（行列/编码/消息） |
| L3 业务域 | `Markdown/`（38 文件）、`ResourceManager`、`PluginTools`（84 文件/32.4k 行）、`HemyTools`、`dialogs/`（19 文件） | 编辑器 + 预览管线、文件树 + TOC、38 插件、HTML/PDF 查看、Vue 对话框 |
| L4 基础设施 | `common/`、`composables/`、`styles/` | `useConfigStore`（手写模块级单例）、EventBus（24 事件）、响应式 i18n、主题 CSS、拖拽/窗口管理 composable |
| 契约 | `shared/`、preload | 92 通道 + 9 领域类型 + 词条；渲染层只通过白名单桥访问系统能力 |

**状态与通信**

- **状态**：`useConfigStore` 保存配置域与对话框状态（`dialogs.*`），组件级状态由 `ref/reactive` 管理；无 Vue Router，界面切换由 welcome-state 与 store 驱动。
- **事件**：EventBus 24 个事件按域前缀命名（`MONACO_*`/`FILE_*`/`EVENT_BUS.*`），进程事件经 `ipcRenderer.on` 进入组件；`composables/useEventBus` 存在但生产未使用（结构观察项）。
- **懒加载**：18 对话框 + 38 插件 + 6 类重型依赖全部 `defineAsyncComponent` 动态导入，共 61 处主要动态 import。

**菜单、对话框与插件工具**

| 体系 | 结构 | 一致性 |
| --- | --- | --- |
| 菜单 | `menu-config.ts`（数据驱动，820 行）→ `MenuBar.vue` 渲染 → `menu-actions.ts` 渲染层拦截；未命中经 `IPC.MENU.ACTION` 转主进程 handler 树 | 渲染层拦截列表与主进程 handler 树以测试/注释对齐 |
| 对话框 | Vue 18 个（懒加载注册表 `dialogs/index.ts`）+ 主进程 JSDOM 6 个（独立 BrowserWindow） | 同一动作存在双路径（结构债 H4） |
| 插件工具 | `PluginTools/` 按分类目录组织，`plugin-tools-const.ts` 注册表（38 项）↔ 菜单 38 项一一对应；纯函数 lib + Vue 页面分层 | 有菜单↔注册表一致性测试 |

**编辑器与预览管线**

- **Monaco**：单 worker、按需语言注册、每文件一个模型；击键链路 500ms 空闲防抖 + 脏指纹（长度 + sha256）跳过未变化内容；5 种编辑/预览模式切换。
- **预览（PF-02 单跳）**：编辑内容 → 150ms 防抖 + 渲染序号 → 预渲染（snippets 展开 / KaTeX / 本地 URL 转换）→ markdown-it 插件（highlight.js / emoji / plantuml / mkdocs-material admonition+tabbed / basic/media/blocks 扩展）→ mermaid/PlantUML 异步 → DOMPurify → 远程图片策略 → v-html + TOC（章节指纹门控）；大文档（>2 MiB / 5 万行）跳 KaTeX/图表并提示。
- **性能结构**：入口 chunk ≈114 KB；主界面（Monaco + 预览）≈9.6 MB 首次进入时异步求值；`out/renderer` ≈24.1 MiB。

| 组成 | 规模 | 说明 |
| --- | --- | --- |
| `shared/ipc-channels.ts` | 92 通道 / 17 组 | 唯一通道真源，命名规范由测试守护 |
| `shared/types/` | 10 文件 / 9 领域 | system / theme / editor / file / quick-link / menu / markdown / crypto / status-bar，`index.ts` 统一出口 |
| `shared/i18n/` | 26 文件 / 12 命名空间 | zh-CN / en-US 各 1,821 词条；`translate()` + `resolveLocale()`；渲染层 `t()`、主进程 `tMain()` |

> 注意：`main/constants/urls.ts` 与 `shared/constants/urls.ts` 存在 52 个同名导出（双份维护），应合并到 shared（见 §9）。

## 6. 关键数据流

<!-- SVG:structure-flows -->

1. **文件：打开 → 编辑 → 保存/自动保存 → 退出落盘**
   选择文件 → IPC（sender 校验 + 路径守卫）→ `file-operations` 读取 + 编码检测 → 回填 Monaco + `appState` → 脏指纹更新 → Ctrl+S/自动保存/切换文件落盘；退出时 `close` 拦截 → `FLUSH_CONTENT`（2s 超时）→ 脏则落盘。
2. **菜单动作：渲染层优先，主进程兜底**
   `MenuBar` 点击 → `HandleMenuAction`（渲染层打开 Vue 对话框/插入文本）→ 未命中经 `IPC.MENU.ACTION` → 主进程 `menu-handle` 解析 → handler 树 → 业务调用/窗口操作。
3. **配置变更：store → IPC → electron-store → 副作用 + 广播**
   设置对话框 `v-model` → `useConfigStore`（300ms 防抖，JSON 往返剥离 Proxy）→ `window.api.config.write` → `config-manager` 路由/校验/迁移 → electron-store 落盘 → 应用副作用（主题/字体/快捷键/定时器）→ 广播 `THEME.UPDATED` / `SYSTEM_SETTING_UPDATE` → 渲染层监听器更新 UI。
4. **Markdown 预览：单跳本地管线**（见 §4「编辑器与预览管线」；无主进程渲染 IPC）。

### 9.3 改进建议（按优先级，不要求实施）

**P1（结构债，建议尽早）**

1. **依赖边界自动化**：引入 `dependency-cruiser` 或自研单测声明 `index → ipc|dialogs → config → utils → shared` 方向矩阵，禁止 utils 反向 import config（改回调注入，如现有 `setRecentFilesLimitProvider` 模式），并把 `config/index.ts` 的 ipc re-export 迁出。
2. **白名单单一化**：以 `shared/ipc-channels.ts` 分组 + 一张「通道路由元数据表」为源，构建期生成两份 preload 白名单与 `window.api` 闭包通道；测试改为「生成产物 vs 渲染层扫描」核对。
3. **收敛对话框体系**：把 `ShowShortcutKeys/ShowUpdateLog/ShowReleaseNotes/ShowRename/ShowConfirmDelete` 迁为 Vue 懒加载对话框，主进程只保留确有独立窗口需求的（在线网页等），消除「新建文件/文件夹」双路径。
4. **主界面二次分块**：Monaco 初始化与预览管线二级懒加载（先外壳骨架，空闲/首编辑时加载 Monaco），降低首次进入的 ~9.6 MB 同步求值；评估 highlight.js 改 `core + 常用语言`。
5. **修正文档口径并自动化**：统一 README/报告中的产物体积、依赖计数、测试数、审计口径；为门禁数字增加自动生成/校验脚本（CI 落盘并与 docs 基线比对）。

**P2（治理与质量）**

6. **注册清单显式化**：新增 `ipc/registry.ts` 只做 `registerAll(mainWindow)` 汇总；入口只调用一次。
7. **状态收口**：新增 `AppContext`（window/stores/listener manager/flags）统一 reset；删除无消费者的 `systemConfig/quickLinksConfig` 或真正接入；主题收敛为 `useTheme()` 单例。
8. **单一注册表**：插件工具由一份 manifest 同时生成菜单项与懒加载注册表；Material 15 项同理。
9. **错误/状态栏统一**：抽 `notifyStatus` + `toUserError` 替换 5 套 helper。
10. **拆分超大文件**：`directory-tree` 按扫描/watch/事件拆 3 文件；`preview-md-basic` 按语法域拆；`MaterialSyntaxDialog` 抽表单/生成器纯函数目录；设置页按页签拆子组件。
11. **工程门禁补强**：CI 增加 `vitest --coverage`、`prettier --check`、`npm audit --omit=dev`；shared 边界加 ESLint `no-restricted-imports`（禁止 renderer import main、禁止 shared 引 electron/node）。
12. **发布链路补全**：新增 release workflow（tag → nsis/portable + latest.yml 上传），补签名策略与 release-1.3.6 tag。

**P3（清理与规范）**

13. **清理死代码/重复资源**：`utils/common.ts`、`SYSTEM.OPEN_EXTERNAL_LINK`、`MermaidRender.vue`、HemyTools 空壳、重复 CSS/模板资源。
14. **目录语义归位**：`window-manager` 移至 `src/main/window/`；`main/constants/urls.ts` 合并到 shared。
15. **格式统一**：`.editorconfig` 与 Prettier `endOfLine` 对齐，修复非 UTF-8 文件；`out/` 拆分构建产物与分析产物，`dist/` 历史安装包归档到 Release。
16. **文档资产治理**：`docs/架构文档.html` 归档并在索引标注「非当前」；`_unused-assets` 移出工作区。

## 10. 结论

- 白泽笔记的整体结构属于「**边界清晰、真源纪律强的本地优先桌面应用**」：进程边界、契约层、安全纵深、懒加载与生命周期收口都达到成熟工程水平，测试具备结构不变量守护能力。
- 当前结构债并非功能缺陷，而集中在 **依赖方向（config↔utils）**、**桥接层手工清单（preload 白名单）**、**双对话框体系** 与 **主界面大 chunk** 四处；同时文档口径漂移与发布链路未 CI 化会放大这些债的维护成本。
- 建议按 §9.3 的 P1→P3 顺序分批判修复：先用「依赖边界测试 + 白名单生成 + 对话框收敛 + Monaco 二级懒加载」四件事降低核心结构风险，再补 CI 门禁与发布流程，最后做清理与资产治理。
