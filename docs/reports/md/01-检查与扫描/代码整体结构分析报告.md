## 0. 摘要与关键结论

**一句话**：白泽笔记是一个「Electron 三进程 + shared 三层单真源 + 自研轻量基础设施」的本地优先 Markdown 笔记应用——主进程收口全部系统能力，preload 用两份白名单把 92 个 IPC 通道收敛为受信桥，渲染层用 Vue 3 承载欢迎页/编辑器/预览/38 个插件工具，工程侧以自建 md→HTML 报告流水线维护文档。

**五条关键结论**

1. **边界清晰、真源纪律强**：92 IPC 通道、shared 三层单真源（类型 14 文件含 IPC/CONFIG/对话框契约、纯函数 utils 11、常量 constants 10）、12 命名空间 i18n 词典各有唯一出口；本轮新增 `ipc-payload-contract` / `dialog-contract` / `theme-contract` 等契约测试，并用「re-export 门面 + 原导出名」模式完成 16 个主进程文件、13 个渲染层文件的实现归位。
2. **主进程是「薄外壳 + 厚内核」**：`index.ts` 只做生命周期编排，业务集中在 `utils/file-utils`；IPC 注册分散 **9 个文件 / 69 处调用**（较首次成文 +2 文件），但统一在 `whenReady` 后一次性执行，全部套发送方校验（68 处）。
3. **渲染层是「双段式外壳 + 单主界面 + 懒加载边界」**：欢迎页入口 chunk **127.07 kB**，主界面（Monaco + 预览）**9,889.38 kB（≈9.89 MB）**整体异步；**64 处动态 import**（`.ts` 61 + `.vue` 3）构成全部按需加载边界，无手工 manualChunks。
4. **预览管线是当前最复杂的单条链路**：预渲染 → markdown-it（mkdocs/basic/media/blocks 四层插件）→ 异步图表 → DOMPurify → 远程图片策略 → v-html + TOC；四层插件已共享 `preview-block-utils`（14 函数 + 2 常量），本轮净减 309 行，逐层可降级、可单测。
5. **主要结构债集中在四处**：`config ↔ utils` 双向依赖（utils→config 实测 **4** 文件）、preload 白名单三份手工清单、Vue 对话框与主进程 JSDOM 对话框双体系、主界面大 chunk；另有 **shared 边界唯一例外**（`shared/utils/backup-dir.ts` 引用 `node:path`）与发布链路未 CI 化（文档口径已完成全仓同步，自动化校验待做）。

## 2. 进程架构

**三进程职责与边界**

| 进程 | 职责 | 关键约束 |
| --- | --- | --- |
| 主进程 `src/main`（69 文件 / 18,240 行） | 窗口生命周期、文件/配置读写、菜单动作、IPC 处理、Markdown 渲染工具（PlantUML 隐藏窗）、自动更新、日志、托盘 | 所有 IPC 注册套 `withSenderCheck`（68 处）；路径守卫 + shell 协议白名单 + 导航拦截 |
| preload `src/preload`（3 文件 / 459 行） | 以 `contextBridge` 暴露受限 API（`window.electron` / `window.api` / 对话框 `window.electronAPI`） | 双入口、白名单手工清单、单文件产物（`isolatedEntries` + 关闭 externalize） |
| 渲染进程 `src/renderer`（255 文件 / 68,211 行） | 全部 UI：欢迎页、编辑器、预览、资源管理器、插件工具、Vue 对话框 | 不直接使用 Node 能力；主题只走 CSS 变量；预览末端 DOMPurify |
| 共享层 `src/shared`（62 文件 / 9,179 行） | 三层单真源：类型契约（14 文件）· 纯函数工具（11 模块）· 跨进程常量（10 模块）+ IPC 通道 + i18n 词典 | 以纯类型/纯数据/纯函数为主；唯一受控例外 `utils/backup-dir.ts` 引 `node:path`（仅主进程消费，需后续注入式改造） |

**安全边界（纵深 6 层）**：导航拦截 → preload 白名单 → 主进程 sender 校验（68 处）→ 路径守卫（真源 `shared/utils/path.ts` 的 `isPathWithin` / `normalizePathForCompare` + realpath 校验）→ shell/外链协议白名单 → CSP/DOMPurify/远程资源阻断。

**本轮结构变化（公共接口归位 0~4 批）**：shared 从「契约层」升级为三层单真源（+23 文件 / +2,979 行）；main/renderer 对 shared 的消费从 37/31 文件升至 **42/38**；main 删除 `global-types.d.ts` 迁入 `shared/types/global.d.ts`；渲染层 18/18 对话框迁移 `BaseDialog` 基座并新增 `WindowControls` 等通用组件。

## 6. 关键数据流

<!-- SVG:structure-flows -->

1. **文件：打开 → 编辑 → 保存/自动保存 → 退出落盘**
   选择文件 → IPC（sender 校验 + 路径守卫，守卫真源 `shared/utils/path`）→ `file-operations` 读取 + 编码检测（目录树 id/哈希来自 `shared/utils/hash`）→ 回填 Monaco + `appState` → 脏指纹更新 → Ctrl+S/自动保存/切换文件落盘；退出时 `close` 拦截 → `FLUSH_CONTENT`（2s 超时）→ 脏则落盘。
2. **菜单动作：渲染层优先，主进程兜底**
   `MenuBar` 点击 → `HandleMenuAction`（渲染层打开 Vue 对话框/插入文本）→ 未命中经 `IPC.MENU.ACTION` → 主进程 `menu-handle` 解析 → handler 树 → 业务调用/窗口操作；URL 类动作只存 id，由 `shared/constants/urls.ts` 真源解析。
3. **配置变更：store → IPC → electron-store → 副作用 + 广播**
   设置对话框 `v-model` → `useConfigStore`（300ms 防抖，JSON 往返剥离 Proxy）→ `window.api.config.write` → `config-manager` 路由/校验/迁移 → electron-store 落盘 → 应用副作用（主题/字体/快捷键/定时器）→ 唯一广播实现 `theme-broadcast.ts` 发送 `THEME.UPDATED` / `SYSTEM_SETTING_UPDATE` → 渲染层监听器更新 UI。
4. **Markdown 预览：单跳本地管线**（见 §4「编辑器与预览管线」；四层插件共享 `preview-block-utils`，LRU 来自 `shared/utils/lru-cache`，无主进程渲染 IPC）。

## 10. 结论

- 白泽笔记的整体结构属于「**边界清晰、真源纪律强的本地优先桌面应用**」：进程边界、契约层、安全纵深、懒加载与生命周期收口都达到成熟工程水平；本轮「公共接口归位」将 shared 升级为三层单真源，并用契约测试与 re-export 门面模式把结构治理推进一步。
- 当前结构债并非功能缺陷，而集中在 **依赖方向（config↔utils）**、**桥接层手工清单（preload 白名单）**、**双对话框体系** 与 **主界面大 chunk** 四处；另有 shared 边界唯一例外（`backup-dir` 的 `node:path`）、文档口径漂移与发布链路未 CI 化会放大维护成本。
- 建议按 §9.3 的 P1→P3 顺序分批判修复：先用「依赖边界测试 + 白名单生成 + 主进程对话框收敛 + Monaco 二级懒加载」四件事降低核心结构风险，再补 CI 门禁与发布流程，最后做清理与资产治理。
