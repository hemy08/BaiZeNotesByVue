> 编号前缀：CMP（Completeness）

## 一、检查范围与方法

- **测试完整性**：21 个用例 vs 模块清单的缺口；`vitest.config.ts` 的 include/coverage 范围与目标一致性；补测优先级。
- **文档完整性**：README「开发文档」章节与 docs/wiki 全部相对链接逐条存在性验证；README 数据（行数、文件数）与实测对比；CHANGELOG/RELEASE-NOTES 版本覆盖；`docs/架构文档.html` 与 md 同步性。
- **资产完整性**：images / assets/icons / resources/themes / resources/icon 的数量清点与「文件名在 src 中引用次数」抽查。
- **安全基线**：`out/tool-results/audit2.json` 15 个漏洞整理；v-html/innerHTML 与 DOMPurify 使用面；webPreferences 与 CSP；加密（node-forge/crypto-js）密钥管理抽查。
- **发布完整性**：electron-builder.yml / dev-app-update.yml / generate-version-config.js → version.json 链路 / package.json scripts。
- **版本一致性**：package.json 1.2.2 vs CHANGELOG vs docs 中的版本号。
- **空壳与未挂载功能**：ShowHtmlVIew / ShowPdfEditor / HemyTools / PluginTools 各工具的入口；electron.vite.config.ts 被注释插件的意图。
- **国际化**：源码硬编码中文现状；**依赖健康**：sharp / png-to-ico / app-builder-bin 等使用点与重复依赖。

方法：以 read/grep 深读源码取证，以只读 PowerShell 命令统计文件数量、行数、链接存在性与引用次数。不确定处标注「待验证」。严重度按模板定义：P0=严重（安全漏洞/数据丢失/崩溃）、P1=高（明显缺陷）、P2=中（改进项/潜在风险）、P3=低（风格/建议）。

 → ✅ 已修复

**位置**：`vitest.config.ts:8-11`

**工作量**：0.5 人日。
