# 代码结构优化计划（批次 1–5）

> **性质**：优化实施计划（非缺陷清单）——基于 [代码整体结构分析报告](../01-检查与扫描/代码整体结构分析报告.md)（2026-11-19 刷新版）的结构风险清单（H1–H7 / M1–M9 / L1–L4），把风险转化为**可分批次执行、可独立回滚、可验收**的工程计划。

> **依据**：[结构分析报告](../01-检查与扫描/代码整体结构分析报告.md)、[当前遗留问题清单](../03-专项治理/当前遗留问题清单.md)、[IPC 通信矩阵](../03-专项治理/IPC通信矩阵.md)、[公共接口归位修复计划](公共接口归位修复计划.md)（已完成批次的模式参考）。

## 0. 摘要

**结论**：结构分析报告确认项目边界与真源治理已达到成熟水平，剩余结构债集中在「依赖方向、桥接层手工清单、双对话框体系、主界面大 chunk、发布链路」五处；本计划按 **P1 结构防御 → P2 运行时收敛 → P3 清理规范** 的顺序分为 **5 个批次（含批次 0 基线确认）**，每批独立提交/回滚，门禁不降级。

**本计划目标（按批次验收）**

1. **结构防御自动化**：依赖方向、preload 白名单、shared 边界三处从「人工守护」升级为「构建/测试强制」；
2. **运行时收敛**：双对话框体系收敛、主界面二级分块、jsdom 依赖边界、状态与 IPC 注册清单收口；
3. **工程门禁与发布**：文档基线自动校验、CI 覆盖率/格式/审计、tag 触发的发布流水线；
4. **真源与可维护性**：单一 manifest、主题单真源、EventBus/错误处理统一、重复资产清理；
5. **清理与规范**：死代码/目录语义、EOL/编码、build 脚本、docs 资产、巨型文件拆分。

**不在本计划范围**（避免与并行迭代冲突）

- 业务功能新增/交互改版、预览渲染管线重写、第三方插件系统、构建工具迁移；
- 并行会话正在改动的文件/模块：执行前先与当前工作区同步并确认「安静窗口」；
- 历史报告/版本快照的数字回写（仅更新当前状态文档与索引）。

## 2. 第 1 批：结构防御（P1）

**目标**：把当前最危险的 3 类结构债（依赖方向、桥接白名单、shared 边界）从「注释/人工约定」升级为「自动检测 + 构建期生成/校验」。**本批不改变任何业务行为。**

### 2.1 依赖环自动检测（H1）

- **现状**：`config` 9 文件 import `utils`；`utils` 4 文件反向 import `config`（`auto-backup`/`i18n`/`utils`/`file-utils/path-utils`）；`config/index.ts` 仍 re-export `ipcListenerManager`；无自动环检测。
- **改动点**：
  1. 新增 `tests/architecture/dependency-boundaries.test.ts`（静态扫描 import，声明方向矩阵：`index → ipc|dialogs → config → utils → shared`，与 `shared → 无反向依赖`）；
  2. `main/config/index.ts` 移除 ipc re-export，受影响引用改为直接 import `ipc/ipc-listener-manager`；
  3. `utils` 反向依赖改「回调注入 / 参数注入」：`auto-backup`（备份目录/设置）、`i18n`（语言）、`utils.ts`（快捷链接）、`file-utils/path-utils`（窗口/资源路径）；
  4. 新增 `npm run arch:check`（或在 `test` 前置），CI 纳入。
- **验收**：方向矩阵测试 0 violation；`utils → config` import 数 = 0；全量 typecheck/test/eslint/build 通过；新增测试 ≥ 15 用例。
- **风险/回滚**：注入式改造可能影响启动顺序（配置早于备份/日志）；按模块拆 3~4 个独立 commit，每步可回滚；不改变函数签名（用可选注入 + 默认实现）。

### 2.2 preload 白名单单一化（H2）

- **现状**：三份手工清单（主窗口 58 send + 25 on、对话框 2 + 1、`window.api` 6），与 92 通道常量无编译期对应；已有 `shared/types/ipc.ts` 契约与 `ipc-payload-contract` 测试。
- **改动点**：
  1. 新增 `build/generate-preload-whitelist.js`（或 electron-vite 构建钩子）：从 `shared/types/ipc.ts` 的 `IpcRequests/IpcResponses/IpcEvents/window.api` 生成 `preload/allowed-channels.generated.ts`（静态 import，保持 preload 单文件产物约束）；
  2. `preload/index.ts`、`preload/dialog.ts` 改为引用生成常量；
  3. 测试改为「生成文件 vs 主进程注册/渲染层调用」双向核对（扩展既有 `ipc-payload-contract`）。
- **验收**：92 通道与三份白名单 100% 对应（缺失/多余即测试失败）；preload 产物仍单文件、sandbox 下 `contextBridge` 正常（E2E 冒烟）；构建通过。
- **风险/回滚**：生成步骤需接入 `dev/build` 两条链路；若生成失败应有清晰报错；保留手写清单为对照测试基线一个版本，确认无差异后删除。

### 2.3 shared 边界例外收口（L4）

- **现状**：`shared/utils/backup-dir.ts` 引 `node:path`（仅主进程消费），是 shared「禁止 Node 运行时」规则的唯一例外。
- **改动点**：
  1. 拆分 `backup-dir-core.ts`（纯函数：时间戳/名称校验/路径比较，接收 `PathApi` 或纯字符串实现）+ main 侧 `backup-dir.ts` 注入 `node:path`；
  2. `shared/utils/index.ts` 只导出纯函数版本；
  3. ESLint `no-restricted-imports`：`src/shared/**` 禁止 `node:*` / `electron` / `vue` / DOM globals（若确需例外，需 `// eslint-disable-next-line` + 注释 + 单测锁定）。
- **验收**：`grep` shared 内 `node:`/`electron` 仅剩类型/注释（或 0 处）；ESLint 规则生效；备份相关测试（auto-backup/config-backup）全过。
- **风险/回滚**：备份路径语义敏感（时间戳/名称/解析），先补等价性测试再迁移；改动局限 2~3 文件。

## 3. 第 2 批：运行时架构收敛（P1~P2）

**目标**：消除双对话框体系与主界面大 chunk 两个用户体验相关结构债，并把 jsdom/状态/IPC 注册三处基础设施收口。

### 3.1 双对话框体系收敛（H3）

- **现状**：Vue 18 个（已统一 BaseDialog）+ 主进程 JSDOM 5 个 + 在线网页窗口；同一动作（如新建文件/文件夹）存在两条路径。
- **改动点**：
  1. 盘点主进程 5 个 JSDOM 窗口（`ShowShortcutKeys` / `ShowUpdateLog` / `ShowReleaseNotes` / `ShowRename` / `ShowConfirmDelete`）与全部调用点；
  2. 逐一迁移为 Vue + BaseDialog（复用 `dialogRenderer` 词典与 `useDialogDrag/Resize`），主进程只保留 `OpenOnlineWebPage` 等确有独立窗口需求的；
  3. 统一「新建文件/文件夹」入口：菜单/欢迎页/资源管理器全部走 Vue 对话框 + 既有 IPC 动作；
  4. 更新 `shared/types/dialog.ts` 契约（`MainProcessDialogName` 缩减）与 `dialog-contract`/`preload` 测试。
- **验收**：JSDOM 对话框数量 5 → 0（在线网页除外）；同一动作仅一条路径（代码检索 + 测试）；UI 手测清单（快捷键/更新日志/发布说明/重命名/删除确认/新建文件文件夹）全过；`dialog-contract` 测试更新。
- **风险/回滚**：对话框 UI/主题/多语言易漏；按对话框逐个提交，保留主进程旧代码一个批次（feature flag 或双入口日志）以便回滚；需真实窗口手测。

### 3.2 主界面二级分块（H4）

- **现状**：主界面异步块 9,889.38 kB（Monaco≈7.3MB / highlight.js≈1.29MB / KaTeX≈0.51MB 与预览管线整体同步求值）；入口 127.07 kB。
- **改动点**：
  1. 把 Monaco 初始化抽为二级异步边界（先渲染主界面骨架/编辑区占位，空闲或首次编辑时加载 Monaco），预览管线同理（首帧不阻塞输入）；
  2. `App.vue` 只保留欢迎页/主界面切换；`BaiZeNotes.vue` 壳层不再 import 编辑器/预览实现；
  3. 更新 E2E 构建契约（入口 chunk、主界面壳 chunk、Monaco chunk 独立）；补充 TTI/内存基线记录。
- **验收**：入口 ≤150 kB；主界面壳 chunk ≤2 MB（Monaco/预览独立按需 chunk）；E2E 构建契约更新且通过；大文档首屏/输入延迟不劣化（记录基线）。
- **风险/回滚**：启动时序/恢复文件路径易回归（此前 PF/批次 7 有先例）；保留原有异步分块策略为回退路径；需实机手测「自动恢复文件/最近文件」。

### 3.3 jsdom 运行时依赖边界（H6）

- **改动点**：随 3.1 完成后评估两种方案——A：删除 JSDOM 对话框 → 主进程不再 `require('jsdom')`（out/main 10.50 MiB → 显著下降）；B：若仍需保留部分 JSDOM，则 `jsdom` 升为 production dependency + 构建 externalize，并记录 asar 体积权衡。CI 增加「asar 运行时必需包」探查步骤。
- **验收**：方案 A 下主进程 bundle 无 jsdom；方案 B 下 asar 含运行时依赖、`externalizeDeps` 配置有注释与测试；两种方案均需记录包体/启动对比数据。
- **风险/回滚**：构建配置变动可能导致运行时崩溃且单测难发现——必须真机启动 + 对话框链路手测；保留构建对比日志。

### 3.4 AppContext 与 IPC 注册清单（M1/M2）

- **改动点**：
  1. 新增 `main/app-context.ts`：集中窗口引用、stores、`ipcListenerManager`、退出/托盘/快捷键 flags，提供 `reset()`（activate/测试复用）；
  2. 新增 `ipc/registry.ts`：`registerAll(mainWindow)` 汇总现有 9 文件 / 69 处注册，`index.ts` 只调用一次；
  3. 统一错误上报 helper（`notifyStatus` / `toUserError`），替换 5+ 套 helper（可与第 4 批联动的部分只在第 4 批做）。
- **验收**：窗口重建/reload/退出路径无重复监听或状态串扰（单测 + 手测）；注册清单单一入口；错误提示文案/类型统一。

## 7. 优先级与排期建议

1. **先做第 1 批**（结构防御）：改动局部、风险可控，收益是后续所有重构的安全网；预计 1 周内完成。
2. **再做第 2 批**（运行时收敛）：H3/H4 与用户体验直接相关，且 3.2 会改变构建契约，建议在无并行发布会话的窗口执行；分 4~5 个独立提交。
3. **第 3 批与第 2 批部分并行**：CI/发布脚本改动与运行时解耦，可提前准备；release workflow 需等 1.3.8 发布决策。
4. **第 4 批**依赖第 2 批组件稳定；第 5 批可随时穿插（尽量在每批收尾时做 1~2 项）。
