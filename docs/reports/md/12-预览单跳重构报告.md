## 1. 问题回顾

修复前预览渲染链路存在 **4 跳 IPC 往返** 与 **主进程同步 KaTeX 渲染**：

1. 渲染层 `ipcRenderer.send(PRE_RENDER, content)` → 主进程 `HemyRenderPre`（图片/文件 URL 转换）→ 回发 PRE_RENDER_RESULT；
2. 渲染层收到后执行 `PreMarkdownRender`（mermaid/plantuml）→ `md.render()`；
3. 渲染层 `ipcRenderer.send(POST_RENDER, html)` → 主进程 `HemyRenderPost`（KaTeX 同步渲染 + Material/TabbedSet 变换）→ 回发 POST_RENDER_RESULT；
4. 渲染层收到后 `PostMarkdownRender` → DOMPurify → v-html。

副作用：每次击键（防抖后）触发 4 次跨进程消息；主进程事件循环被同步 KaTeX 阻塞；渲染串行化。

|---|---|---|
| 每轮预览渲染的渲染 IPC | **4 跳**（2 send + 2 结果回发） | **0 跳**（markdown 全流水线在渲染进程完成） |
| 主进程渲染通道 | 4 个（PRE/POST + 2 个 RESULT） | **全部删除**（常量/注册/监听/白名单清理） |
| KaTeX 渲染位置 | 主进程同步 `renderToString`（阻塞事件循环） | **渲染层** katex 包（已有 CSS），不再阻塞主进程 |
| 主进程渲染文件 | `renders/` 4 文件（HemyRender/KatexRender/MaterialRender/TabbedSetRender，797 行） | **删除**，逻辑逐行迁移至渲染层 `preview-local-render.ts`（854 行） |
| PlantUML | 主进程本地 IPC | **保留**（离线图表资源依赖，测试证明 1 图仅 1 次 invoke、0 次 send） |
| mermaid | 渲染层本地渲染 + hash 缓存 | 未改动 |

## 5. 遗留与建议

| 项 | 说明 |
|---|---|
| 另存为后相对路径 | 「另存为」（md/txt）后主进程更新活动路径但未发 `USER_SELECT_FILE`，相对图片 URL 会按旧目录解析——建议主进程 `SaveActiveFileAs` 成功后补发该事件（1 行改动，需确认事件契约）。 |
| DOMPurify URI 策略 | DOMPurify 3.4.17 默认 URI 策略会剥离 `C:/...` 盘符绝对路径（jsdom 实测；修复前主进程管线同样存在，非本次引入）——建议按报告给出的 `ALLOWED_URI_REGEXP` 方案安全评审后单独立项。 |
| 章节解析二次 parse | markdown-it 章节解析仍保留二次 `md.parse`（原始内容行号语义，PF-14 依赖），后续可优化。 |
| KaTeX 公式缓存 | 本轮未加公式缓存（P2 优化项）。 |
