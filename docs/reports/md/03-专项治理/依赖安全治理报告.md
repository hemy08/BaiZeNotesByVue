## 2. 数据来源与方法

### 2.1 告警拉取

- 凭据：`git credential fill`（`host=github.com`）读取本机 Git 凭据，脚本内不硬编码 token。
- 接口：`https://api.github.com/repos/hemy08/BaiZeNotesByVue/dependabot/alerts?state=open&per_page=100`，Header 携带 `Authorization: Bearer <token>`、`Accept: application/vnd.github+json`、`X-GitHub-Api-Version: 2022-11-28`。
- **踩坑记录**：Dependabot alerts 接口**不支持 `page` 参数**（传 `page=1` 会返回 HTTP 400「Pagination using the `page` parameter is not supported」），必须按响应 `Link: rel="next"` 游标翻页；本仓库共 3 页（100 / 100 / 54）。
- 校验：拉取总数 254，与 GitHub 安全页 open 数一致；告警编号范围 1–298（其余 44 条为已关闭/已修复后关闭的历史告警）。
- 参考：[GitHub REST API — Dependabot alerts](https://docs.github.com/en/rest/dependabot/alerts)。

### 2.2 分类与「当前是否可复现」核验方法

1. 按 `security_advisory.severity` / `dependency.scope` / `dependency.relationship` / `dependency.manifest_path` / `dependency.package.name` 五个维度聚合。
2. 读取当前 `package.json`（直接依赖声明范围）与 `package-lock.json`（828 个依赖节点的实际解析版本），对每条告警做 semver 核验：把 GitHub 返回的 `vulnerable_version_range`（形如 `>= 2.0.0, < 2.1.5`，逗号分隔需归一化为空格）与 lockfile 中该包**全部安装副本**逐一比对。
3. 判定规则：

| 判定 | 含义 | 判定条件 |
| --- | --- | --- |
| `FIXED` | 已修复 | lockfile 中该包所有副本均不在 `vulnerable_version_range` 内 |
| `REMOVED` | 依赖已移除 | 当前 lockfile 中无该包任何安装副本 |
| `STALE_MANIFEST` | 清单已删除 | 告警引用路径（`src/renderer/src/lib/**`）在当前仓库不存在 |
| `ACTIVE` | 仍受影响 | lockfile 中仍存在落在 `vulnerable_version_range` 内的副本 |

> 严重级别口径：GitHub API 返回 `medium`，安全页面中文口径称「中危（moderate）」，本报告统一记作「中（medium）」。

## 4. npm audit 差异归因（0 vs 254）

### 4.1 两种工具的口径对比

| 维度 | GitHub Dependabot alerts | `npm audit`（官方 registry，含 dev） |
| --- | --- | --- |
| 数据源 | GitHub Advisory Database（GHSA/CVE，含未收录进 npm 库的条目）+ 仓库依赖图 | npm registry advisory 接口（`npm audit` 端点） |
| 扫描对象 | 仓库依赖图中**全部被识别的 manifest**（含锁文件、直接清单、历史快照） | 当前 `package-lock.json` 的**实际安装树** |
| 版本判定 | 告警创建时依赖图快照中的解析版本 + manifest 声明范围 | 每次运行时的 lockfile 解析版本 |
| 覆盖范围 | 历史 open 告警（需依赖图重扫或人工 dismiss 才关闭） | 当前一次快照，实时计算 |
| 是否扫描未安装清单 | 会（只要曾被依赖图收录，如 vendor 目录 manifest） | 不会 |
| devDependencies | 覆盖（标注 scope=development） | 覆盖（`--omit=dev` 才排除） |
| 输出 | 逐告警（含 GHSA/CVE、修复版本、依赖关系） | 逐漏洞（含 via/effects/range） |

### 4.2 差异的五条实证

**① 告警版本要求是升级前快照，当前声明已高于修复版本（51 条 package.json 告警）。**

| 包 | 告警创建时要求 | 当前 `package.json` 声明 | 不一致告警数 |
| --- | --- | --- | ---: |
| `electron` | `^31.0.1` | `^43.8.12` | 42 |
| `vite` | `^5.2.11` | `^8.3.8` | 7 |
| `katex` | `^0.16.10` | `^0.18.10` | 1 |
| `uuid` | `^10.0.0` | `^14.0.3` | 1 |

> 依赖升级落地于提交 `19ef1fe`（2026-11-15）；此后 GitHub 侧未把这些告警批量重算关闭，因此 `state=open` 不代表当前可复现。

**② overrides + 直接依赖升级已把受影响包解析到修复版本（209 条已修复）。**
- 当前 `overrides` 共 20 项（完整清单见附录 B），覆盖 **46 条告警**涉及的包：`dompurify`、`@xmldom/xmldom`（0.8.15）、`js-yaml`（4.3.2）、`brace-expansion`（1.1.22 / 2.1.8 / 5.0.13）、`minimatch`（3.1.5 / 5.1.9 / 11.0.9）、`postcss-selector-parser`（6.1.6）、`browserslist`、`@babel/core`、`undici`、`glob` 等。
- 代表项：`@xmldom/xmldom` 0.8.15（15 条 high/medium 告警全部修复）、`dompurify` 3.4.18（21 条全部修复）、`node-forge` 已移除（17 条）、`electron` 43.8.12（85 条全部修复）。

**③ 30 条告警对应依赖已从依赖树移除（§3.7）。** npm audit 只能看到当前树，看不到已移除的包；GitHub 历史告警在依赖图重扫前保持 open。

**④ 15 条告警指向已删除的 vendor 清单（§3.8）。** 这些清单从未安装 `node_modules`，不属于 npm audit 的扫描对象。

**⑤ 工具库差异（次要）。** npm audit 使用 npm registry 的 advisory 数据，GHSA 中部分条目（尤其新发布、撤回、或仅 GitHub 收录的）可能未进入 npm 的 audit 端点；即便同一条 advisory，两者发布的「修复版本」时点也可能不同。本仓库当前安装版本均高于所有告警声明的修复版本，故即使放开库差异，npm audit 仍为 0。

### 4.3 差异结论与口径建议

- **判定口径**：判断「当前是否可复现漏洞」以 `npm audit`（官方 registry）+ 本地 lockfile semver 核验为准；Dependabot 告警定位为「历史暴露面与版本更新提醒」，需结合依赖图刷新周期看趋势，而不是直接当作当前漏洞数。
- 本仓库 `npm audit` 0 漏洞是真实结果：828 个依赖全部不在告警受影响范围，且 `overrides` 把历史上高危的传递依赖强制在修复版本。
- 254 条告警中的 15 条 vendor 陈旧告警**无法通过代码修复**（清单已不存在），需 GitHub 侧关闭或等待依赖图重扫（建议见 §10）。
- 建议在治理记录中固定口径：**「Dependabot open 告警数」与「npm audit 漏洞数」分别独立统计、不互相替代**；本报告与 `.github/dependabot.yml` 均按该口径维护。

### 6.2 安全更新（security updates）说明

- **本文件只控制「版本更新」PR。** 「安全更新」PR 由 GitHub 仓库设置独立控制，无法通过 `dependabot.yml` 开启或配置：
  - 路径：仓库 **Settings → Code security and analysis → Dependabot**；
  - 需同时开启 **Dependabot alerts**（本仓库已开启，254 条 open 告警即其产物）与 **Dependabot security updates**；
  - security updates 不受 `ignore` 中 `version-update:semver-major` 影响（官方口径），会针对可修复的告警单独开 PR。
- 建议维护者在仓库设置中确认 security updates 开关为开启状态，并在下一轮告警评审时以「告警数回落」为准验收。

### 7.3 处置

1. **不删除 `resources/themes/monaco-themes`**：其 `themes/*.json` 是 55 套 Monaco 主题的运行时数据源，删除会破坏主题功能。
2. **不参与依赖治理**：该副本不安装依赖、不参与构建，其 `package.json` 中的 `devDependencies`（`vite ^6.0.3` 等）是上游包自身开发依赖，对本仓库无运行风险。
3. **在 `dependabot.yml` 中用 `exclude-paths` 排除 `src/renderer/src/lib/**` 与 `resources/themes/**`**：避免后续为这些不参与构建的清单生成版本更新 PR；已存在的 15 条历史告警在 GitHub 侧关闭/重扫（§10）。
