# B5 附件管理风险与实施方案

> **性质**：风险分析与实施方案（只读评估，未改代码）。
> **项目基线**：v1.5.1（开发中）；当前门禁实测 312 测试文件 / 5,741 用例，IPC 100 通道 / 17 组，preload 白名单 send 66 + receive 28。
> **评估对象**：孤儿附件清理、附件重命名、附件引用更新。
> **结论先行**：B5 已具备“附件引用审计/定位”，但删除与重命名属于**高数据风险操作**；应先做只读孤儿审计，再以系统回收站做安全清理，最后做事务式重命名，禁止默认永久删除。

## 1. 现状与事实

### 1.1 已具备

| 能力 | 当前实现 |
| --- | --- |
| 附件引用索引 | 工作区索引解析 `![](...)` / `[](...)` 的图片/附件相对路径 |
| 存在性检查 | 聚合 `attachments`，标记 `exists`、`referencedBy`、缺失数量 |
| 附件管理对话框 | 缺失/正常分组、引用来源展开、在资源管理器中定位 |
| 编码支持 | 索引/链接更新复用编码探测；B4 已支持按原编码写回 |

### 1.2 未具备

- 未被任何 Markdown 引用的附件清单（孤儿清单）；
- 孤儿附件删除/移入回收站；
- 附件重命名；
- 附件重命名后的 Markdown 引用更新；
- 删除/重命名的事务、回滚与审计记录。

### 1.3 当前索引边界

| 项 | 当前口径 |
| --- | --- |
| 文本索引 | `.md` / `.markdown` / `.txt`，单文件 2 MiB |
| 文件数上限 | 20,000 |
| 目录深度上限 | 32 |
| 忽略目录 | `node_modules`、`.git`、`.ssh` 等工作区忽略目录 |
| 符号链接 | 跳过 |
| 附件解析 | 仅 Markdown 内联式图片/链接；HTML `<img>`、引用式定义暂不解析 |
| 渲染层权限 | 不直接读写文件；附件定位经既有 `FILE_MANAGER.OPEN_IN_EXPLORER` |

## 2. 风险矩阵

| ID | 风险 | 触发条件 | 影响 | 等级 | 处置 |
| --- | --- | --- | --- | --- | --- |
| B5-R1 | 误删仍被引用的附件 | 索引过期、解析漏项、删除前未复核 | 笔记图片/附件永久丢失 | **高** | 删除前强制刷新 + 重新扫描 + 移入回收站 |
| B5-R2 | 删除无法恢复 | 直接 `unlink`/递归删除 | 用户资料不可恢复 | **高** | 只使用系统回收站 `shell.trashItem`，不提供硬删 |
| B5-R3 | 目录/符号链接逃逸 | 传入目录、symlink、`..` | 删除工作区外文件 | **高** | 仅普通文件、Path Guard、realpath containment |
| B5-R4 | 重命名断链 | 附件被多篇笔记引用 | 图片/附件打不开 | 高 | 事务式两阶段：计划 → 改名 → 写回 |
| B5-R5 | 重命名部分失败 | 某来源文件不可读/编码异常/被占用 | 一半链接已改、一半未改 | 高 | 先计划、失败回滚或整体中止；逐文件报告 |
| B5-R6 | 覆盖同名附件 | 目标已存在 | 原附件被覆盖 | 高 | 排他检查/`wx` 写入；冲突要求改名或取消 |
| B5-R7 | 引用解析漏项 | HTML `<img>`、reference 式链接、代码块内引用 | 误判为孤儿 | 高 | 删除前保守复核；漏项一律不删 |
| B5-R8 | 索引体积/扫描卡顿 | 附件数量大、目录深 | 打开对话框慢、内存上涨 | 中 | 分页/上限/懒扫描/缓存 TTL |
| B5-R9 | 非 UTF-8 来源文件 | GBK/UTF-16 Markdown | 更新引用时损坏文本 | 中 | 复用 B4 编码探测与 BOM 保留 |
| B5-R10 | 并发操作 | 删除/重命名同时保存/外部改文件 | 状态不一致 | 中 | 主进程串行队列 + 操作前二次校验 |

## 3. 设计原则

1. **只读优先**：先做孤儿审计，不直接把“候选”变成“可删除”；
2. **可恢复**：清理只进系统回收站；应用内不提供永久删除；
3. **双重确认**：UI 预览 + 主进程二次校验；
4. **保守判定**：任何解析不确定/编码失败/状态异常，一律不删；
5. **事务化**：重命名先计划、后改名、再写回；失败可回滚；
6. **主进程唯一写盘**：渲染层只发结构化请求；不新增文件系统权限。

## 4. 方案对比

| 方案 | 内容 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 只做审计 | 孤儿清单/大小/引用数 | 零数据风险 | 不解决磁盘占用 | 第一阶段必做 |
| B. 审计 + 移入回收站 | 多选、确认、`shell.trashItem` | 可恢复、满足清理需求 | 需新增受控 IPC | **推荐** |
| C. 审计 + 永久删除 | 直接 `unlink` | 彻底释放 | 不可恢复、误删代价高 | 不采用 |
| D. 事务式重命名 | 改名 + 全量引用更新 | 不断链 | 实现复杂，失败需回滚 | 第三阶段 |

## 5. 推荐方案

### 5.1 阶段一：只读孤儿审计

**附件全集**

- 扫描工作区内所有附件扩展名：图片、PDF、Office、压缩包、音视频等；
- 复用忽略目录/大小/数量/深度限制；
- 跳过符号链接、目录、隐藏的系统目录；
- 只读元数据（大小、mtime），不读内容。

**引用集合**

- 来自工作区索引 `attachments[].path` 的并集；
- 仅信任“成功解析”的引用；
- 对解析失败/无法读取的 Markdown，记录“未完成引用分析”，并**禁止**其目录下附件进入可删除候选。

**孤儿判定**

```text
孤儿候选 = 附件全集 - 引用集合 - 保守排除集合
```

保守排除集合包括：

- 引用解析失败的文件；
- 代码块/HTML/reference 式链接可能漏解析的文件；
- 索引构建失败或超限截断；
- 隐藏目录、模板目录、用户配置的保留目录。

**UI**

- 标签页：全部 / 缺失引用 / 孤儿候选；
- 展示相对路径、大小、mtime、引用数（候选必为 0）；
- 汇总“可释放空间”；
- 只读，不提供删除入口（阶段一）。

### 5.2 阶段二：安全清理

**流程**

1. 用户勾选候选；
2. 点击“移入回收站”；
3. 弹出确认框：数量、总大小、路径列表、不可恢复提示；
4. 主进程强制刷新索引并重新扫描引用；
5. 逐项校验：工作区内、普通文件、非 symlink、重新确认为孤儿；
6. 使用 `shell.trashItem` 移入回收站；
7. 返回逐项结果；部分失败可见，不整体回滚已成功项；
8. 刷新索引、记录审计日志（不含正文）。

**限制**

- 单次最多 N 个（建议 100）与总大小上限（建议 500 MiB）；
- 不允许删除目录；
- 不允许删除 `.md` 笔记；
- 不允许删除仍被任何 Markdown 引用的附件；
- 不允许永久删除；系统回收站不可用时直接失败并提示。

### 5.3 阶段三：附件重命名

**两阶段事务**

```text
阶段 A（改名前）：
  构建附件引用更新计划
  - 找所有引用 oldPath 的 Markdown 来源
  - 生成新相对引用（保留原有写法风格）
  - 校验目标名/路径/冲突
阶段 B（改名后）：
  1. 文件改名为 newPath
  2. 按计划更新来源 Markdown
  3. 任一步失败：记录失败清单
     - 改名成功但写回失败：提供回滚改名或保留新文件+手动修复入口
```

**引用更新**

- 解析 `![alt](path)`、`[text](path)` 中的本地路径；
- 保留 `./`、`<...>` 空格写法、相对路径风格；
- 忽略 http/data/app/绝对路径/越界路径；
- 复用 B4 的编码探测与 BOM 保留；
- 不更新代码块内文本；
- 不可解码文件跳过并报告，不强行覆盖。

**并发与冲突**

- 主进程串行队列；
- 目标已存在：拒绝并提示；
- 改名后写回期间文件被外部修改：检测 mtime，跳过并报告；
- 失败时提供“回滚改名”动作（再次校验旧路径不存在）。

### 5.4 新增 IPC（阶段二/三）

原则：新增通道必须完整走链路，不新增例外。

| 通道建议 | 方向 | 用途 |
| --- | --- | --- |
| `FILE.GET_ATTACHMENT_AUDIT` | R→M invoke | 只读扫描孤儿/引用/大小 |
| `FILE.TRASH_ATTACHMENTS` | R→M invoke | 批量移入回收站（重校验） |
| `FILE.RENAME_ATTACHMENT` | R→M invoke | 事务式重命名 + 引用更新计划 |
| `FILE.APPLY_ATTACHMENT_RENAME` | R→M invoke | 改名后应用引用更新/回滚 |

- 全部经 `withSenderCheck`；
- 路径由主进程从工作区根拼接，渲染层不传根；
- 返回结构化 `{ ok, code, items }`；
- 通道名最终以 `ipc-channels.ts` 三段式为准。

## 6. 安全与数据保护

| 边界 | 措施 |
| --- | --- |
| Path Guard | `isPathAllowed` + realpath containment；拒绝越界/UNC/设备名 |
| 文件类型 | 只允许附件扩展名白名单；禁止目录/笔记删除 |
| 符号链接 | `lstat` 拒绝 symlink；改名目标再校验 |
| 删除 | 只用 `shell.trashItem`；系统回收站不可用则失败 |
| 并发 | 主进程队列 + 操作前二次 stat/索引刷新 |
| 编码 | 复用 `decodeFileContent` / `encodeFileContent`，保留 BOM |
| 日志 | 审计动作与结果；不记录笔记正文 |
| 例外 | 不新增 KNOWN_EXCEPTIONS / CSP / allowlist |

## 7. 分阶段实施

| 阶段 | 内容 | 交付 | 预估 |
| --- | --- | --- | --- |
| P0 | 附件全集扫描 + 孤儿审计（只读） | 标签页/大小/候选/保守排除 | 1.5～2.5 人日 |
| P1 | 批量移入回收站 | 确认、重校验、结果、审计 | 1～2 人日 |
| P2 | 附件重命名 + 引用计划 | 改名、写回、失败清单 | 2～3 人日 |
| P3 | 回滚/并发/编码/E2E | 回滚、冲突、编码回归 | 1～1.5 人日 |

**合计**：约 5.5～9 人日；建议按 P0 → P1 → P2 独立发版，不一次性上线。

## 8. 测试与验收

### 8.1 单元测试

- 孤儿判定：全引用、部分引用、无引用、缺失引用；
- 保守排除：解析失败、超限、忽略目录、代码块；
- 删除：目录、symlink、越界、仍被引用、已不存在、回收站失败；
- 重命名：冲突、目录、symlink、编码、BOM、别名/相对路径、部分失败；
- 并发：操作中文件变化、mtime 变化；
- 批量上限：数量/总大小截断。

### 8.2 E2E

- 孤儿附件可被列出且不显示为可删除（P0）；
- 移入回收站后文件从工作区消失、索引刷新；
- 仍被引用附件即使被勾选也拒绝删除；
- 附件重命名后 Markdown 图片正常显示；
- 失败项有明确提示，不出现半更新且无提示。

### 8.3 验收指标

- 误删仍被引用附件 = 0；
- 永久删除入口 = 0；
- 重命名后引用断链 = 0（测试集）；
- 主进程二次校验覆盖 100% 删除/重命名请求；
- 现有 312 文件 / 5,741 用例门禁不退化。

## 9. 不在本阶段范围

- 附件内容预览/OCR/全文检索；
- 附件去重（内容 hash）与合并；
- 自动清理；
- 云同步/回收站保留策略；
- 附件版本历史。

## 10. 待决策

1. 孤儿附件是否允许“移入回收站”之外提供“永久删除”（建议不提供）？
2. 单次批量上限与总大小上限取多少？
3. 重命名后若引用更新失败，默认“回滚改名”还是“保留新文件 + 手动修复”？
4. 是否允许创建子目录/移动附件到其他目录（建议先只改名、不移动）？

> 未决策前建议默认：只移入回收站、单次 100 个/500 MiB、失败默认回滚、只改名不移动。
