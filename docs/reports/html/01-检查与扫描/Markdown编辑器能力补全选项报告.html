2.3 对本项目的判断

  • 已经对齐：搜索、命令面板、多标签、历史、lint、拼写、智能输入、大纲，这些在 1.5.1 已落地，说明编辑器基础层不再是主要差距；
  • 最自然的下一步：先做 A5 属性 + B1/B2/B4 关系与索引，把「文件树」升级成「可查询的本地知识库」；
  • 最容易形成差异化的能力：E1 网页剪藏 + E2 PDF 标注 + E3 OCR，与现有本地文件/安全架构契合；
  • 不建议照搬：完整数据库、实时协作、云同步、全文 WYSIWYG 替换 Monaco；这些是产品级/团队级工程，不是单个版本能稳妥交付的。

2.4 基于当前架构的适配评估（2026-11-21）

2.4.1 当前架构对能力落地的约束

架构事实 对新增能力的影响
主进程负责文件读写、Path Guard、目录树；渲染层通过 IPC 白名单访问 搜索、索引、链接重命名、附件扫描应放主进程或 worker；不要在渲染层直接读磁盘
主进程仍是“单活动文档”语义；多标签是视图层 + localStorage 多文档、后台索引、页面预览不能依赖“当前文件”隐式状态，必须显式传路径
全工作区搜索当前按需扫描，没有持久索引/数据库 B2/B1/B4 需要先补一个可增量更新的工作区索引层；不要把索引塞进 electron-store
预览是独立 markdown-it 渲染链，编辑器是 Monaco 属性面板、悬浮预览、块引用可在预览/索引层做，不必替换 Monaco；真正 WYSIWYG 成本高（已单独评估并暂缓）
配置存 electron-store，UI 偏好在 localStorage 大型索引/缓存应放应用数据目录并定义重建策略，不能依赖 localStorage 容量
命令面板、菜单动作、EventBus 已统一 E6、E11、C3/C4 等可复用命令/菜单/设置链路，属于低风险增量
Windows-only、安装包/入口体积预算紧 OCR/PDF/富文本等重依赖必须懒加载并重新实测预算；跨平台成本另计

2.4.3 最值得借鉴的五个能力

  1. A5 Front matter/属性面板：把文件从“纯文本”变成“带元数据的数据”，为标签、查询、模板打基础；不改编辑器内核。
  2. B2 + B1（索引基础 + Wiki 双链/反向链接）：这是 Obsidian/Logseq/思源最核心的知识库闭环；需要先补主进程工作区索引，但不需要 WYSIWYG 或块模型。
  3. B4/B5（链接检查、附件管理）：建立在 B1/B5 索引之上的低边际成本能力，直接解决死链和孤儿附件。
  4. E6 日记/模板/快速收件箱：S~M 成本即可形成日常使用入口，与现有模板/命令面板/文件树高度契合。
  5. E1 Web Clipper：外部内容捕获的差异化能力；复用 Turndown，但要把本地接收端的安全边界设计好。

2.4.5 难度重估说明

  • 报告 §3 的工作量是“单功能相对估算”；叠加到本项目后，索引类能力整体上调半级（主进程增量索引 + 文件监听 + 重建/上限），涉及文件重命名的能力上调一级（Path Guard、回滚、事务性），涉及外部内容的能力另加安全评审；
  • 入口体积只有 0.5 KiB 余量，任何重依赖（PDF/OCR/富文本）必须懒加载并重新跑 budget:check；
  • Windows-only、无插件沙箱、无持久索引是当前三大架构约束，规划时需一起考虑；
  • E9（Focus/Typewriter/写作目标/Style Check）已在 1.5.1 写作体验 P0 中落地（可选、默认关闭），不再是待做项；A7 智能输入已扩展为普通/写作模式通用。

6. 关键风险与依赖提示

  • B1/B4 会改变文件语义（链接/重命名），要先定链接语法、歧义规则、相对路径策略和回滚方案；
  • B2/E5 索引会影响主进程性能与目录监听链路，必须定义忽略规则与增量更新；数据库视图不要先于属性/索引做；
  • A3 历史已有 MVP，但 localStorage 容量有限；后续需升级为磁盘级历史与清理策略；
  • E1/E2/E3 涉及外部内容/二进制/PDF，必须复用现有 Path Guard、app://、CSP 与 worker 边界；
  • E4 块引用会引入稳定块 ID 与复制/移动/删除语义，建议在 B1 索引稳定后再做；
  • E9 Style Check 需要规则集与误报控制，可参考 Vale 的规则模型；
  • D5/D6 涉及后端、隐私与成本，建议先明确产品定位；AI 默认应离线/可关闭；
  • 当前 单文件架构、Windows-only、未签名 是长期约束，规划时需一起考虑。

7. 验收标准

7.1 通用

  • 每一批功能必须有：单元测试 + 关键 E2E + 不降低现有覆盖率阈值；
  • 不破坏现有门禁：typecheck / ESLint 0 warning / Prettier / vitest / E2E / audit / budget / fuses；
  • 性能敏感功能（搜索、索引、多文档、预览）需给出量化基线（启动、内存、搜索耗时）；
  • 涉及文件语义的能力（链接、重命名、历史、剪藏）必须有回滚方案与失败提示；
  • 外部内容（剪藏/PDF/OCR/AI）必须有明确隐私开关与本地优先策略。
