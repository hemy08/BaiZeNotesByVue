白泽笔记代码整体结构分析报告

性质：结构分析（非缺陷清单）——对 v1.3.6 代码库做一次自顶向下的整体结构切片，梳理进程边界、模块分层、数据流、工程链路与结构风险。 分析时点：2026-11-19（v1.3.6，git HEAD 3ea3a51，工作区干净）。规模与门禁数字均为当时实测；历史报告的旧口径不适用于本报告。 方法：3 个并行只读分析代理分别深读「主进程 + preload」「渲染层」「共享层 + 构建/测试/文档」，根代理汇总并出图。原始分析记录见 out/tool-results/struct-main.md、struct-renderer.md、struct-cross.md。

0. 摘要与关键结论

一句话：白泽笔记是一个「Electron 三进程 + shared 单真源 + 自研轻量基础设施」的本地优先 Markdown 笔记应用——主进程收口全部系统能力，preload 用两份白名单把 92 个 IPC 通道收敛为受信桥，渲染层用 Vue 3 承载欢迎页/编辑器/预览/38 个插件工具，工程侧以自建 md→HTML 报告流水线维护文档。

五条关键结论

  1. 边界清晰、真源纪律强：92 IPC 通道、9 领域共享类型、12 命名空间 i18n 词典各有唯一出口，且有防回归测试做「常量 ↔ 调用点」双向核对。
  2. 主进程是「薄外壳 + 厚内核」：index.ts 只做生命周期编排，业务集中在 utils/file-utils；IPC 注册分散 7 个文件但统一在 whenReady 后一次性执行，全部套发送方校验。
  3. 渲染层是「双段式外壳 + 单主界面 + 懒加载边界」：欢迎页入口 chunk ≈114 KB，主界面（Monaco + 预览 ≈9.6 MB）整体异步；61 处动态 import 构成全部按需加载边界，无手工 manualChunks。
  4. 预览管线是当前最复杂的单条链路：预渲染 → markdown-it（mkdocs/basic/media/blocks 四层插件）→ 异步图表 → DOMPurify → 远程图片策略 → v-html + TOC，逐层可降级、可单测。
  5. 主要结构债集中在三处：config ↔ utils 双向依赖、preload 白名单三份手工清单、Vue 对话框与主进程 JSDOM 对话框双体系；另有文档口径漂移与发布链路未 CI 化。

状态与通信

  • 状态：useConfigStore 保存配置域与对话框状态（dialogs.*），组件级状态由 ref/reactive 管理；无 Vue Router，界面切换由 welcome-state 与 store 驱动。
  • 事件：EventBus 24 个事件按域前缀命名（MONACO_*/FILE_*/EVENT_BUS.*），进程事件经 ipcRenderer.on 进入组件；composables/useEventBus 存在但生产未使用（结构观察项）。
  • 懒加载：18 对话框 + 38 插件 + 6 类重型依赖全部 defineAsyncComponent 动态导入，共 61 处主要动态 import。

菜单、对话框与插件工具

体系 结构 一致性
菜单 menu-config.ts（数据驱动，820 行）→ MenuBar.vue 渲染 → menu-actions.ts 渲染层拦截；未命中经 IPC.MENU.ACTION 转主进程 handler 树 渲染层拦截列表与主进程 handler 树以测试/注释对齐
对话框 Vue 18 个（懒加载注册表 dialogs/index.ts）+ 主进程 JSDOM 6 个（独立 BrowserWindow） 同一动作存在双路径（结构债 H4）

编辑器与预览管线

  • Monaco：单 worker、按需语言注册、每文件一个模型；击键链路 500ms 空闲防抖 + 脏指纹（长度 + sha256）跳过未变化内容；5 种编辑/预览模式切换。
  • 预览（PF-02 单跳）：编辑内容 → 150ms 防抖 + 渲染序号 → 预渲染（snippets 展开 / KaTeX / 本地 URL 转换）→ markdown-it 插件（highlight.js / emoji / plantuml / mkdocs-material admonition+tabbed / basic/media/blocks 扩展）→ mermaid/PlantUML 异步 → DOMPurify → 远程图片策略 → v-html + TOC（章节指纹门控）；大文档（>2 MiB / 5 万行）跳 KaTeX/图表并提示。
  • 性能结构：入口 chunk ≈114 KB；主界面（Monaco + 预览）≈9.6 MB 首次进入时异步求值；out/renderer ≈24.1 MiB。

6. 关键数据流

  1. 文件：打开 → 编辑 → 保存/自动保存 → 退出落盘 选择文件 → IPC（sender 校验 + 路径守卫）→ file-operations 读取 + 编码检测 → 回填 Monaco + appState → 脏指纹更新 → Ctrl+S/自动保存/切换文件落盘；退出时 close 拦截 → FLUSH_CONTENT（2s 超时）→ 脏则落盘。
  2. 菜单动作：渲染层优先，主进程兜底 MenuBar 点击 → HandleMenuAction（渲染层打开 Vue 对话框/插入文本）→ 未命中经 IPC.MENU.ACTION → 主进程 menu-handle 解析 → handler 树 → 业务调用/窗口操作。
  3. 配置变更：store → IPC → electron-store → 副作用 + 广播 设置对话框 v-model → useConfigStore（300ms 防抖，JSON 往返剥离 Proxy）→ window.api.config.write → config-manager 路由/校验/迁移 → electron-store 落盘 → 应用副作用（主题/字体/快捷键/定时器）→ 广播 THEME.UPDATED / SYSTEM_SETTING_UPDATE → 渲染层监听器更新 UI。
  4. Markdown 预览：单跳本地管线（见 §4「编辑器与预览管线」；无主进程渲染 IPC）。

9.3 改进建议（按优先级，不要求实施）

P1（结构债，建议尽早）

  1. 依赖边界自动化：引入 dependency-cruiser 或自研单测声明 index → ipc|dialogs → config → utils → shared 方向矩阵，禁止 utils 反向 import config（改回调注入，如现有 setRecentFilesLimitProvider 模式），并把 config/index.ts 的 ipc re-export 迁出。
  2. 白名单单一化：以 shared/ipc-channels.ts 分组 + 一张「通道路由元数据表」为源，构建期生成两份 preload 白名单与 window.api 闭包通道；测试改为「生成产物 vs 渲染层扫描」核对。
  3. 收敛对话框体系：把 ShowShortcutKeys/ShowUpdateLog/ShowReleaseNotes/ShowRename/ShowConfirmDelete 迁为 Vue 懒加载对话框，主进程只保留确有独立窗口需求的（在线网页等），消除「新建文件/文件夹」双路径。
  4. 主界面二次分块：Monaco 初始化与预览管线二级懒加载（先外壳骨架，空闲/首编辑时加载 Monaco），降低首次进入的 ~9.6 MB 同步求值；评估 highlight.js 改 core + 常用语言。
  5. 修正文档口径并自动化：统一 README/报告中的产物体积、依赖计数、测试数、审计口径；为门禁数字增加自动生成/校验脚本（CI 落盘并与 docs 基线比对）。

P2（治理与质量）

  1. 注册清单显式化：新增 ipc/registry.ts 只做 registerAll(mainWindow) 汇总；入口只调用一次。
  2. 状态收口：新增 AppContext（window/stores/listener manager/flags）统一 reset；删除无消费者的 systemConfig/quickLinksConfig 或真正接入；主题收敛为 useTheme() 单例。
  3. 单一注册表：插件工具由一份 manifest 同时生成菜单项与懒加载注册表；Material 15 项同理。
  4. 错误/状态栏统一：抽 notifyStatus + toUserError 替换 5 套 helper。
  5. 拆分超大文件：directory-tree 按扫描/watch/事件拆 3 文件；preview-md-basic 按语法域拆；MaterialSyntaxDialog 抽表单/生成器纯函数目录；设置页按页签拆子组件。
  6. 工程门禁补强：CI 增加 vitest --coverage、prettier --check、npm audit --omit=dev；shared 边界加 ESLint no-restricted-imports（禁止 renderer import main、禁止 shared 引 electron/node）。
  7. 发布链路补全：新增 release workflow（tag → nsis/portable + latest.yml 上传），补签名策略与 release-1.3.6 tag。

P3（清理与规范）

  1. 清理死代码/重复资源：utils/common.ts、SYSTEM.OPEN_EXTERNAL_LINK、MermaidRender.vue、HemyTools 空壳、重复 CSS/模板资源。
  2. 目录语义归位：window-manager 移至 src/main/window/；main/constants/urls.ts 合并到 shared。
  3. 格式统一：.editorconfig 与 Prettier endOfLine 对齐，修复非 UTF-8 文件；out/ 拆分构建产物与分析产物，dist/ 历史安装包归档到 Release。
  4. 文档资产治理：docs/架构文档.html 归档并在索引标注「非当前」；_unused-assets 移出工作区。

10. 结论

  • 白泽笔记的整体结构属于「边界清晰、真源纪律强的本地优先桌面应用」：进程边界、契约层、安全纵深、懒加载与生命周期收口都达到成熟工程水平，测试具备结构不变量守护能力。
  • 当前结构债并非功能缺陷，而集中在 依赖方向（config↔utils）、桥接层手工清单（preload 白名单）、双对话框体系 与 主界面大 chunk 四处；同时文档口径漂移与发布链路未 CI 化会放大这些债的维护成本。
  • 建议按 §9.3 的 P1→P3 顺序分批判修复：先用「依赖边界测试 + 白名单生成 + 对话框收敛 + Monaco 二级懒加载」四件事降低核心结构风险，再补 CI 门禁与发布流程，最后做清理与资产治理。
