三、P0 严重问题（2 项）

3.1 FE-01：欢迎页打开文件/文件夹后主界面数据空白（数据丢失风险）
  • 位置：src/main/ipc/handlers.ts:149-191、src/renderer/src/App.vue:4-12、MarkdownEditComponent.vue:319、ResourceManager.vue:129-132、file-operations.ts:700,830-840
  • 现象：
    1. 渲染层 App.vue 用 v-if="showWelcome" 切换，主界面组件（编辑器/资源管理器）只有在收到 WELCOME_ENTER_MAIN 后才挂载、监听器才注册；
    2. 「打开文件夹」主进程先 send CLEAR_EDITOR_PREVIEW → await ReloadDirFromDisk()（内部发 FILE_SYSTEM_DATA）→ 最后才 send WELCOME_ENTER_MAIN（handlers.ts:157-161）；
    3. 「打开文件」同理：先 await OpenSelectFile()（发 SHOW_SELECTED_FILE_CONTEXT/USER_SELECT_FILE）→ 最后 send WELCOME_ENTER_MAIN（handlers.ts:185-186）；
    4. 主界面挂载后不主动拉取当前文件/目录树（BaiZeNotes.vue:453-477 只加载配置与主题）。
    5. 对比「最近文件夹」入口（App.vue:38-46）先隐藏欢迎页再发 IPC，因此不受影响。
  • 影响：首次启动点「打开文件/打开文件夹」→ 编辑器与目录树空白；用户输入或关窗时 flush 会把空/新内容写回主进程并可能落盘 → 覆盖原文件。
  • 建议：主进程调整发送顺序（先 WELCOME_ENTER_MAIN 再发数据事件），或渲染层主界面 onMounted 主动 invoke 拉取当前活动文件内容 + 目录树（幂等重建，推荐）；补欢迎页 E2E 冒烟。
  • 备注：静态时序推断，需实机运行确认；若实机不符则降为 P2 健壮性问题。
3.2 PF-1：预览对每个行内代码执行 highlightAuto 全语言探测（慢 12~155 倍）
  • 位置：src/renderer/src/components/Markdown/MarkdownPreviewComponent.vue:59-72
  • 现象：.use(highlightjs, { inline: true, hljs, highlight }) 未传 auto: false；markdown-it-highlightjs@4.3.0 默认 auto: true，其 dist/core.js 用 highlightAuto 覆盖 md.options.highlight，组件自定义回调完全失效（实测 getLanguage 调用 0 次）。
  • 实测（单轮 md.render，同机）：
    文档 行内代码数 当前耗时 仅加 auto:false 放大
    16 KiB 153 232.8 ms 1.5 ms 155×
    29 KiB — 342.1 ms 2.3 ms 149×
    50 KiB — 553.0 ms 4.5 ms 123×
  • 影响：每次 150 ms 防抖后在渲染进程主线程阻塞 100~553 ms（与 Monaco 输入同线程）→ 输入卡顿、大文档不可用。
  • 建议：.use() 时传 auto:false，并在插件安装后覆盖带 getLanguage 守卫的 options.highlight；或去掉 inline:true。

9.8 实机回归修复（19:30~19:40）：欢迎页与窗口控制全部无反应

现象（用户实机反馈）：欢迎界面点击「打开文件 / 打开文件夹」无反应；窗口右上角「最小化 / 最大化 / 关闭」也无反应；界面本身显示正常。

根因（产物级，单元测试无法覆盖）：

  1. electron.vite.config.ts 的 preload 配置有 index / dialog 两个入口，二者共享 src/shared/ipc-channels.ts；
  2. Rollup 把共享模块提取为独立 chunk，产物 out/preload/index.js 第 1 行为 require("./chunks/ipc-channels-*.js")；
  3. 主窗口与对话框均 sandbox: true，Sandboxed preload 只能 require('electron') 与少量内置模块，无法 require 相对路径文件 → preload 启动即抛错；
  4. contextBridge.exposeInMainWorld('electron' / 'api', ...) 未执行 → 渲染层 window.electron / window.api 缺失；
  5. 欢迎页与窗口按钮都直接调用 window.electron.ipcRenderer.send(...) → 点击时抛错被事件系统吞掉 → 表现为"全部无反应"。

修复：preload 构建启用 electron-vite 的 isolatedEntries: true（每个入口自包含、无共享 chunk），并按框架要求同时 externalizeDeps: false（第三方依赖内联，Electron sandbox 硬性要求）。修复后 out/preload 仅 index.js（7.7KB）+ dialog.js（6.7KB），产物内只剩 require("electron")，contextBridge 暴露语句齐全。

回归防护：新增 tests/unit/preload-build-config.test.ts，对 electron.vite.config.ts 做静态断言（preload 必须 isolatedEntries: true + externalizeDeps: false，禁止旧白名单写法），防止未来配置回退。

验证：out/preload 单文件 + contextBridge.exposeInMainWorld 存在 + 打包 asar 内 out/preload 无 chunks 目录；全量 132 文件 / 2,205 用例通过。

9.9 实机回归修复（19:35~19:45）：启动总是显示欢迎页（产品决策调整）

现象（用户实机反馈）：preload 修复后重启应用，启动直接进入主窗口，看不到欢迎界面。
