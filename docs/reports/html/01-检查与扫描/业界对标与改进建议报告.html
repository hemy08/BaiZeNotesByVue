业界对标与改进建议报告

性质：外部对标、差距分级与改进路线图（非缺陷报告、非实施记录）。 项目基线：v1.5.6 开发中（最新发布版本 v1.5.5）；报告整理时间 2026-11-28。 对标对象：Typora、Obsidian、Notion、Joplin、Logseq、Zettlr、iA Writer、VS Code、Mdnice/Doocs。 结论先行：白泽在工程质量、安全加固、中文写作体验、导入导出广度上已属同类第一梯队；下一阶段最值得投入的不是继续堆功能，而是补 5 个结构性方向——编辑范式、AI、检索底座、扩展性、知识网络；其中**中文内容生产（图床/博客/公众号）**是最具差异化、投入产出最高的切口。 与既有报告的关系：能力候选与工作量口径沿用《Markdown 编辑器能力补全选项报告》的 A/B/C/D/E 系列 ID；WYSIWYG 技术评估见《Monaco 与 WYSIWYG 双编辑器技术评估报告》（D8 已决定暂缓）；全文索引见《B2 全文索引风险与实施方案》（阈值驱动、纯 JS worker、暂不引入 SQLite）。本报告不重复能力清单，只回答三个问题：业界基线是什么、差距在哪、先做什么。 使用方式：§6 看优先级矩阵与路线图；附录 A 看可执行清单；§7 看明确不做的方向。

1. 结论与范围

1.1 五条结论

  1. 基础能力已对齐：搜索、命令面板、多标签、历史、lint、拼写、智能输入、大纲、双链/反链、附件管理、PDF 标注、OCR、模板/日记/收件箱，1.5.x 已陆续落地；编辑器基础层不再是主要差距。
  2. 最大体验代差是编辑范式：Monaco 源码 + 分栏预览仍是“开发者工具”心智；Typora 的无缝所见即所得、Obsidian 的 Live Preview 是普通用户的第一感知差异。
  3. 最大战略缺口是 AI：2026 年 Notion AI、Obsidian AI 插件、Joplin AI/MCP 已把“写作助手 + 笔记问答 + 语义检索”变成默认预期；白泽目前零 AI。
  4. 最该补的底座是持久索引：当前全文检索按需扫描，无法支撑万级笔记、图谱、数据库视图与 AI RAG；但应按 B2 报告的阈值触发，优先纯 JS worker，不急于引入 SQLite。
  5. 最值得做的差异化是中文内容生产：图床、Hexo/Hugo 博客、微信公众号排版是 Typora 用户的高频外挂组合；白泽若内置，能形成“写作→排版→发布”的闭环，这是 Obsidian/Notion 不擅长的中文场景。

3.3 三条竞争路线与白泽的位置

路线 代表 赢家逻辑 白泽是否适合
写作工具 Typora、iA Writer 单篇写作体验极致 适合作为“基本盘”，但单靠它难差异化
知识库/生态 Obsidian、Logseq 插件 + 双链 + 数据化 适合作为“增长盘”，但插件生态需要长期投入
协作/平台 Notion、Craft 团队协作 + 数据库 + AI 不适合单人本地优先产品，除非转团队

建议定位：Typora 的写作手感 + Obsidian 的知识网络 + 中文内容生产 + 本地优先 AI/隐私。不做 Notion 的跟随者。

4. 五个结构性差距

4.1 编辑范式：从“分栏”到“就地预览”

现状

  • Monaco 源码编辑器 + 独立 markdown-it 预览；MarkdownEditComponent.vue 以单一 Monaco 实例编排。
  • 已有编辑/预览/分屏三种布局与滚动同步，但仍是“写代码 + 看结果”的心智。

业界基线

  • Typora：文档模型是富文本树，编辑区直接显示最终排版。
  • Obsidian：文档模型仍是 Markdown 源文本，用 decorations 隐藏标记、渲染样式，光标行显示源码（Live Preview）。
  • VS Code：源码 + 预览分栏，面向开发者。

差距与影响

  • 非技术用户第一眼感知“像 IDE”，学习成本高；中文输入法下分栏视线跳跃；长文写作沉浸感弱。

建议路径（三步，不重启 D8）

  1. Monaco 内联预览（S~M）：图片/公式/Mermaid/表格用 decoration/widget 就地渲染，隐藏标记符；只处理可视区域，避免大文档卡顿。
  2. 单栏实时预览（M~L）：源码与渲染合一，光标行显示 Markdown 标记；提供“源码/实时预览/分屏”三态切换。
  3. 可选富文本模式（XL，D8）：Tiptap/Milkdown/ProseMirror，与 Monaco 双模式共存；仅在 1、2 验证后评估。

风险与约束

  • 中文 IME 组合期不得改写文本；撤销栈/选区映射/大文档性能必须专项测试；必须 feature flag 灰度。
  • 不改变“Markdown 字符串是唯一真源”的现有约束（见 WYSIWYG 评估报告 §2）。

优先级/工作量：P0（第 1 步，S~M）；P1（第 2 步，M~L）；第 3 步仅评估，不排期。

验收指标：中文输入 0 丢字/0 错位；1 万行文档滚动 ≥50fps；撤销/重做 100 次一致；内联预览开关可回退。

4.2 AI：从“零”到“本地优先的写作助手”

现状

  • 源码无 AI Provider、无流式对话、无 embedding；只有「AI 导航」菜单里的 70 个外部站点链接，不参与写作流。
  • 已有能力可复用：气泡工具栏、命令面板、工作区索引、全文搜索、diff 预览。

业界基线

  • Notion AI：续写/总结/翻译/问答/数据库 AI。
  • Obsidian：AI 插件生态（本地/云端）、Copilot 类插件。
  • Joplin：AI Chat、语义搜索、MCP（插件/生态）。
  • Logseq：块引用 + 插件生态（AI 由社区插件提供）。

差距与影响

  • AI 已成为“笔记工具是否现代”的默认预期；缺失会让用户外挂 ChatGPT，割裂写作流。

建议 MVP（按投入产出排序）

能力 说明 依赖 工作量
选中文本操作 润色/改写/扩写/缩写/翻译/纠错/续写；diff 预览后应用 气泡工具栏 M
文档级操作 摘要/大纲/标题/标签建议 工作区索引 S~M
文档问答 当前文档问答，引用段落可点击 分块/检索 M
工作区问答（RAG） 跨笔记问答，引用来源 持久索引/embedding L
语义搜索 自然语言找笔记 embedding M~L
自动双链建议 基于语义相似度建议 [[链接]] 索引 + embedding M

架构建议

层 方案
Provider 本地默认 Ollama/LM Studio；云端 BYOK 以 OpenAI-compatible 为主（DeepSeek/Qwen/Kimi/GLM/OpenAI），Anthropic 走原生适配
进程 主进程 ai/ 服务；流式响应、取消、超时、重试、token 计量
IPC 新域 ai：AI.CHAT_STREAM、AI.CANCEL、AI.LIST_MODELS、AI.EMBED（按 IPC 治理链路注册/白名单）
安全 API Key 用 safeStorage 加密；默认不联网；发送前展示上下文；不默认外发路径/全文；审计日志
RAG 复用 B2 索引 + 分块 + 可选本地 embedding；BM25/向量混合排序；引用可点击
UI 气泡工具栏 + 命令面板 + 侧边栏；所有改写先 diff 再应用

风险与约束

  • 隐私：默认本地模型；云端必须显式开启并显示将发送的内容。
  • 成本：token 预算/单次确认/模型分级（本地小模型做润色，云端大模型做长文总结）。
  • 提示注入：笔记内容可能包含恶意指令；系统提示与用户内容隔离，工具调用需确认。
  • 合规：不默认上传；不记录正文到日志。

优先级/工作量：P0 / M~L（MVP 4~8 周）。

验收指标：本地模型可用且断网可润色；云端 Key 加密存储；发送前上下文可见；取消后无残留流；RAG 引用可跳转。

4.3 检索底座：从“按需扫描”到“可增量索引”

现状

  • 全文检索复用 A2 按需扫描；usage-guide.html 明确“1.5.x 不建持久全文索引”。
  • 工作区索引是内存快照（workspace-index-ipc.ts 5s TTL），覆盖标题/标签/Wiki 链接/摘要/附件引用，不含正文倒排。
  • B2 报告已给出阈值与纯 JS worker 方案，暂不引入 SQLite FTS5。

业界基线

  • Obsidian：本地索引，万级笔记即时搜索；反链/图谱/快速切换共用索引。
  • Notion：服务端全文 + AI 检索。
  • Joplin：SQLite FTS + 语义搜索。

差距与影响

  • 万级笔记搜索慢、重复扫盘；无法支撑图谱、数据库视图、AI RAG、规模化反链。

建议路径（沿用 B2 决策）

  1. 阶段 0（已具备）：保留 A2 指标（P50/P95、扫描文件数、命中/截断），设阈值：文件数 >2,000 或文本 >100 MiB 或 P95 >2s。
  2. 阶段 1：worker_threads + FlexSearch/MiniSearch + 可重建快照；主进程串行队列；失败回退 A2。
  3. 阶段 2：索引字段扩展（标题层级/正文/标签/front matter/链接/mtime/hash）；增量更新复用 fs.watch；提供“重建索引”与忽略规则。
  4. 阶段 3（可选）：本地 embedding（如 all-MiniLM）或 provider embedding；混合排序；为 AI RAG/语义搜索供数。
  5. 不推荐：当前阶段引入 SQLite/原生依赖（ABI、打包、审计、加密迁移成本高）；渲染层 IndexedDB 索引（形成第二真源并绕过主进程文件权限边界）。

优先级/工作量：P0 / M~L（阶段 1）。

验收指标：1 万笔记 P95 搜索 <500ms（B2 阶段 1 的 2,000 文件目标 ≤150ms）；索引构建不阻塞 UI；索引损坏可自动重建并回退；空闲内存增量 ≤100MB（构建峰值 ≤300MB）；索引目录按工作区隔离。

4.4 扩展性：从“38 个内置工具”到“可扩展平台”

现状

  • 38 个内置“插件工具”是功能集合（plugin-tools-manifest.ts 菜单树 + baize:menu:plugins:* 动作前缀），不是第三方扩展 API。
  • 无第三方插件 manifest、无沙箱、无权限模型、无 API 版本化；插件菜单本身仍在，但只能打开内置工具。

业界基线

  • Obsidian：数千社区插件，manifest + 权限 + 市场。
  • VS Code：扩展 API + 市场 + 沙箱（Extension Host/Webview）。
  • Joplin：插件 API + 市场。

差距与影响

  • 用户工作流无法定制；内置工具越多，维护成本越高；生态是长期护城河。

建议路径（分阶段）

阶段 内容 风险 工作量
v0 用户宏（声明式动作序列）+ CSS 片段 + 模板包；不执行任意 JS，只暴露命令/编辑器/文件读写的最小 API 低 S~M
v1 manifest（id/version/minAppVersion/permissions/contributes）+ 独立宿主进程（utilityProcess 或沙箱 renderer）+ 能力授权 + 消息桥 中 L~XL
v2 本地目录安装 → 签名市场；API 版本化与兼容测试 高 XL

API 表面（v1 建议）

  • commands、editor（选区/装饰）、workspace（打开文件/面板）、vault（读写/搜索）、events、settings、UI（状态栏/侧栏/模态）、自定义 Markdown 渲染钩子。

红线

  • 不放宽 webPreferences/Path Guard/CSP/Fuses；插件权限可审计；禁止渲染层 eval；网络访问需白名单与显式授权。
  • 插件代码不得直接获得 Node/Electron 全量 API；宿主只暴露白名单能力，文件访问仍走 Path Guard。

优先级/工作量：P0（v0，S~M）；P1（v1，L~XL）。

验收指标：沙箱逃逸测试 0 高危；插件权限清单可见/可撤销；API 版本不兼容有明确报错；禁用插件后无残留监听/定时器。

4.5 知识网络：从“双链”到“网络”

现状（代码明确）

  • workspace-index.ts:45：Wiki 链接不解析 ![[embed]] 嵌入语义、不展开别名/heading 跳转。
  • wiki-link-actions.ts:26：heading 暂不参与跳转，![[embed]] 不在能力范围。
  • 无图谱、无块引用、无数据库视图；front matter 有 aliases 字段（FrontMatterDialog.vue 固定字段），但链接解析未使用。

业界基线

  • Obsidian：双链 + 反链 + 图谱 + Canvas + Bases + 别名/嵌入/块引用。
  • Logseq：块引用 + Linked References + 日记。
  • 思源：内容块/嵌入/块级双链 + 数据库多视图。
  • Notion：数据库 + 关系属性。

建议顺序（按投入产出）

顺序 能力 说明 工作量

7. 不建议做的方向

方向 原因
Notion 式块编辑器 + 实时协作 维护成本极高，偏离本地优先单人产品；除非转团队协作
继续堆内置工具 38 个已够多，边际收益低；转向插件/宏扩展
移动端/Web 全面铺开 双线作战成本高；先做只读 PWA 或浏览器剪藏
默认云端 AI 破坏“本地优先/隐私”定位；坚持本地默认 + BYOK
为插件放宽安全边界 安全加固是差异化资产，不能拿来换生态
当前阶段引入 SQLite FTS5 原生依赖/ABI/打包/审计成本高；先按 B2 纯 JS 路线
真 WYSIWYG 立即替换 Monaco D8 已评估暂缓；先做内联预览/单栏模式

8. 结论

“Typora 的写作手感 + Obsidian 的知识网络 + 中文内容生产工作流 + 本地优先 AI/隐私”——这四件事的组合，比做“Notion 跟随者”更有胜算。

白泽的护城河不是“功能最多”，而是本地优先、安全可控、中文友好、工程可靠。AI 和插件要围绕这四点做，而不是为了追热点破坏它。
