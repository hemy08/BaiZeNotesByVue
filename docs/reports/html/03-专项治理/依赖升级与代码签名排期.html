3. 代码签名上线清单（需人工前置）

3.1 采购与准备

  • [ ] 选择证书：OV/EV Windows 代码签名证书（EV 可更快建立 SmartScreen 信誉；需企业资质）
  • [ ] 确认签名方式：本地 PFX（certificateFile + certificatePassword）或 Azure Trusted Signing（需 Azure 订阅）
  • [ ] 准备时间戳服务：http://timestamp.digicert.com（或等价）

3.2 工程接入

  • [ ] electron-builder.yml 配置 win.signingHashAlgorithms、signAndEditExecutable、证书来源（CI secrets / Azure）
  • [ ] CI release workflow 注入签名密钥；latest.yml 签名校验说明
  • [ ] 更新源完整性：electron-updater 校验 sha512（已有）；可选 asar integrity
  • [ ] 构建产物验证：signtool verify /pa /v + 安装/更新冒烟

3.3 验收

  • [ ] 干净 Windows VM 安装无 SmartScreen 红屏（EV 需积累信誉）
  • [ ] 自动更新签名前后均可升级
  • [ ] Release 说明标注签名状态与指纹
  • [ ] 回滚：保留未签名构建产物与证书吊销流程

4. 排期建议

  1. 先做 B1~B3（工具链/测试链，风险可控、无产品行为变更）；
  2. 再做 B4（运行时行为变更，需真机手测）；
  3. B5 electron 45 与发布窗口绑定，单独分支 + 完整回归；
  4. B6 katex 等待 mermaid 升级配合；
  5. 代码签名与 B5 同步推进（证书采购周期通常 3~10 个工作日，需提前启动）。

5. 风险与回滚

  • 每批独立分支/commit；门禁（typecheck/eslint/prettier/vitest/build/E2E/docs/quality/budget）全绿才合并；
  • electron 45 升级失败回滚到 43.x 并保留 electron-store 旧版；
  • 签名仅影响发布产物，不影响源码/测试；证书配置走 secrets，不落盘。
