B2 全文索引风险与实施方案

性质：风险分析与实施方案；1.5.1 方案 A 决策已完成：暂不建持久索引，只做指标。 项目基线：v1.5.1（开发中）；当前门禁实测 312 测试文件 / 5,741 用例，IPC 100 通道 / 17 组，preload 白名单 send 66 + receive 28。 评估对象：是否新建持久全文索引；当前全文检索复用 A2 按需搜索。 结论先行：当前 A2 搜索在中小工作区可用且安全，1.5.1 不新建持久索引；已补 elapsedMs 指标与慢搜索日志，后续达到阈值再采用“worker_threads + 纯 JS 索引 + 可重建快照”，不优先引入 SQLite/原生依赖。

1. 现状与事实

1.1 当前全文检索

项 当前实现
入口 全工作区搜索/替换（A2）
范围 当前工作区 .md / .markdown / .txt
方式 主进程按需扫描文件并匹配
选项 大小写、整词、正则
结果 文件/行/列/预览，支持跳转与批量替换
持久化 无；每次搜索重新扫描
上限 文件数 20,000、单文件 2 MiB、结果 500 条（以现有实现为准）
安全 只搜工作区根；忽略目录/符号链接；主进程受控

1.2 知识库索引与全文检索的关系

层 数据 是否持久 用途
工作区索引 标题/标签/Wiki 链接/摘要/附件引用 否（内存快照，5s TTL） 标签、反链、链接检查、悬浮预览
A2 全文搜索 文件内容按需匹配 否 全文查找/替换
B2 持久全文索引（候选） 分词/倒排/位置 是 大工作区低延迟全文检索

当前 B2 的“全文索引”实际是“工作区索引 + A2 按需搜索”，不是独立的持久倒排索引。

2. 风险矩阵

ID 风险 触发条件 影响 等级 处置
B2-R1 大工作区搜索慢 文件数多/磁盘慢 搜索延迟高、UI 等待 中 指标量化；必要时持久索引
B2-R2 重复扫盘/IO 放大 频繁搜索、无缓存 磁盘占用与能耗上升 中 请求合并/短期缓存；持久索引
B2-R3 结果上限截断 命中超过 500 条 用户误以为没有更多结果 中 明确“已截断”提示；分页/提高上限需评估
B2-R4 与知识库视图不一致 标签/反链用索引、全文用 A2 同一文件两套结果口径 低 统一数据源/结果字段
B2-R5 索引损坏/过期 崩溃、异常退出、外部改文件 搜不到/搜到旧内容 高（若做持久索引） 版本化、校验、可重建、失败回退 A2
B2-R6 索引占磁盘/内存 大量长文/附件误入 体积膨胀 中 索引大小上限、排除规则、压缩
B2-R7 隐私/安全 索引写到错误位置/跨工作区 笔记内容泄露 高 按工作区隔离、应用数据目录、Path Guard、清理策略
B2-R8 中文分词质量 中文无空格 召回低/误命中 中 Intl.Segmenter + 保守子串兜底
B2-R9 原生依赖风险 选 SQLite FTS5 Electron ABI/打包/审计成本 高 优先纯 JS；原生方案需专项评估
B2-R10 索引构建阻塞 主进程同步构建 启动/搜索卡顿 高 worker_threads、分片、可取消

3. 方案对比

方案 内容 优点 缺点 结论
A. 维持 A2 按需搜索 现状 + 指标 零新依赖、零持久化风险 大工作区慢、重复 IO 当前默认
B. 纯 JS 持久索引（推荐候选） worker + FlexSearch/MiniSearch + JSON/二进制快照 无原生依赖、可重建、跨会话 需处理分词/增量/体积 达到阈值再做
C. SQLite FTS5 原生数据库 + FTS5 查询强、成熟 Electron ABI、打包、审计、加密/迁移成本 暂不推荐
D. 渲染层索引 浏览器 IndexedDB/WASM 主进程压力小 渲染层读盘/权限边界破坏、不可接受 禁止

3.1 为什么暂不选 SQLite FTS5

  • 需要 Electron 原生模块重建/分发，影响打包与 Fuses 冒烟；
  • 需要审计新原生依赖与安全边界；
  • 数据库文件迁移/损坏恢复/加密策略复杂；
  • 当前工作区规模尚未证明必须使用数据库级方案。

3.2 纯 JS 索引候选

  • FlexSearch：倒排/分词/增量友好，体积可控；
  • MiniSearch：API 简洁、序列化方便，适合中小规模；
  • 二者均需评估许可证、体积、维护状态与中文分词效果；
  • 不在本报告阶段引入依赖，先做 PoC/基准。

4. 推荐方案

4.1 先量化，不先建索引（阶段 0）

在 A2 搜索增加可观测指标（只记录聚合，不记录正文）：

  • 搜索耗时 P50/P95；
  • 扫描文件数、读取字节数；
  • 命中数、是否截断；
  • 缓存命中/重复查询；
  • 工作区文件数、总大小。

触发持久索引的参考阈值（需产品确认）：

  • 工作区文件数 > 2,000 或总文本 > 100 MiB；
  • 搜索 P95 > 2s；
  • 用户日均搜索次数较高且重复扫描明显。

未达到阈值时，保持 A2，避免为“可能的需求”增加持久化复杂度。

4.2 达到阈值后的架构（阶段 1+）

渲染层 Knowledge/Search UI
  → 主进程 IPC（查询/重建/状态）
  → FullTextIndexService（主进程，串行）
  → worker_threads（构建/查询）
  → 索引快照（应用数据目录，按工作区隔离）
  → 失败/未就绪回退 A2 按需搜索

索引数据

  • 文档：路径、mtime、size、内容 hash、标题；
  • 词项：英文按词、中文按 Intl.Segmenter，保留位置用于高亮；
  • 只索引工作区根内文件；忽略目录/符号链接规则复用现有索引；
  • 索引版本号 + 工作区标识；不跨工作区复用。

构建与更新

  • 首次搜索/手动重建时后台构建，不阻塞 UI；
  • 增量：mtime + size 变化才重建单文件；
  • 文件删除：标记删除并清理倒排；
  • 索引损坏：校验失败 → 删除/重建 → 回退 A2；
  • 并发：主进程串行队列，worker 可取消；
  • 上限：文件数/索引大小/单文件大小，超限回退 A2。

查询

  • 支持普通关键词/短语/大小写/整词；
  • 正则默认回退 A2（正则不适合倒排）；
  • 返回文件/行/列/预览，保持与 A2 相同字段，便于 UI 复用；
  • 结果截断明确提示。

4.3 隐私与安全

  • 索引只写应用数据目录，不写工作区；
  • 按工作区隔离；关闭/切换工作区时释放；
  • 不记录笔记正文到日志；
  • 查询接口只接受查询串/选项，不接受任意根路径；
  • 新增 IPC 必须走完整链路，不新增例外；
  • 索引文件权限按当前用户，避免多用户共享泄露。

5. 分阶段实施

阶段 内容 交付 预估
P0 A2 指标与阈值判定 指标、基准脚本、决策记录 0.5～1 人日
P1 索引服务 PoC（worker + 小规模） 建/查/增量/回退，基准报告 2～3 人日
P2 持久化/恢复/上限 快照、版本、损坏重建、隔离 1.5～2 人日
P3 UI 接入与回退 查询复用 A2 结果 UI，失败降级 1～1.5 人日
P4 大工作区/E2E/性能 2k/5k 文件、冷/热启动、内存 1～1.5 人日

合计：约 6～9 人日（仅在 P0 证明需要后启动）。

6. 测试与验收

6.1 单元/集成

  • 分词：中英混合、标点、代码块、大小写；
  • 增量：新增/修改/删除/重命名；
  • 编码：GBK/UTF-16/BOM 文件可被索引；
  • 恢复：索引损坏/版本不匹配/工作区切换；
  • 上限：文件数/单文件/索引大小截断；
  • 回退：worker 失败/索引未就绪时走 A2；
  • 安全：越界路径/符号链接/忽略目录不索引。

6.2 性能验收

指标 目标（建议）
冷构建 2,000 文件 ≤ 10s（后台，不阻塞 UI）
热查询 P95 ≤ 150ms
增量单文件更新 ≤ 50ms
索引体积 ≤ 工作区文本大小的 50%
内存 空闲 ≤ 100 MiB；构建峰值 ≤ 300 MiB
回退 索引不可用 100% 回退 A2

6.3 门禁

  • 现有 312 文件 / 5,741 用例不退化；
  • 新增 IPC 契约/白名单/安全测试齐全；
  • 体积预算：索引依赖不得进入首屏（动态/worker chunk）；
  • 不新增 CSP/allowlist 例外。

7. 不在本阶段范围

  • 语义搜索/向量检索；
  • 跨工作区全局索引；
  • 云端索引/同步；
  • 正则全文索引（继续 A2）；
  • 附件内容/OCR 检索（属于 E2/E3）；
  • 索引加密/多用户共享。

8. 待决策

  1. 是否接受“暂不建持久索引”，先以 A2 指标驱动？
  2. 触发阈值（文件数/耗时/使用频率）取多少？
  3. 纯 JS 索引选 FlexSearch 还是 MiniSearch（需 PoC 对比）？
  4. 索引文件是否允许超过工作区文本大小 50%？
  5. 是否需要在 1.5.x 内完成，还是列入 1.6 知识库增强？

未决策前建议默认：先做 P0 指标，不引入依赖；1.5.x 不承诺持久全文索引。

9. 1.5.1 实施结果与决策（2026-11-22）

决策：1.5.1 不新建持久全文索引，不引入数据库。

已落地：

  • A2 搜索成功结果新增 elapsedMs（主进程按需搜索耗时，不改变既有结果字段/上限）；
  • 慢搜索（≥500ms）记录聚合日志：耗时 / 扫描文件数 / 命中数 / truncated，不记录查询词和正文；
  • 现有标签/反链/链接检查继续使用工作区内存索引，全文搜索继续复用 A2；
  • 不新增 IPC、不新增依赖、不改变服务启动/关闭链路。

后续触发持久索引的条件（任一）：

  • 常用工作区文件数 > 2,000 或总文本 > 100 MiB；
  • 搜索 P95 > 2s；
  • 用户频繁搜索且重复扫描明显影响体验。

达到条件后再进入“worker_threads + 纯 JS 索引 + 可重建快照”的 PoC，不直接上数据库。
