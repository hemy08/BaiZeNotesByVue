四、logger 双写设计（src/main/utils/logger.ts）

现状确认：logger 的 writeLog() 早已是「文件 + 控制台」双写，本次未改变其契约，只做两点强化：

  1. 双写镜像（迁移兼容前提）：WARN/ERROR 在写入文件流的同时调用 console.warn/console.error（单行格式化文本，含时间戳/级别/脱敏后消息），DEBUG/INFO 同样镜像控制台但不进状态栏（AS-11）。因此原 expect(console.error/warn).toHaveBeenCalled() 类断言在迁移后仍然成立。
    • 已在 writeLog() 增加「CQ-10 双写契约」注释，明确该镜像为迁移兼容/诊断可见性设计，不允许后续随意删除。
  2. Error 实参保真（新增）：原 formatMessage 对 Error 对象执行 JSON.stringify 会得到 {}，迁移 console.error('xxx', err) 后会丢失错误信息。新增 formatLogArg()：
    • 文件/控制台：Error 优先输出完整 stack（含 message），无 stack 时输出 Name: message；
    • 状态栏镜像：includeStack: false，只输出单行 Name: message，避免堆栈刷进 UI；
    • 普通对象仍 JSON.stringify（失败 String 兜底），与历史日志格式兼容；用户主目录脱敏在最终整行统一执行（AS-11 不变）。
  3. 补充单元测试（tests/unit/logger.test.ts，+2 用例）：
    • 文件日志保留 Error message/stack，不出现 {}；控制台镜像同样保留错误信息；
    • 状态栏镜像 Error 参数为单行 保存失败 Error: disk full（无堆栈）。

五、PF-7 拖拽/缩放 IPC 与 Monaco layout 合帧

  • 实现：mousemove 只记录最新坐标/bounds，requestAnimationFrame 帧内最多提交一次 WINDOW.MOVE（缩放为 MOVE + SET_SIZE 各一次）；mouseup 立即 flush 最终位置，不丢最后一帧；无 rAF 环境退化为立即发送。
  • 量化：单帧内 3 次 mousemove → 1 次 IPC（测试断言）；按 1000 Hz 鼠标采样推算，拖拽 IPC 峰值约 1000 次/s → 约 60 次/s（-94%），缩放约 2000 次/s → 约 120 次/s。
  • Monaco：editorAreaWidth 连续变化/窗口 resize 触发的 layout() 同样 rAF 合帧（每帧最多 1 次），组件卸载时取消未执行帧。
  • 附带修复 PF-4 暴露的既有渲染缺陷：FileTreeNode 的 v-memo 只依赖 path/fileExtension/isExpanded，主进程整树下发新对象时深层新增/删除会被 memo 跳过（目录树不刷新）；新增 treeRevision 依赖后整树刷新正确失效，同时保留「展开/收起只重渲被切换子树」的收益。

1. 问题一：NSIS 打包失败

1.1 现象
  • 执行 npm run build:win 时弹出 NSIS 错误框："Error writing temporary file. Make sure your temp folder is valid."
  • electron-builder 日志：编译出卸载器生成器后执行该 exe，process failed, exit code 2；dist 中只留下 400KB 左右的残缺 Setup.exe。
1.2 根因（已用对照实验证实）
实验 结果
同一 NSIS 生成器 exe 放在 %TEMP%、E:\github.com\... 外部目录运行 exit 0，成功生成卸载器
同一 exe 放在工作区内（dist\、项目根、工作区任意新子目录）运行 exit 2，报临时文件错误
检查路径完整性标签 工作区根目录带显式 Low Mandatory Level 完整性标签，且未标记不继承 → 所有子目录/新文件继承 Low
把工作区内 exe 的完整性标签改为 Medium 后运行 exit 0，成功
把外部 exe 的完整性标签改为 Low 后运行 exit 2，复现失败

结论：受管沙箱工作区被标记为 Low 完整性级别。从 Low 完整性目录启动的进程同样以低完整性运行，无法写入 Medium 完整性的 %TEMP%，NSIS 因此报"临时文件夹无效"并退出。与 electron-builder 版本、NSIS 脚本、TEMP 路径均无关。

1.3 修复
项 内容
一次性修复 icacls dist /setintegritylevel Medium（out/、resources/ 同步处理）
仓库级防护 新增 build/prepare-build-dirs.js：在 electron-builder 运行前检查 dist/out 完整性级别，非 Medium 时自动提升（幂等、跨平台 no-op、失败仅告警不阻塞）
接线 package.json 全部 build:* / build:unpack / verify:pack 脚本在 electron-builder 前调用该脚本（8 处）
效果 即使 npm run clean 后重建目录再次继承 Low 标签，也会在打包前自动校正

  • Electron 的 closed 事件在窗口已销毁后触发，此时访问 window.webContents 抛 TypeError: Object has been destroyed；
  • 新建文件 / 重命名对话框关闭时触发该路径 → 主进程未捕获异常弹窗。
2.3 修复（src/main/utils/ipc-security.ts）
改动 说明
注册时捕获引用 registerTrustedDialogWindow 在登记时一次性捕获 webContents 引用与 id，closed 清理函数只使用捕获值，不再访问窗口属性
显式注销防御 unregisterTrustedDialogWindow 读取 webContents 加 try/catch，窗口已销毁时静默返回（清理由 closed 监听器负责）
主窗口判定加固 isTrustedSender 读取主窗口 webContents 同样加 try/catch，销毁竞态按"非受信发送方"处理，异常不会冒泡到 IPC 事件循环
2.4 回归测试（tests/unit/ipc-security.test.ts 新增 2 例，共 19 例）
  1. closed 监听器触发时窗口已销毁（webContents getter 抛错）→ 不抛异常且登记表正确清理；
  2. 对已销毁窗口显式注销 → 不抛异常。
