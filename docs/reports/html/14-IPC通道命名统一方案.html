1.2 发现的六类命名问题

#问题典型例子
A前缀四套并存baize-notes:update-theme、baize:notes:welcome:open-file、config:read、window-minimize、get-current-theme
B分隔符/层级混用baize:notes:welcome:open-file（4 段）vs baize-notes:update-theme（2 段）；file-manager-context-menu-* 13 个超长前缀
C动词/事件语义不统一命令式 window-minimize、get-current-theme、update-*、dialog-*-enter 混用；事件型 *-updated、*-changed、*-result 未统一
D拼写/语义错误markdown-edit-model（应为 mode，2 处）；monaco-insert-text-block-templates 实为通用文本插入；open-plugin-tool 为死通道
E方向不可辨同一前缀下混有 R→M send/on、invoke/handle、M→R 推送
F通道名与常量名不一致常量 TEXT_BLOCK_TEMPLATES ↔ 通道 monaco-insert-text-block-templates；COPY_IMAGELINK ↔ copy-imagelink（缺连字符）

2. 统一命名规范

2.1 格式

baize:<domain>:<name> —— 固定三段，全小写 kebab-case；domain 取白名单；示例：baize:window:minimize、baize:config:read、baize:theme:updated、baize:fs:copy-relative-path、baize:file:open-with-encoding。

2.2 领域白名单（18）

window · config · setting · theme · editor · monaco · view · menu · file · fs · navigation · dialog · plugin · render · quick-links · overlay · status-bar · system

2.3 命名细则（5 条）

规则内容示例
R1 动作语义请求-响应（invoke/handle）与 R→M 命令用动词原形开头baize:window:minimize、baize:config:read
R2 事件语义主进程→渲染层推送/结果事件用过去式或结果后缀baize:theme:updated、baize:setting:auto-save-changed
R3 单数实体实体一律单数，冗余词删除file-manager-context-menu-rename → baize:fs:rename
R4 拼写与语义修正 model→mode 等拼写；名称须与用途一致markdown-edit-model → baize:view:edit-mode
R5 常量命名不变不改 IPC.<GROUP>.<KEY> 常量名与分组，仅统一通道字符串值，用测试锁定格式IPC.WINDOW.MINIMIZE 值改为 baize:window:minimize

格式校验正则：^baize:[a-z][a-z-]*:[a-z][a-z0-9-]*$，并断言 domain ∈ 18 个白名单（建议新增 tests/unit/ipc-channel-naming.test.ts）。

4. 迁移方案（成本极低）

4.1 关键前提（已核实）

  • 通道引用 100% 走常量：main/preload/renderer 均 IPC.* 引用；HTML 对话框内联脚本通过模板插值注入常量；preload 对话框 send 白名单也引用常量；
  • 因此无需逐个改调用点，只改常量值即可全局生效。

4.2 改动清单

#文件/对象改动
1src/shared/ipc-channels.ts123 个字符串值替换为建议值（唯一真源）
2tests/unit/ipc-channel-constants.test.ts 等硬编码旧值断言同步
3tests/unit/ipc-channel-naming.test.ts（新增）格式正则 + domain 白名单 + 唯一性
4docs/reports 通信矩阵重生成同步
5out/tool-results/ipc-channel-rename-map.json执行依据（已生成）

4.3 与死通道清理合并（推荐）

  1. 先删除 16 个死通道（常量 + 收发端 + 测试）；
  2. 对剩余 107 个通道一次性套用新命名（改常量值）；
  3. 重生成通信矩阵，更新检查报告中的通道名；
  4. 跑门禁 + 新增命名测试。

4.4 不建议的做法

  • ❌ 保留旧值别名（内部闭环，无外部消费者，会产生双轨认知负担）；
  • ❌ 逐个调用点改名（徒增风险，失去常量真源意义）；
  • ❌ 在通道名中加方向后缀（噪音；方向由调用位置与矩阵区分，测试校验两端模式）。
