二、PF-4 目录树增量重扫（微基准）

基准方法：合成目录树（3840 个 .md 文件 / 4297 节点，深度 3 层）+ 真实 node_modules 样本；每项取 3 次中位数。

场景 优化前 优化后 变化
全量递归扫描（4297 节点） 30.4 ms 17.4 ms -42.8%
完整目录刷新（扫描 + 建树 + 整树 JSON） 29.4 ms 18.9 ms -35.7%
watcher 外部单文件变更触发的刷新 28.6 ms（=全量） 1.5 ms（只重扫 1 个子树） -94.8%
watcher 同批 3 个文件变更 29.5 ms（=全量） 1.6 ms -94.6%
真实 node_modules 子树扫描 280.0 ms / 5218 节点 82.3 ms（且依赖目录已整体排除） -70.6%
工作区 = 本仓库根目录一次全量扫描 约 315 ms+（报告基准 node_modules 样本 339 ms） 35.1 ms / 3166 节点 约 -89%
整树 JSON（4297 节点） 942,291 字符 942,291 → 935,838 字符 稳定 id 后内容未变时不再重复发送

实现要点：

  1. readdir({ withFileTypes: true }) 替代「逐条目 lstat」，并加 64 并发上限的 readdir 闸门（递归等待子目录时不占名额，无死锁）；
  2. watcher 批次把变更路径折叠为「受影响目录」（父子目录合并、按阈值 8 个目录内只重扫该子树），超出阈值/新目录/涉及根目录时回退全量扫描；
  3. 节点 id 改为「路径派生稳定 id」，整树 JSON 内容未变时逐字节稳定 → watcher 批次的「JSON 未变则跳过 IPC」去重真正生效；
  4. node_modules / .git / .svn / .hg / .idea / .vscode 不进入目录树、其内部事件不触发刷新。

四、PF-9 KaTeX 缓存 + 大文档降级

场景 优化前 优化后 变化
267 个公式文档第二次渲染（缓存命中） 24.49 ms（首轮冷启动） 1.26 ms -94.9%

实现要点：

  1. KaTeX 结果 LRU 缓存（key = 公式字符串，上限 200 条，命中刷新顺序、超限淘汰最久未用；失败结果不缓存）；
  2. 阈值常量 PREVIEW_LARGE_DOC_BYTE_THRESHOLD（2 MiB）/ PREVIEW_LARGE_DOC_LINE_THRESHOLD（5 万行），单次线性扫描提前判定；
  3. 超大文档：跳过 KaTeX + 跳过 mermaid/PlantUML 图表渲染（源码保留为代码块），预览顶部显示一次「文档过大，预览已简化」提示条，编辑器保持可用。

五、PF-7 拖拽/缩放 IPC 与 Monaco layout 合帧

  • 实现：mousemove 只记录最新坐标/bounds，requestAnimationFrame 帧内最多提交一次 WINDOW.MOVE（缩放为 MOVE + SET_SIZE 各一次）；mouseup 立即 flush 最终位置，不丢最后一帧；无 rAF 环境退化为立即发送。
  • 量化：单帧内 3 次 mousemove → 1 次 IPC（测试断言）；按 1000 Hz 鼠标采样推算，拖拽 IPC 峰值约 1000 次/s → 约 60 次/s（-94%），缩放约 2000 次/s → 约 120 次/s。
  • Monaco：editorAreaWidth 连续变化/窗口 resize 触发的 layout() 同样 rAF 合帧（每帧最多 1 次），组件卸载时取消未执行帧。
  • 附带修复 PF-4 暴露的既有渲染缺陷：FileTreeNode 的 v-memo 只依赖 path/fileExtension/isExpanded，主进程整树下发新对象时深层新增/删除会被 memo 跳过（目录树不刷新）；新增 treeRevision 依赖后整树刷新正确失效，同时保留「展开/收起只重渲被切换子树」的收益。
