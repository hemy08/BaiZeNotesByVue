ARC-01 远程内容窗口继承特权 preload，构成远程→主进程任意能力调用链 P0 ✅ 已修复

位置：src/main/dialogs/OpenOnlineWebPages.ts:6-13、src/preload/dialog.ts:4-13、src/main/utils/utils.ts:105-107、src/main/dialogs/dialog-defaults.ts:4-11 ｜ 影响：远程页面可经 IPC 让主进程执行本地程序/打开任意链接 ｜ 工作量：2-3 人日

OpenOnlineWebPageWithDialog 用 createDialogOptions 创建窗口——该工厂强制注入 DIALOG_WEB_PREFERENCES（preload 为 dialog.js），随后对任意远程 URL 执行 loadURL(url)。dialog.js 通过 contextBridge 暴露了 ipcRenderer.send(channel, ...args)（不校验通道名）与 shell.openExternal；而主进程存在"能力型"通道：navi-tab-open-exe → shell.openPath(exePath)（任意路径执行本地程序）、open-external-link → shell.openExternal(url)、baize:notes:open-specific-folder 等，均无来源与参数校验。任何被加载的远程页面都可直接调用这些通道。

// OpenOnlineWebPages.ts:7-12 — 远程 URL + 特权 preload 窗口
windowManager.createWindow('online-web-page', createDialogOptions({...}))
localOpenWebPageDialog.loadURL(url)
// dialog.ts:5-7 — 任意通道透传
send: (channel, ...args) => ipcRenderer.send(channel, ...args)
// utils.ts:105-107 — 未校验的执行型通道
ipcMain.on('navi-tab-open-exe', (_, exePath) => shell.openPath(exePath))

修复建议：① 远程内容窗口一律不挂 preload（独立无特权窗口）；② 主进程对 navi-tab-open-exe / open-external-link 等通道做路径/协议白名单与来源（sender）校验；③ mermaid 等远程脚本改为本地资源打包。注：system-setting.ts:14 默认 pluginOpen 为 'browser'（外部浏览器），但可切换为 local-dialog 触发该路径（OpenOnlineWebPages.ts:20-26）；同类窗口 OpenMermaidRenderFrame.ts:68-73 从 CDN 加载远程脚本扩大攻击面。
