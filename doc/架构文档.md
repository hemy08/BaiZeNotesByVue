## 概述

### 系统简介

白泽笔记是一款基于 Electron + Vue 3 + TypeScript 构建的跨平台桌面笔记应用，专注于提供优雅的 Markdown 编辑体验。应用名称源自中国古代神兽"白泽"，寓意智慧与知识的汇聚。

### 核心特性

- **Monaco Editor 集成**：采用 VS Code 同款编辑器，提供强大的代码编辑能力
- **多主题支持**：内置 20+ 精美主题，支持浅色/深色模式切换
- **实时预览**：Markdown 实时渲染，支持 Mermaid、PlantUML、KaTeX 等扩展语法
- **插件工具集**：内置加密解密、格式转换、网络工具等实用插件
- **文件管理**：支持多标签页、文件树导航、自动保存
- **跨平台**：支持 Windows、macOS、Linux

### 技术选型理由

| 技术 | 选型理由 |
|-----|---------|
| Electron 38 | 最新稳定版，提供完整的桌面应用能力，支持原生 API 调用 |
| Vue 3 | Composition API 提供更好的逻辑复用，响应式系统性能优异 |
| TypeScript 6 | 强类型保障代码质量，IDE 支持完善 |
| Monaco Editor | VS Code 同款编辑器，语法高亮、智能提示、快捷键生态成熟 |
| electron-vite | 专为 Electron 优化的构建工具，开发体验流畅 |
| electron-store | 简单可靠的持久化存储方案 |

#### 架构决策记录（ADR）

**ADR-001: 选择Monaco Editor作为核心编辑器**

- **状态**：已采纳
- **背景**：需要为用户提供专业的Markdown编辑体验
- **决策**：采用Monaco Editor
- **理由**：
  1. VS Code同款编辑器，用户熟悉度高
  2. 原生支持TypeScript，类型安全
  3. 语法高亮、智能提示、快捷键功能完善
  4. 性能优异，可处理大文件
- **影响**：包体积增大（~2MB），但用户体验显著提升

**ADR-002: 采用IPC通信而非remote模块**

- **状态**：已采纳
- **背景**：Electron渲染进程需要访问主进程能力
- **决策**：使用IPC通信，禁用@electron/remote
- **理由**：
  1. remote模块存在安全风险
  2. IPC通信更安全、性能更好
  3. 符合Electron最佳实践
- **影响**：需要手动定义IPC通道，代码量略增

**ADR-003: 主题系统采用CSS变量方案**

- **状态**：已采纳
- **背景**：需要支持多主题切换
- **决策**：使用CSS变量定义主题色
- **理由**：
  1. 运行时动态切换，无需重新加载
  2. 代码简洁，维护方便
  3. 浏览器原生支持，性能优异
- **影响**：IE不支持（但Electron使用Chromium，无此问题）

## 架构决策记录

### ADR-001: Electron技术栈选型

**状态**：已采纳

**背景**：
需要开发一款跨平台桌面笔记应用，支持Windows、macOS、Linux。

**决策**：
选择Electron作为桌面应用框架，Vue 3作为UI框架，TypeScript作为开发语言。

**理由**：
1. **Electron优势**：
   - 跨平台支持完善
   - 生态成熟，文档丰富
   - 可使用Web技术栈
   - 原生API访问能力强

2. **Vue 3优势**：
   - Composition API提供更好的逻辑复用
   - 响应式系统性能优异
   - TypeScript支持完善
   - 学习曲线平缓

3. **TypeScript优势**：
   - 强类型保障代码质量
   - IDE支持完善
   - 重构能力强

**影响**：
- 包体积较大（~150MB）
- 内存占用较高（~200MB）
- 开发效率显著提升

### ADR-002: Monaco Editor选型

**状态**：已采纳

**背景**：
需要为用户提供专业的Markdown编辑体验，包括语法高亮、智能提示、快捷键等功能。

**决策**：
选择Monaco Editor作为核心编辑器组件。

**理由**：
1. VS Code同款编辑器，用户熟悉度高
2. 原生支持TypeScript，类型安全
3. 语法高亮、智能提示功能强大
4. 快捷键系统完善
5. 性能优异，可处理大文件
6. 可扩展性强，支持自定义语言

**影响**：
- 包体积增加约2MB
- 初始化时间略长
- 编辑体验显著提升

### ADR-003: IPC通信架构

**状态**：已采纳

**背景**：
Electron渲染进程需要访问主进程能力（文件操作、对话框等）。

**决策**：
采用IPC通信模式，禁用@electron/remote模块。

**理由**：
1. **安全性**：remote模块存在安全风险
2. **性能**：IPC通信性能更好
3. **最佳实践**：符合Electron官方推荐
4. **可控性**：通信过程更透明

**实现**：
- 使用`ipcMain.handle`/`ipcRenderer.invoke`处理异步请求
- 使用`ipcMain.on`/`ipcRenderer.send`处理同步消息
- 使用`ipcListenerManager`统一管理监听器

**影响**：
- 需要手动定义IPC通道
- 代码量略增
- 安全性和性能提升

### ADR-004: 主题系统设计

**状态**：已采纳

**背景**：
需要支持多主题切换，包括浅色、深色主题，以及多种配色方案。

**决策**：
采用CSS变量方案实现主题系统。

**理由**：
1. **动态切换**：运行时动态切换，无需重新加载
2. **代码简洁**：通过修改变量值即可切换主题
3. **性能优异**：浏览器原生支持，性能优异
4. **易于扩展**：添加新主题只需定义变量值

**实现**：
- 定义主题配置接口`ThemeStyles`
- 使用CSS变量定义颜色值
- Monaco编辑器主题独立配置
- 主题配置持久化存储

**影响**：
- 主题切换无闪烁
- 代码维护方便
- 不支持IE（Electron使用Chromium，无此问题）

### ADR-005: 文件自动保存策略

**状态**：已采纳

**背景**：
需要防止用户数据丢失，提供自动保存功能。

**决策**：
采用定时器+脏检查的自动保存策略。

**理由**：
1. **减少IO**：只在文件有修改时保存
2. **用户可控**：可配置保存间隔
3. **性能平衡**：避免频繁IO影响性能

**实现**：
- 默认30秒检查一次
- 检查`global.current_active_file.content`是否有修改
- 有修改则调用`SaveActiveFile()`
- 应用关闭时清理定时器

**影响**：
- 数据安全性提升
- 性能影响可控
- 用户无感知
