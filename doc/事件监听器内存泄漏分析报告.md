### 2.3 渲染进程监听器问题

#### ⚠️ 问题: 缺少统一的清理机制

**现状**:
- 各个组件独立管理自己的 IPC 监听器
- 没有类似主进程的 `IPCListenerManager`
- 依赖开发者手动在 `onBeforeUnmount` 中清理

**风险**:
- 🟡 如果开发者忘记清理，会导致内存泄漏
- 🟡 组件频繁创建销毁时，累积效应明显

**建议改进**:
创建渲染进程专用的监听器管理器:

```typescript
// src/renderer/src/utils/ipc-renderer-manager.ts
class IpcRendererManager {
    private listeners: Map<string, Function[]> = new Map()
    
    on(channel: string, listener: Function) {
        window.electron.ipcRenderer.on(channel, listener)
        
        if (!this.listeners.has(channel)) {
            this.listeners.set(channel, [])
        }
        this.listeners.get(channel)!.push(listener)
    }
    
    cleanup() {
        this.listeners.forEach((listeners, channel) => {
            listeners.forEach(listener => {
                window.electron.ipcRenderer.removeListener(channel, listener)
            })
        })
        this.listeners.clear()
    }
}

export const ipcRendererManager = new IpcRendererManager()
```

## 📈 九、内存泄漏风险评估

### 9.1 短期运行 (< 1小时)

**风险等级**: 🟢 低

- 用户正常使用不会遇到明显问题
- 监听器数量较少，内存占用可忽略

---

### 9.2 中期运行 (1-8小时)

**风险等级**: 🟡 中

- 频繁打开/关闭对话框会导致监听器累积
- 假设用户每小时打开10次对话框，8小时后可能有80个重复监听器
- 内存增加约 10-20MB (估算)

---

### 9.3 长期运行 (> 8小时)

**风险等级**: 🔴 高

- 监听器持续累积，可能导致:
  - 事件触发时执行多次回调
  - 内存占用持续增长
  - 应用响应变慢
  - 极端情况下崩溃
