### 4.3 通信机制更新

#### IPC 通信
- 主进程 → 渲染进程：theme-updated、file-system-data、monaco-editor-insert-after-cursor 等
- 渲染进程 → 主进程：get-current-theme、file-manager-context-menu-create-file 等

#### EventBus 通信
- $on：监听事件
- $emit：触发事件
- $off：移除监听
- $offAll：清除所有监听

### 4.4 数据流更新

#### 文件加载流程
1. 用户选择文件 → IPC 发送到主进程
2. 主进程读取文件内容 → 通过 IPC 返回渲染进程
3. 渲染进程更新 Monaco 编辑器 → 触发预览渲染
4. 预览渲染 → Markdown 解析 → HTML 生成
5. 更新预览视图

#### 渲染流程
1. 编辑器内容变化 → 触发预渲染
2. 主进程处理（Material Admonitions、图片转换、KaTeX）
3. 返回预渲染结果 → Mermaid 渲染
4. Markdown-it 解析 → HTML 生成
5. 后处理 → 显示预览

#### 主题切换流程
1. 用户选择主题 → IPC 发送到主进程
2. 主进程获取主题样式 → 广播到所有窗口
3. 渲染进程接收主题 → 应用 CSS 变量
4. 更新 Monaco 编辑器主题 → 重新渲染组件

## 8. 主题优化方案更新

### 8.1 优化背景

#### 原始实现方式
- 所有主题配置硬编码在 `src/main/utils/theme-config.ts` 文件中
- 每次调用 `getCurrentThemeStyles()` 都需要从内存中的对象读取
- 代码结构不够清晰，维护困难
- 添加新主题需要修改代码文件，不够灵活

### 8.2 优化方案

#### 优化目标
- 主题配置文件化
- 主题缓存机制
- 主题预加载
- 代码结构优化

#### 优化实现
- 主题配置文件化：将主题配置保存为 JSON 文件
- 主题缓存机制：实现主题缓存，减少重复读取
- 主题预加载：应用启动时预加载主题
- 代码结构优化：优化代码结构，提升可维护性

### 8.3 优化效果

#### 架构优化
- ✅ 主题配置文件化，易于维护
- ✅ 主题缓存机制，提升性能
- ✅ 主题预加载，减少启动后的文件操作

#### 代码优化
- ✅ 代码量减少 61%
- ✅ 代码结构更清晰
- ✅ 职责划分更明确

#### 功能优化
- ✅ 支持动态主题加载
- ✅ 支持主题文件管理

#### 性能优化
